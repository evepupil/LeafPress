# 跑灵感

作者说「跑灵感」，或者定时任务让你跑灵感时，照这份做。目标：往灵感收件箱放 5～10 条作者真会想写的选题，每条写清为什么值得写、从哪个角度写。找候选、去重、排序都由 LeafPress 的代码做，你只负责挑和写。

## 1 读档案，定主题词

1. `leafpress accounts --json`：找到知乎账号（平台 `zhihu`）的编号。编号从返回里读，不要猜。
2. `leafpress account show <知乎账号> --json`：整份读档案，弄清这个号写给谁、写什么、不写什么。档案里只写了规则文件的位置时，去读那份文件。
3. 提炼 3～5 个主题词：每个 2～8 个字，是知乎上会有人提问的说法（例如「大模型」「AI 编程」「认知偏差」「指数基金」），不要整句，不要档案里没有的方向。

没有知乎账号就不给主题词，直接下一步。

## 2 找候选

运行 `leafpress ideas gather --topics <词1,词2,…> --json`，工具超时设成 5 分钟（要连几十次知乎接口，通常 1～2 分钟）。

- `sources`：每个来源找到几条、新进池几条；有 `warning` 的记下来，最后告诉作者（额度用完、密钥失效、没有知乎账号……）。
- `pool`：候选池。每条有 `id`（`c-…`）、`kind`、`title`、`url`、`payload`：
  - `question`：知乎问题。`payload.via` 是怎么找到的（`personal` 按账号推荐、`topic` 按主题词、`blog` 用作者的博客反找、`hot` 热榜）；`payload.answerSummaries` 是已有回答的摘要；`payload.relatedWorkIds` 是作者对得上的作品；`payload.blogWorkIds` 是对得上的博客。
  - `followup`：作者数据好的已发作品（近 7 天增长、累计阅读）。
  - `devlog`：作者某个项目这一周的提交说明和进度流水标题。

池是空的就告诉作者今天没找到，停下。

## 3 挑

挑 5～10 条，宁缺毋滥：池里没有像样的，少于 5 条也行。

先弄清每个账号写什么体裁：档案和它指向的写作规则里写着。例如作者的知乎号只写说明文（把一套方法、一个机制讲透，让读者拿走一套能用的判断），不写个人经历、行业随笔、观点抒发。挑选题时照这个筛。

- **知乎问题**至少 3 条（池里够的话）：
  - 跑题的不要：和档案写的方向不沾边的（社会新闻、娱乐八卦、作者从没写过的领域）；
  - 体裁对不上的不要：只求表态的（「如何评价 / 如何看待某人某事」，除非能落到讲清一个机制）、求个人经历的、书单和资源清单类的；
  - 读 `answerSummaries`：已有回答又多又扎实、作者说不出新东西的不要；已有回答泛泛而谈、作者有亲身经验或现成素材的优先；
  - `via` 含 `blog` 的（作者有现成博客能改）优先，但问题要真问到博客写的事上；
  - 问法本身有毛病（引战、钓鱼、过于宽泛如「如何看待 AI」）的不要。
- **续写**不超过 2 条：写续篇、换个角度再写，或者换平台再发（博客转知乎、知乎回答扩成博客文章）。
- **开发记录**不超过 2 条：从提交说明和进度流水里找有故事的事：踩过的坑、做过的取舍、做成的东西。只是改格式、修小毛病的那一周不要。这类一般适合博客的问题复盘，挂博客账号；能提炼成一个通用机制的，也可以写成知乎说明文。
- 不和已有的重复：`leafpress ideas --json` 看已有灵感，选题相近的不要（池里只去掉了同一个问题，相近的选题要你自己看）。

## 4 写

每条一个 JSON 对象：

- `candidateId`：候选编号（`c-…`）。
- `text`：一句话标题。
  - 问题：用问题原标题；
  - 续写：「续写：<新选题>」或「转<平台>：<作品标题>」；
  - 开发记录：写成一个能发的选题，例如「LeafPress 出图偶发失败：日志里的地址连到了整个浏览器」，不写「本周开发复盘」这种空话。
- `detail`：固定四行，一行一项：

  ```
  来源：<链接或位置>（<怎么找到的：按账号推荐 / 主题词：大模型 / 博客反找：b-3 / 热榜 / 已发作品 / 开发记录>）
  为什么值得写：<一两句，具体：提问的人卡在哪、已有回答缺什么、作者手里有什么>
  建议角度：<一两句，具体：写什么、用哪个例子、结论往哪个方向>
  相关作品：<编号《标题》，多个用顿号隔开；没有写「无」>
  ```

  问题的链接一定要写在「来源」那行：灵感转成知乎作品时，LeafPress 靠这个链接自动配「回答问题」工作流。

- `accountId`：问题写知乎账号；续写和开发记录写打算发的账号，拿不准就不写。
- `source`：问题、续写写 `schedule`；开发记录写 `devlog`。

不编数字：阅读量、回答数接口拿不到，就不写。理由不写「热门话题」「流量大」这种空话。

## 5 交

1. 把数组通过标准输入交给 `leafpress ideas add --stdin --json`。整批失败时看报错：哪个候选不在池里（已推过、已跳过、不存在）就把那条去掉再交一次，不要改编号硬交。
2. 加成功后，把这次看过、没挑的候选编号交给 `leafpress ideas skip <编号,编号,…> --json`，标成跳过（14 天内不再出现）。只给你看过的编号，不要用 `--rest`：跑的过程中可能有新候选进池，你没看过。
3. 用三五行告诉作者：加了几条（列标题），哪些来源出了问题。

## 边界

- 只用这几个命令：`accounts`、`account show`、`ideas`、`ideas gather`、`ideas add`、`ideas skip`、`works`（看已有作品时）。不转作品、不接手作品、不改档案、不改任何文件。
- 不自己上网搜知乎：问题都从候选池里来。
- 作者在网页上删掉的灵感，LeafPress 会记住不再推，不用你管。
