## 0. 通用鉴权（四个接口共用）

来源：官方文档「鉴权」`https://developer.zhihu.com/console/api/v3/docs`（guide/authorization 节）。

| Header | 示例值 | 说明 |
| - | - | - |
| `Authorization` | `Bearer <your_access_secret>` | Bearer 鉴权头，注意 `Bearer` 后有一个空格 |
| `X-Request-Timestamp` | `1742822400` | **秒级** Unix 时间戳（不是毫秒）。额度查询接口明确「与服务端时间相差不能超过 10 分钟」 |
| `Content-Type` | `application/json` | JSON 接口固定值（GET 接口官方 curl 示例里也带） |

要点：

- 服务端会同时校验 `Authorization` 与 `X-Request-Timestamp`。
- **除这两个头外没有别的签名**（无 HMAC、无 nonce、无请求体签名）。文档中唯一例外是异步任务类接口支持可选 `Idempotency-Key`，与本调研四个接口无关。
- Access Secret 在 `https://developer.zhihu.com/profile` 生成查看。
- 官方通用 curl 模板（来源同上）：

```shell
curl -G 'https://developer.zhihu.com/api/v1/content/zhihu_search' \
  --data-urlencode 'Query=怎么理解rave文化' \
  -H 'Authorization: Bearer <your_access_secret>' \
  -H "X-Request-Timestamp: $(date +%s)" \
  -H 'Content-Type: application/json'
```

- 统一响应外层结构：`{ "Code": 0, "Message": "success", "Data": ... }`，`Code` 为 `0` 表示成功。

## 1. 账号创作数据：creator_account_stats

来源：官方文档 `https://developer.zhihu.com/console/api/v3/docs`（creator/creator_account_stats 节）；对照快照 `https://github.com/Akira-TL/xieyao-meow/blob/main/docs/reference/zhihu-open-platform/creator/creator-account-stats.md`（2026-09-12，除额度数字外与官方一致）。

### 1.1 地址与方法

| 说明 | 值 |
| - | - |
| HTTP URL | `https://developer.zhihu.com/api/v1/user/creator_account_stats` |
| HTTP Method | `GET` |

### 1.2 请求参数（Query）

| 名称 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `ContentType` | String | 否 | `all`、`answer`、`article`、`pin`、`zvideo`，默认 `all` |
| `StartDate` | String | 否 | 开始日期，格式 **`YYYY-MM-DD`**（不是时间戳）。必须与 `EndDate` 同时提供 |
| `EndDate` | String | 否 | 结束日期，格式 `YYYY-MM-DD`，不得早于 `StartDate`。必须与 `StartDate` 同时提供 |

约束：日期必须**成对提供或同时省略**；省略时使用服务端默认统计范围，不承诺固定天数。

### 1.3 响应字段（均位于 `Data`）

顶层：

| Data 字段 | 类型 | 可选 | 含义 |
| - | - | - | - |
| `ContentType` | String | 否 | 规范化后的内容类型 |
| `Metrics` | Object | 是 | 内容指标（累计值），见下表；含 `Yesterday` / `Today` 嵌套 |
| `Audience` | Object | 是 | 受众画像及可选 `Status` / `Reason` |
| `CreationCounts` | Object | 是 | `Answer` / `Article` / `Video` / `Follower` 数量（Int64） |
| `Followers` | Object | 是 | 粉丝概览（FollowerSummary） |
| `FollowerDetails` | Object | 是 | `Daily` 日序列、`Today`、`Period`（7/14/30 日周期）数据 |
| `FollowerProfile` | Object | 是 | 画像及互动对象，需结合 `Status` / `Reason` 使用 |

`Metrics`（累计 + 昨日/今日嵌套）：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Updated` | String | 是 | 统计更新时间 |
| `ViewCount` | Int64 | 是 | 阅读量 |
| `PlayCount` | Int64 | 是 | 播放量 |
| `UpvoteCount` | Int64 | 是 | 赞同数 |
| `CommentCount` | Int64 | 是 | 评论数 |
| `LikeCount` | Int64 | 是 | 喜欢数 |
| `CollectCount` | Int64 | 是 | 收藏数 |
| `ShareCount` | Int64 | 是 | 分享数 |
| `RepinCount` | Int64 | 是 | 转发数 |
| `PublishCount` | Int64 | 是 | 发布内容数 |
| `ClickRate` | Float64 | 是 | 点击率 |
| `ReadFinishedRate` | Float64 | 是 | 阅读完成率 |
| `PlayFinishedRate` | Float64 | 是 | 播放完成率 |
| `IncreasedUpvoteCount` | Int64 | 是 | 新增赞同数 |
| `DecreasedUpvoteCount` | Int64 | 是 | 减少的赞同数 |
| `IncreasedLikeCount` | Int64 | 是 | 新增喜欢数 |
| `DecreasedLikeCount` | Int64 | 是 | 减少的喜欢数 |
| `Yesterday` | Metrics | 是 | 昨日指标，字段结构同 Metrics（递归） |
| `Today` | Metrics | 是 | 今日指标，字段结构同 Metrics |

`CreationCounts`：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Answer` | Int64 | 否 | 回答数量 |
| `Article` | Int64 | 否 | 文章数量 |
| `Video` | Int64 | 否 | 视频数量 |
| `Follower` | Int64 | 否 | 粉丝数量 |

`Followers`（FollowerSummary）：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Total` | Int64 | 是 | 粉丝总数 |
| `Yesterday` | Int64 | 是 | 昨日粉丝净增数 |
| `NewYesterday` | Int64 | 是 | 昨日新增粉丝数 |
| `CancelledYesterday` | Int64 | 是 | 昨日取消关注数 |
| `ActiveCount` | Int64 | 是 | 活跃粉丝数 |
| `ActiveRatio` | String | 是 | 活跃粉丝占比（注意类型是 String） |

`FollowerDetails`：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Daily` | Array\<FollowerDaily\> | 是 | 粉丝数据日序列 |
| `Today` | FollowerDaily | 是 | 当日粉丝数据；实际统计日期以 `Date` 为准 |
| `Period` | FollowerPeriod | 是 | 7/14/30 日周期粉丝数据 |

`FollowerDaily`：`Date`(String, 必返)、`NetIncrease`(Int64 净增)、`NewCount`(Int64 新增)、`UnfollowCount`(Int64 取关)、`HomepageVisitorCount`(Int64 主页访客)、`HomepageFollowCount`(Int64 主页带来的关注)、`HomepageConversionRate`(Float64 主页转粉率)，除 `Date` 外均可选。

`FollowerPeriod`：`Date`(String, 必返) + 以下字段（均可选，7/14/30 天三档）：`NetIncrease7Days/14Days/30Days`、`NewCount7Days/14Days/30Days`、`UnfollowCount7Days/14Days/30Days`、`HomepageVisitorCount7Days/14Days/30Days`、`HomepageFollowCount7Days/14Days/30Days`、`HomepageConversionRate7Days/14Days/30Days`。计数为 Int64，转粉率为 Float64。

`Audience`（受众画像，本接口与单篇接口结构相同）：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Status` | String | 是 | 画像数据状态 |
| `Reason` | String | 是 | 画像状态或数据缺失原因 |
| `Source` | Array\<AudienceProfileItem\> | 是 | 访问来源分布 |
| `Activeness` | Array\<AudienceProfileItem\> | 是 | 活跃程度分布 |
| `ActiveTime` | Array\<AudienceProfileItem\> | 是 | 活跃时间分布 |
| `Content` | Array\<AudienceContentItem\> | 是 | 画像关联的内容列表 |
| `Gender` | Array\<AudienceProfileItem\> | 是 | 性别分布 |
| `Age` | Array\<AudienceProfileItem\> | 是 | 年龄分布 |
| `Interest` | Array\<AudienceProfileItem\> | 是 | 兴趣分布 |
| `Location` | Array\<AudienceProfileItem\> | 是 | 地域分布 |
| `OS` | Array\<AudienceProfileItem\> | 是 | 操作系统分布 |

`AudienceProfileItem`：`Name`(String, 必返 分类名称)、`Ratio`(Float64, 必返 占比)、`Count`(Int64, 可选 数量，缺失不补零)。
`AudienceContentItem`：`ContentType`(String)、`ContentToken`(String, 字符串保留精度)、`Title`(String)、`FollowCount`(Int64)，均必返。
`FollowerProfile`：`Status`(Int32, 可选；值为 0 时省略)、`Reason`(String, 可选)、`Audience`(Audience, 可选)、`Interactions`(FollowerInteractions, 可选)。`FollowerInteractions`：`Status`(Int32, 必返)、`Creators`(Array\<FollowerCreatorItem\>：`Avatar`/`MemberToken`/`Name`(String)、`FollowCount`(Int64))、`Content`(Array\<AudienceContentItem\>)。

### 1.4 响应示例（官方原文）

```json
{
  "Code": 0,
  "Message": "success",
  "Data": {
    "ContentType": "all",
    "Metrics": {
      "Updated": "2026-09-08 12:00:00",
      "ViewCount": 100,
      "UpvoteCount": 10,
      "Yesterday": {
        "ViewCount": 20
      }
    },
    "Followers": {
      "Total": 50,
      "Yesterday": 2,
      "NewYesterday": 3,
      "CancelledYesterday": 1
    }
  }
}
```

（官方注明：以下为结构示例，仅展示部分字段；示例数值不代表实际账号数据。）

### 1.5 分页

无。单次请求返回账号维度汇总。

### 1.6 错误码（官方原文）

| Code | 说明 |
| - | - |
| `0` | 请求成功 |
| `10001` | 参数错误或内容不可用 |
| `20001` | 鉴权或授权失败 |
| `30001` | 调用频率、并发或当日额度超限 |
| `30002` | 额外配置的成功次数额度耗尽 |
| `30003` | 请求被风控拒绝 |
| `90001` | 服务内部错误 |

### 1.7 解析注意（官方「字段阅读说明」）

- JSON 字段名区分大小写。
- 可选数值指标未返回时**不应补零**；已提供且为 0 的会保留。
- 状态/字符串/集合字段也可能因零值、空字符串、空集合而省略。
- Int64 计数保留整数精度（JS 中需注意，勿走 Number 丢精度）。
- 比例沿用上游原值，单位未明确时不要自行乘 100 或拼百分号。
- 统计可能延迟，日期范围不保证对每项指标同时生效。

## 2. 单篇创作数据：creator_content_stats

来源：官方文档 `https://developer.zhihu.com/console/api/v3/docs`（creator/creator_content_stats 节）；对照快照 `https://github.com/Akira-TL/xieyao-meow/blob/main/docs/reference/zhihu-open-platform/creator/creator-content-stats.md`（2026-09-12，除额度数字外与官方一致）。

### 2.1 地址与方法

| 说明 | 值 |
| - | - |
| HTTP URL | `https://developer.zhihu.com/api/v1/user/creator_content_stats` |
| HTTP Method | `GET` |

仅支持本人**已发布**的内容；草稿、未发布或其他不可用状态不在支持范围。

### 2.2 请求参数（Query）

| 名称 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `ContentUrl` | String | 是 | 当前用户创作的回答、文章、想法或视频链接 |
| `StartDate` | String | 否 | 开始日期，格式 `YYYY-MM-DD`，需与 `EndDate` 同时提供 |
| `EndDate` | String | 否 | 结束日期，格式 `YYYY-MM-DD`，不得早于 `StartDate` |

**`ContentUrl` 支持的写法**（官方「我的创作全文 API」节明确列出的知乎 HTTPS 链接格式，全文/评论/单篇统计三个接口共用该链接校验规则；来源 `https://developer.zhihu.com/console/api/v3/docs` creator/user_content_detail 节）：

| 内容类型 | `ContentUrl` 形式 |
| - | - |
| 文章 | `https://zhuanlan.zhihu.com/p/{id}` |
| 回答（短链） | `https://www.zhihu.com/answer/{id}` |
| 回答（完整链） | `https://www.zhihu.com/question/{id}/answer/{id}` |
| 想法 | `https://www.zhihu.com/pin/{id}` |
| 视频 | `https://www.zhihu.com/zvideo/{id}` |

官方同文档「PPT 生成 API」节对 `resource_url` 也给出了完全一致的三种回答/文章格式，可互相印证。

日期同 1.2：成对提供或同时省略；省略时用服务默认统计范围，不承诺固定天数。

### 2.3 响应字段（`Data`）

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Items` | Array | 否 | 单篇内容统计条目列表；**没有统计数据时可为空数组**（空数组 ≠ 各指标为零） |
| `Items[].ContentType` | String | 否 | 内容类型：`answer`、`article`、`pin`、`zvideo` |
| `Items[].ContentToken` | String | 否 | 内容标识，保留字符串精度 |
| `Items[].Url` | String | 否 | 内容链接 |
| `Items[].Title` | String | 是 | 内容标题，空标题省略 |
| `Items[].Metrics` | Object | 是 | 内容指标，见下 |
| `Items[].Audience` | Object | 是 | 受众画像，结构同 1.3 `Audience` |

`Metrics`（按天，`Date` 为统计日期）：

| 字段 | 类型 | 可选 | 说明 |
| - | - | - | - |
| `Date` | String | 是 | 统计日期（`YYYY-MM-DD`） |
| `ViewCount` | Int64 | 是 | 阅读量 |
| `PlayCount` | Int64 | 是 | 播放量 |
| `UpvoteCount` | Int64 | 是 | 赞同数 |
| `CommentCount` | Int64 | 是 | 评论数 |
| `LikeCount` | Int64 | 是 | 喜欢数 |
| `CollectCount` | Int64 | 是 | 收藏数 |
| `ShareCount` | Int64 | 是 | 分享数 |
| `RepinCount` | Int64 | 是 | 转发数 |
| `PublishCount` | Int64 | 是 | 发布内容数 |
| `ClickRate` | Float64 | 是 | 点击率 |
| `ReadFinishedRate` | Float64 | 是 | 阅读完成率 |
| `PlayFinishedRate` | Float64 | 是 | 播放完成率 |
| `PageShowUV` | Int64 | 是 | 内容曝光用户数（UV） |
| `NewFollowerCount` | Int64 | 是 | 新增关注用户数 |
| `FollowerConversionRate` | Float64 | 是 | 转粉率 |
| `PositiveInteractionRate` | String | 是 | 正向互动率（注意类型是 String） |
| `FollowerGain` | Int64 | 是 | 内容带来的转粉数量 |
| `IncreasedUpvoteCount` | Int64 | 是 | 新增赞同数 |
| `DecreasedUpvoteCount` | Int64 | 是 | 减少的赞同数 |
| `IncreasedLikeCount` | Int64 | 是 | 新增喜欢数 |
| `DecreasedLikeCount` | Int64 | 是 | 减少的喜欢数 |
| `UpvoteCount7Days` | Int64 | 是 | 7 日赞同数 |

## 3. 本人内容列表：user/contents

来源：官方文档 `https://developer.zhihu.com/console/api/v3/docs`（zhihu-user-data/user_contents 节）；对照快照 `https://github.com/Akira-TL/xieyao-meow/blob/main/docs/reference/zhihu-open-platform/user/user-contents.md`（2026-09-12，与官方一致）。

### 3.1 地址与方法

| 说明 | 值 |
| - | - |
| HTTP URL | `https://developer.zhihu.com/api/v1/user/contents` |
| HTTP Method | `GET` |

### 3.2 请求头

| Header | 必填 | 说明 |
| - | - | - |
| `Authorization` | 是 | `Bearer <your_access_secret>` |
| `X-Request-Timestamp` | 是 | 秒级 Unix 时间戳 |
| `X-OAuth-Token` | 否 | 不传时查询本人；传入时查询该 OAuth 凭证对应的**已授权用户**（LeafPress 查本人，不传即可） |
| `Content-Type` | 固定值 `application/json` | - |

### 3.3 请求参数（Query）

| 名称 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `Offset` | Int64 | 否 | 分页偏移量，默认 `0` |
| `Limit` | Int64 | 否 | 返回数量，默认 `20`，最大 `50` |
| `ContentType` | String | **是** | 可选值：`all`、`answer`、`article`、`zvideo`、`pin`、`question`；`all` 表示全部类型 |
| `SortField` | String | 否 | 排序字段：`like_count`、`ts`，默认 `ts`（时间） |
| `SortOrder` | String | 否 | 排序方向：`asc`、`desc`，默认 `desc` |

### 3.4 响应字段（`Data`）

| 参数名 | 类型 | 是否必返 | 描述 |
| - | - | - | - |
| `Items` | Array[ContentItem] | 是 | 内容列表 |
| `Paging` | Paging | 是 | 分页信息 |

`ContentItem`：

| 参数名 | 类型 | 是否必返 | 描述 |
| - | - | - | - |
| `ContentType` | String | 是 | 固定小写：`answer`、`article`、`zvideo`、`pin`、`question` |
| `Url` | String | 是 | 内容链接 |
| `CreatedAt` | Int64 | 是 | 内容创建时间，**秒级时间戳** |
| `LikeCount` | Int64 | 是 | 点赞数 |
| `CommentCount` | Int64 | 是 | 评论数 |
| `FavoriteCount` | Int64 | 是 | 收藏数 |
| `Title` | String | 是 | 内容标题 |
| `Summary` | String | 是 | 内容摘要 |

`Paging`：

| 参数名 | 类型 | 是否必返 | 描述 |
| - | - | - | - |
| `IsEnd` | Bool | 是 | 是否已到最后一页 |
| `NextOffset` | **String** | 否 | 下一页分页偏移量（注意：类型是 String，例 `"20"`） |
| `Totals` | Int64 | 是 | 总数 |

要点（写代码前必读）：

- **没有独立的「编号」字段**。内容标识要从 `Url` 里解析（回答 `…/answer/{id}`，文章 `zhuanlan.zhihu.com/p/{id}`），或用单篇统计接口返回的 `ContentToken`。
- **没有赞同数**，只有 `LikeCount`（点赞/喜欢）。要赞同数需另调单篇创作数据接口（`UpvoteCount`）。
- **没有发布时间以外的编辑时间字段**，只有 `CreatedAt`。
- 回答的 `Title` 是不是问题标题：官方示例（见 3.5）中 `ContentType: "answer"` 的条目 `Title` 为「如何理解某个问题？」——形式上是问题标题。但官方文档**没有一句话明说**回答条目的 `Title` 就是所属问题标题，此点标注为「示例可推断，未见官方明文」（见 BLOCKED）。

## 4. 额度查询：quota

来源：官方文档 `https://developer.zhihu.com/console/api/v3/docs`（guide/quota 节）；对照快照 `https://github.com/Akira-TL/xieyao-meow/blob/main/docs/reference/zhihu-open-platform/core/quota.md`（2026-09-12，额度项列表与官方现行版不一致，见 6.2）。

### 4.1 地址与方法

请求行（官方原文）：`GET /api/v1/quota`，完整地址 `https://developer.zhihu.com/api/v1/quota`。

该查询**不消耗业务额度**。

### 4.2 请求头

| 参数 | 必填 | 说明 |
| - | - | - |
| `Authorization` | 是 | `Bearer <your_access_secret>` |
| `X-Request-Timestamp` | 是 | Unix 秒级时间戳，**与服务端时间相差不能超过 10 分钟** |

### 4.3 Query 参数

| 参数 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `APIIDs` | String | 否 | 多个 API ID 用**逗号**分隔；`APIIDs` 参数**只能出现一次**；未提供时返回当前已配置的可展示额度 |

示例：`GET /api/v1/quota?APIIDs=knowledge,zhihu_search`

### 4.4 可查询额度项（官方现行版）

| API ID | 名称 | 覆盖范围 |
| - | - | - |
| `global_search` | 全网搜索 | 全网搜索 |
| `zhihu_search` | 知乎搜索 | 知乎内容搜索 |
| `hot_list` | 热榜 | 知乎热榜 |
| `question_discovery` | 问题发现 | 问题推荐及问题回答摘要 |
| `zhida_openai` | 直答 | 直答服务 |
| `tools` | 小工具 | PDF 解析及 PPT 生成 |
| `knowledge` | 知识库 | 知识库文件上传、知识库列表、知识库内容列表及知识库检索 |
| `user_data` | 知乎用户数据 | 用户创作列表、关注、收藏及收藏夹数据 |
| `creator` | 创作能力 | 本人全文、评论、账号统计、单篇统计 |

不传 `APIIDs` 时按上表顺序返回当前已配置额度项；尚未接入额度配置的 API 会被省略，不会导致整个列表失败。显式请求多个 API 时同样返回其中已配置的子集；若全部尚未配置，成功返回空数组。账号关联多个租户时，查询结果会汇总相关租户额度。

### 4.5 响应字段（`Data` 为数组）

| 字段 | 类型 | 说明 |
| - | - | - |
| `APIID` | String | 额度项 ID |
| `APIName` | String | 额度项名称 |
| `TotalQuota` | Int64 | 当前自然日总额度 |
| `TotalUsed` | Int64 | 当前自然日已使用额度 |
| `RemainingQuota` | Int64 | 当前自然日剩余额度，最低为 0 |

### 4.6 响应示例（官方原文）

```json
{
  "Code": 0,
  "Message": "success",
  "Data": [
    {
      "APIID": "knowledge",
      "APIName": "知识库",
      "TotalQuota": 500,
      "TotalUsed": 12,
      "RemainingQuota": 488
    }
  ]
}
```

### 4.7 调用示例（官方原文）

```bash
curl -G 'https://developer.zhihu.com/api/v1/quota' \
  --data-urlencode 'APIIDs=knowledge,zhihu_search' \
  -H 'Authorization: Bearer <your_access_secret>' \
  -H "X-Request-Timestamp: $(date +%s)"
```

### 4.8 错误码（官方原文）

| Code | 说明 |
| - | - |
| `10001` | `APIIDs` 参数格式错误或包含未知 API ID；旧客户端参数不兼容时提示更新到最新版 Zhihu CLI |
| `20001` | Access Secret 鉴权失败 |
| `30001` | 请求频率超过限制，请稍后重试 |
| `90001` | 额度数据读取失败 |

### 4.9 分页

无。

## 5. 每日免费额度规则

来源：官方文档「服务价格」「鉴权」「Zhihu CLI」及各创作接口节，`https://developer.zhihu.com/console/api/v3/docs`。

1. 平台提供**每日免费调用额度**，部分服务**共用同一额度组**：调用组内任一服务都消耗该组的剩余免费次数。
2. **创作能力组**（本人全文 `content_detail`、评论 `content_comments`、账号统计 `creator_account_stats`、单篇统计 `creator_content_stats`）共用一个额度，quota 项 ID 为 `creator`。
3. **知乎用户数据组**（用户创作列表 `contents`、关注 `followees`、收藏 `collections`、收藏夹 `favlists`、收藏夹内容 `favlist_contents`）共用 `user_data` 额度。
4. 同一知乎账号下的**多个 Access Secret 共用**该账号的额度。
5. 每日额度按**北京时间 00:00 重置**，未用完的次数**不结转**。每日免费额度属于限时优惠，后续可能根据活动情况调整。
6. 免费额度用完后可付费继续调用（价格见官方「服务价格」节：账号创作数据、单篇创作数据均 10 元/千次；用户创作内容摘要 10 元/千次；计费按成功调用次数，鉴权失败/参数错误/触发限流不计费；余额不足时请求不执行）。
7. 各服务实际剩余次数见「个人中心 - 用量统计 - 各接口限免额度」，或直接调 quota 接口。

### 5.1 具体数字：官方与社区快照不一致（两种都列）

**官方文档（2026-10-09 抓取）**：

- 创作能力组：「默认每个租户每个自然日**共计 200 次**，未实名等低额度用户为 10 次」。（creator_account_stats / creator_content_stats / user_content_detail / user_content_comments 四节均为 200 次。）
- 问题发现组：「默认每个租户每个自然日 100 次，未实名等低额度用户为 10 次」。
- 小工具组（PDF 解析 + PPT 生成共用）：「普通用户每天 10 次，低额度用户每天 2 次」。
- 官方文档**没有「实名用户 100 次」这一表述**；任务书里的「100 次」未在官方现行文档出现。

**社区快照（xieyao-meow，2026-09-12 抓取的官方页面）**：

- 创作能力组：「默认每个租户每个自然日共计 **100 次**，未实名等低额度用户为 10 次」，且快照称组内还包含「两种问题推荐」（个性化问题推荐、根据主题推荐问题）。
- 快照中另有独立「知乎问题回答」额度。

结论：官方在 2026-09-12 → 2026-10-09 之间把创作能力组额度从 100 提到 200，并把问题推荐拆到「问题发现」组。**写代码时不要硬编码具体数字，一律以 quota 接口返回的 `TotalQuota` 为准**（官方原文也反复强调「实际额度以额度查询结果为准」）。

## 7. BLOCKED（未收全 / 拿不准）

1. **单篇创作数据多天返回形态未确认**：官方只给了一天（`Date: "2026-09-08"`）的示例。传起止日期时 `Items` 是否一天一条、还是一条内含多天序列，官方文档没写。LeafPress 需实测或按天调用（`StartDate=EndDate`）验证。
2. **user/contents 回答条目 `Title` 是否恒为问题标题**：官方示例可推断，但无明文。稳妥做法：answer 类型用「问题标题 + 回答摘要」展示，或调全文接口取 `Title`。
3. **`ContentUrl` 带查询参数（如 `?utm_...`）是否被接受**：官方只说支持上述五种 HTTPS 路径格式，未说明带 query 是否通过校验。
4. **创作能力组「200 次」的适用前提**：官方写「默认每个租户每个自然日共计 200 次」，租户与知乎账号的对应关系（个人号是否即一个租户）未说明；与快照的 100 次冲突处理建议见 5.1。
5. **额度查询项 `question_answers` vs `question_discovery` 的过渡**：快照（旧）有 `question_answers`，官方现行有 `question_discovery`；传旧 ID 是否仍被识别未验证（quota 接口对未知 ID 返回 `10001`）。

## 8. 实测（2026-10-10）

> 2026-10-10 主控用作者的真实密钥对开放平台做了一次只读核对。**本节以下面的实测为准；与上文官方文档不一致处，以这里为准。**

1. **每秒限流**：
   - 内容列表 0.7 秒内连发 3 次，第 3 次返回 `{"Code":30001,"Message":"second limit exceeded"}`；
   - 每次请求间隔 1.3 秒，连发十几次都没被拦。
2. **偶发失败**：单篇数据、账号数据都出现过 `{"Code":90001,"Message":"request failed"}`，隔几秒重试同一个请求就成功。
3. **额度**：`GET /api/v1/quota?APIIDs=creator` 返回 `{"Code":0,"Data":[{"APIID":"creator","APIName":"创作能力","TotalQuota":200,"TotalUsed":0,"RemainingQuota":200}]}`。
   - 内容列表属于 `user_data`，每天 10000 次；
   - 查额度本身不占 `creator`。
4. **单篇数据 `creator_content_stats`，不带日期**：返回 1 条。
   - `Items[0].Metrics` 是**到现在为止的累计**，含今天，例如 `ViewCount 12071, UpvoteCount 66, CollectCount 176, CommentCount 28`；
   - 同一个 `Metrics` 里嵌着 `Today: { Date: "2026-10-10", ViewCount: 112, … }` 和 `Yesterday: { Date: "2026-10-09", ViewCount: 100, … }`，是那一天各自的数；
   - 实测：累计 − `Today` = 按「发布日 → 昨天」请求得到的整段合计（12071 − 112 = 11959），两种算法对得上。
5. **单篇数据，带起止日期**：只返回 1 条整段合计，`Metrics` 里没有 `Date`，**不会每天一条**。范围很长时直接 90001：从 2025-08-18 或 2020-01-01 起都失败，50 天的范围能成功。
6. **账号数据 `creator_account_stats`**：`Data` 的结构：
   - `Metrics`：累计（`ViewCount` 等），嵌 `Yesterday`、`Today`；
   - `Followers: { Total: 186, Yesterday: 0, NewYesterday: 0, CancelledYesterday: 0, ActiveCount, ActiveRatio }`；
   - `FollowerDetails: { Today: { Date: "2026-10-09", NetIncrease, … }, Period: {…} }`；
   - `CreationCounts: { Answer: 44, Article: 18, … }`。
7. **内容列表**：
   - 一页 `Limit=50` 实际返回 44 条，有过滤，必须按 `Paging.NextOffset` 翻页，不能拿条数判断；
   - 类型有 `pin`、`article`、`answer`、`question`；
   - 回答的链接是短链接 `https://www.zhihu.com/answer/<编号>`。

## 9. 问题发现、热榜、搜索（跑灵感用，2026-10-19）

来源：三路侦察逐字读官方文档 JSON（`https://developer.zhihu.com/console/api/v3/docs`，2026-10-19 抓取）并对照社区快照；主控用作者的账号实测一次（下面「实测」各条）。用在 [灵感 · 跑灵感](../模块设计/灵感-跑灵感.md)。

### 9.1 问题推荐：`GET /api/v1/user/question_recommendations`

| 参数 | 必填 | 说明 |
|---|---|---|
| `Query` | 否 | 主题关键词。**不传**按当前账号画像推荐；传了按主题推荐；传空串或纯空白报 `10001` |
| `Count` | 否 | 默认 5，1～20 |

- 返回 `Data.Items[]` 只有 `Title`、`Url` 两个字段：没有浏览量、关注数、回答数、创建时间、热度、推荐理由，问题编号要从 `Url` 里取。
- 不分页；返回可能不足 `Count` 或为空。
- 额度：「问题发现」组（`question_discovery`），和问题回答共用，实名账号每天 100 次。日额度用完返回 `30001`。

### 9.2 问题回答：`GET /api/v1/content/question_answers`

| 参数 | 必填 | 说明 |
|---|---|---|
| `QuestionUrl` | 是 | 完整的知乎问题链接 |
| `Offset` | 否 | 默认 0 |
| `Limit` | 否 | 默认 20，1～50 |

- 每个回答只有 `ContentType`（固定 answer）、`ContentToken`、`Url`、`Summary`（服务给的截取文本，不是 AI 摘要、不是全文）；没有赞同数、作者、时间；排序方式官方没说。
- 分页用 `Paging.IsEnd`、`Paging.NextOffset`（Int64）；`Paging.Totals` 文档说是回答总数，「未提供时可能不返回」。
- 额度同 9.1；`10001` 在这里还表示问题不存在。

### 9.3 热榜：`GET /api/v1/content/hot_list`

- 只有 `Limit`（默认、最大 30）；返回 `Total` 和 `Items[]{Title, Url, ThumbnailUrl, Summary}`，没有任何数字。
- 额度 `hot_list`；错误码只有 0、20001、30001、90001。

### 9.4 知乎搜索：`GET /api/v1/content/zhihu_search`

- `Query` 必填；`Count` 默认、最大 10；`SortBy` 形如 `字段:方向:(最小,最大)`，字段只有 `CommentCount`、`VoteUpCount`、`EditTime`（发布时间）。
- 不能只搜问题：结果混着问题、回答、文章，只能按 `ContentType` 自己筛；`HasMore` 固定 false，不能翻页。
- 每条有 `Title`、`ContentType`、`ContentID`、`ContentText`（可能带 `<em>`）、`Url`（带 `utm_` 参数）、`CommentCount`、`VoteUpCount`、作者信息、`EditTime`、`AuthorityLevel`、`RankingScore`。
- 额度 `zhihu_search`。

### 9.5 实测（作者账号，2026-10-19）

1. **额度**：`question_discovery` 100、`hot_list` 100、`zhihu_search` 5000、`global_search` 5000、`creator` 200（每天）。
2. **个性化推荐**（`Count=10`，0.6 秒）：10 条全是问题，内容是理财（红利低波、定投）、服务器、Vibe Coding，对得上作者在知乎写过的方向。
3. **主题推荐**（`Query=大模型`，1 秒）：5 条都是 AI 相关问题。
4. **拿博客标题当主题词**：「claude code里面使用chatgpt的模型教程」推回来 8 个 Claude Code 问题，其中「如何让claude code自由选择不同的大模型？」几乎就是这篇博客的题；短关键词「黑苹果 硬件」推回来的是泛泛的硬件问题，跑偏。
5. **问题回答**（`Limit=5`，0.9 秒）：`Paging` 只有 `IsEnd`、`NextOffset`，**没给 `Totals`**；摘要每条 140～230 字。所以拿不到回答数。
6. **搜索**（1.4 秒）：10 条里 9 条是文章、1 条是回答（回答的 `Url` 里有问题编号，`Title` 是问题标题加「 - 知乎」）。
7. **热榜**（0.7 秒）：30 条全是问题，基本是社会新闻。
