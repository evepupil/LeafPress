# 知乎相关工具
> 调研日期：2026-10-01

> **核实更正（2026-10-01，另派一路换模型核对官方页面，以本段为准）**
> - 免费额度：官方首页写的是「注册免费获取 5000 次/天调用」；正文里「每天 1000 次」只见于第三方文章，官方站内没有这个数字。
> - 单个接口另有上限：问题推荐、问题下回答摘要默认每天 100 次；创作数据类接口每天共 200 次；未实名认证的用户每天 10 次。
> - 超出后按千次付费：知乎搜索 20 元、全网搜索 15 元、热榜 10 元（官方计费文档）。官方 FAQ 另写「邀测阶段，计费请与商务沟通」，两处口径并存。
> - 个人可用：官方文档只要求用知乎账号登录后生成 Access Secret，没有企业门槛；需要公司信息的只有 OAuth 应用接入。
> - 接入形态：除 API 外，官方给各接口都配了 Skill 和 MCP，另有统一的知乎 MCP 和官方命令行工具 Zhihu CLI（附 skill 包）。
> - 上线时间：「2026 年 5 月」只有第三方报道（约 5 月 17～18 日），官方页面没写日期。

## 结论
1. **知乎官方已经把「读」全面开放了，这是委托人现有工具之外最大的空白**：developer.zhihu.com 数据开放平台（2026 年 5 月上线）提供搜索、热榜、问题推荐、直答、本人创作数据统计等 20 多个端点，注册后在个人中心拿 Access Secret 即可用，免费额度每天约 1000 次（页面另一处写注册送 5000 次/天，两处数字不一致，见「拿不准的点」），支持 API / MCP / Skill 三种接入方式。委托人缺的「找值得回答的问题」「数据回看」两件事，官方接口直接就能做，不需要逆向。出处：https://developer.zhihu.com/ 、https://developer.zhihu.com/docs
2. **写回答前「找问题」已有一条官方通路**：官方有 `GET /api/v1/user/question_recommendations`（问题推荐，走账号画像）和 `GET /api/v1/content/question_answers`（问题下回答摘要）两个端点；开源封装里 klarkxy/zhihu-search 已经把这两个端点连同 22 个端点全部包好，提供 CLI + MCP + Skill 三种形态，2026-10-01 还在提交。「按关键词找浏览量高但回答少的问题」没有现成开源工具，但用官方 `zhihu_search` 拉结果后自己按 `answer_count`/浏览量过滤即可补上，工作量很小。出处：https://github.com/klarkxy/zhihu-search/blob/main/docs/API_COVERAGE.md
3. **「数据回看」官方给的是统计口径，第三方给的是监控口径，两者互补**：官方 `creator_account_stats` / `creator_content_stats`（账号和单篇创作数据）可通过 klarkxy/zhihu-search 的 `creator` 档位被 AI 助手调用；233stone/zhihu-data 补的是官方后台没有的点击率、完读率和 10 分钟级趋势，但它走创作者中心 Cookie + 手动配 x-zse-96 签名，是本地 Flask 看板而非 AI 可调用的接口，只能当兜底。出处：https://developer.zhihu.com/docs 、https://github.com/233stone/zhihu-data
4. **发布链路委托人已经够用，别引入逆向类工具**：zhihu-publisher（官方 skill，走 openapi.zhihu.com 签名接口，每人每天限发 50 次）+ 委托人自写 skill 已覆盖发布；GitHub 上的知乎 MCP 基本是 Cookie 登录态或逆向 zse96 签名路线（meurz/zhihu-mcp-server 已归档、Douyh123/zhihu-mcp 半年没动、VSCode-Zhihu 作者已声明停维护），有登录态和风控风险，不建议碰。
5. **Markdown 转知乎格式这条线被官方 skill 部分替代**：md2zhihu（80 星、不支 Windows、靠 git 分支图床）和 VSCode-Zhihu（943 星、2023 年停更、登录已坏）都是旧时代产物；委托人的 zhihu-publisher 自带 validate/preview 转换链路，格式转换的空白只剩「命令行单文件转换小工具」这种锦上添花的需求。

## 知乎官方开放能力

知乎现在有两条「官方」通路，委托人手里的 zhihu-publisher 只用到了其中一条（发布）：

**① 数据开放平台 developer.zhihu.com（读为主，2026 年 5 月开放）**
- 地址：https://developer.zhihu.com/ （文档目录：https://developer.zhihu.com/docs ）
- 统一接入域名 `https://developer.zhihu.com`，`Authorization: Bearer <Access Secret>` 鉴权，Access Secret 在个人中心获取，无需 app_key 签名。
- 开放的能力（据 klarkxy/zhihu-search 对官方目录的核对，快照 2026-09-28，官方目录共 33 条文档：3 指南、22 API、4 Skill、4 MCP，22 条 API 含 24 个业务端点）：
  - 搜索：知乎站内搜索 `GET /api/v1/content/zhihu_search`（单次上限 10 条）、全网搜索 `global_search`（上限 20 条）
  - 热榜：`GET /api/v1/content/hot_list`（上限 30 条）
  - 直答（知乎自研大模型）：`POST /v1/chat/completions`
  - **问题发现**：`GET /api/v1/user/question_recommendations`（按画像推荐适合回答的问题）、`GET /api/v1/content/question_answers`（问题下回答摘要）
  - 本人公开数据：用户创作列表、关注、收藏、收藏夹
  - **创作数据**：`GET /api/v1/user/creator_account_stats`（账号级）、`GET /api/v1/user/creator_content_stats`（单篇级）、本人创作全文、本人创作评论
  - 知识库（上传/检索）、PDF 解析、PPT 生成、官方额度查询 `GET /api/v1/quota`
  - OAuth：`openapi.zhihu.com/authorize` + `/access_token`（授权码换 token，供拿用户授权）
- 门槛与额度：注册后在个人中心拿 Access Secret 即可；免费额度一说是每天 1000 次调用（weste.net 报道、jzl.com 选型文），官方页面另有「注册免费获取 5000 次/天调用」字样，两处矛盾，未实测。计费：官方 FAQ 写「当前处于邀测阶段，具体计费方案请与商务团队沟通」。申请更高配额需邮件联系提供使用场景。
- 没看到面向个人的「写回答」接口；写操作走的是下面第②条。
- 出处：https://developer.zhihu.com/ 、https://developer.zhihu.com/docs 、https://github.com/klarkxy/zhihu-search/blob/main/docs/API_COVERAGE.md 、https://www.weste.net/2026/05-19/zhihu-API-MCP-Skill.html 、https://www.jzl.com/news/zhihu-api

**② 发布 OpenAPI openapi.zhihu.com（写）**
- zhihu-publisher skill 调用的 `POST https://openapi.zhihu.com/openapi/publish`，`X-App-Key` + HMAC-SHA256 签名（app_key 从个人主页 URL 取，app_secret 从 https://www.zhihu.com/playground/zhihu-publisher 申请）；支持 article / question / pin 三种类型，频率限制为每人每天最多发布 50 次（skill 文档自述）。
- 出处：https://github.com/zhihu/ZhihuPublisher （reference/publish-openapi.md）

**官方 GitHub org**：https://github.com/zhihu （37 个公开仓库，330 followers；ZhihuPublisher 仓库无 LICENSE 文件，GitHub API 显示 no-license，与其发布渠道 skills.sh 上的描述并存，与委托人本机「MIT」的版本信息不一致，未核实到 MIT 授权文本，见「拿不准的点」）

## 拿不准的点
1. **官方免费额度数字矛盾**：developer.zhihu.com 首页 FAQ 写「注册免费获取 5000 次/天调用」，但 weste.net 报道和 jzl.com 选型文都写「每天 1000 次」。两处都未实测，且 FAQ 同时写「邀测阶段，计费与商务沟通」，额度政策可能在变动。建议委托人注册后在官方 `GET /api/v1/quota` 端点自查。
2. **zhihu-publisher 的开源协议**：委托人本机版本署 MIT，但 GitHub 上 zhihu/ZhihuPublisher 仓库没有 LICENSE 文件（GitHub API 返回 no-license），未核实到 MIT 授权文本，可能协议只在发布渠道（skills.sh）或 npm 包元数据里声明。
3. **官方是否面向个人开放「写回答」接口**：开发平台 24 个业务端点里只看到发布相关接口在 openapi.zhihu.com（zhihu-publisher 用的 /openapi/publish，含 question 类型即「发提问」，未见「写回答/answer」端点）；不排除有未公开的灰度能力。第三方文（xiaobei 项目注释）称「知乎没有对个人开发者开放的发布 API」，与 zhihu-publisher 实际能发文章/提问/想法的事实并存——准确说法是：能发文章/提问/想法，没看到「以回答身份写 answer」的接口。
4. **逆向/自动化类工具的封号反馈**：GitHub 搜索和 issue 检索中没有找到知乎因使用 MCP/爬虫工具封号的直接公开案例（只有 klarkxy 文档提到上游 30003 风控拒绝码），不能证明没有风险，只能说明没搜到。低调低频使用是社区共识，但无官方背书。
5. **klarkxy/zhihu-search 的 license 是 NOASSERTION**（自定义 LICENSE 文本，未逐条读），商用/二次分发前需自行确认条款。
6. **233stone/zhihu-data 的可用性**：x-zse-96 签名需手动从 DevTools 获取，知乎近期改版后是否仍能取到该参数未验证（仓库 2026-08 还有提交，README 没提失效，倾向可用但未实测）。
