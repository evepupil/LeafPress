# B站投稿与运营工具
> 调研日期：2026-10-01

## 结论
1. **视频投稿首选 biliup（biliup/biliup）**：5463 star、MIT、2026-09-30 仍在提交，是本轮律师函风波后唯一保持活跃的主力工具；字段覆盖最全（标题/简介/标签/分区/封面/分P/定时发布/合集管理），自带官方 AI 助手 skill（`npx skills add biliup/biliup`），有 Windows 安装包，与 Claude Code 的配合是所有选项里最顺的。
2. **别碰「bilibili-api（Python 库）」及其下游 MCP**：2026-07-06 收到 B站委托律所的侵权告知函，仓库已归档并删代码；基于它做的 bilibili-mcp（如 adoresever/bilibili-mcp，上传/发动态/发专栏功能最全）随时可能步后尘，且法律风险明确。同样原因，bilibili-API-collect 接口文档集（20k+ star）已于 2026-01-28 关停——B站从 2026 年起系统性打击逆向生态，这个趋势不会逆转。
3. **官方开放平台个人用不了**：入驻要求中国境内法人、营业执照彩色扫描件、盖章承诺函，官方文档明示「暂未开通个人开发者的申请入驻」；视频投稿（ARC_BASE scope）、专栏稿件发布都在权限白名单里，需申请+审核。委托人是独立开发者（个人主体），短期走不通，有公司主体后可作为合规正解。
4. **专栏/图文动态自动发布目前没有安全可用的现成工具**：唯一能发的开源 MCP（adoresever）底层库已死；官方接口又只对企业开放。建议动态先靠 biliup 投稿时附带的粉丝动态字段（`dynamic`）半自动覆盖，图文动态/专栏手动发。
5. **读评论、做选题调研可以用 XZXZZX-Ai/bilibili-mcp**（只读：字幕/评论/搜索，Apache-2.0，2026-09-27 仍活跃），与投稿链路解耦，风险低。通用多平台上传工具（如 MediaCrawler 系、social-auto-upload 等）不在本轮范围内，另有同事负责。

## 官方能力
- 入口：哔哩哔哩开放平台 https://openhome.bilibili.com/ （文档 https://openhome.bilibili.com/doc ）
- **个人能不能用：不能。** 官方镜像文档明示「暂未开通个人开发者的申请入驻」；入驻准入要求为「在中国境内合法成立并存续的法人」，需提交营业执照彩色扫描件、盖章《入驻承诺函》（出处：https://bilibili.apifox.cn/doc-885661 、https://open.bilibili.com/agreement/management-protocol 、https://www.explinks.com/api/scd20240709052919a4a3d7 ）。
- 开放的内容能力（对通过资质审核的开发者）：视频稿件投递/编辑/删除（`ARC_BASE` scope，需申请权限+用户授权，接口 `member.bilibili.com/arcopen/fn/archive/add-by-utoken`，支持 title/cover/tid/tag/copyright/desc/no_reprint 等，非正式会员单日限投 5 稿，出处：https://openhome.bilibili.com/doc/4/f7fc57dd-55a1-5cb1-cba4-61fb2994bf0f ）；专栏稿件发布/删除/查询（`/arcopen/fn/article/add`，出处：https://open.bilibili.com/doc/4/ddf67fb6-daad-6023-b67a-cc06a28caa4c 、https://bilibili.apifox.cn/api-23767554 ）；视频分区查询（https://openhome.bilibili.com/doc/4/4f13299b-5316-142f-df6a-87313eaf85a9 ）。
- 限制：投稿接口在「接口权限白名单」，创建应用需填写申请理由并经审核；稿件提交后有审核期。定时发布、分P 是否在开放平台参数里未核实到（见「拿不准的点」）。
- 对比：直播开放平台（open-live.bilibili.com）另有「个人开发者」注册入口（https://open-live.bilibili.com/open-register-form/personal ），但那只是直播互动玩法，不含视频投稿。

## 工具逐个说明

### biliup（B站录播+投稿一体化工具链，事实上的开源标准）
- 地址：https://github.com/biliup/biliup
- 形态：命令行（Rust 二进制）+ 自托管 WebUI（Next.js，默认端口 19159）+ Python 投稿库（bili_webup）+ **AI 助手 skill（仓库根目录 SKILL.md，`npx skills add biliup/biliup`）**；另有 Windows 桌面版安装包
- 能做什么：`upload`（多P：多个文件参数）、`append`（向已有稿件追加分P）、`show`/`list`/`comments`/`reply`（查稿件、读评论、回复评论）、`season`（合集管理：列合集/加稿/移出/排序）、`login`（短信/密码/扫码/浏览器/Cookie 五种登录）、`server`（WebUI 投稿模板、边录边传、切片投稿）。投稿字段（源码 `Studio` 结构体，https://github.com/biliup/biliup/blob/master/crates/biliup/src/uploader/bilibili.rs ）：copyright、source、tid/tid_v2（分区）、cover、title、desc、dynamic（粉丝动态文案）、tag、videos（分P 列表）、**dtime（定时发布，需大于提交时刻 4 小时的 10 位时间戳）**、no_reprint、is_only_self、charging_pay（充电）、dolby、lossless_music（Hi-Res）、interactive、mission_id（活动）、open_subtitle
- 实现方式：逆向网页端创作中心接口，借用户登录态（cookie+token 存 `cookies.json`）；非官方接口
- AI 助手能否调用：**能，且官方原生支持**——README 明说「提供 skill，让你的 Agent 成为 up 主」，SKILL.md 覆盖安装/登录/上传/追P/合集全流程；CLI 本身也天然适合 Claude Code 驱动
- 开源协议：MIT
- 活跃度：5463 star，最近提交 2026-09-30（gh api 实读），未归档；注意主仓库已把 Rust CLI（原 biliup-rs）收编，Release 里的 biliupR 二进制就是命令行版
- 已知坑：上传过频被风控拦截——Issue [#1565 上传次数过快导致失败](https://github.com/biliup/biliup/issues/1565)、[#1583 投稿过于频繁如何解决](https://github.com/biliup/biliup/issues/1583)（WebUI 切片发布已内置 601 暂停机制）；[#1762 转载类型稿件不支持活动参加](https://github.com/biliup/biliup/issues/1762)。定位以录播/切片为主，纯录屏教程用它主要是投稿功能
- 对委托人的价值：**高**——字段最全（含定时发布/分P/合集）、Windows 有安装包、官方 skill 直接对接 Claude Code
- 出处：README https://github.com/biliup/biliup#readme 、使用文档 https://biliup.github.io/biliup/docs/guide/introduction/ 、CLI 文档 https://biliup.github.io/biliup-rs

## 专栏 / 图文动态发布现状
- 开源侧：唯一有 `bili_send_opus`（专栏）/`bili_send_dynamic`（图文动态）能力的是 adoresever/bilibili-mcp，底层库已因律师函关停（见上）；原 bilibili-api-python 的 Article/Dynamic 模块随库死亡。
- 官方侧：开放平台有「专栏稿件管理」（发布/删除/查询，`/arcopen/fn/article/add`，出处：https://open.bilibili.com/doc/4/ddf67fb6-daad-6023-b67a-cc06a28caa4c ），但企业专属。
- 结论：截至 2026-10-01，个人开发者没有安全合规的专栏/图文动态自动发布工具，建议手动发布，视频投稿的粉丝动态文案用 biliup `dynamic` 字段带上。

## 拿不准的点
- **B站开放平台投稿接口是否支持定时发布/多分P**：文档页为 JS 动态加载，只抓到部分参数表（title/cover/tid/tag/copyright/desc/no_reprint 等），未见到 dtime 或 videos 数组字段，也未见到明确「不支持」的说明——留待有企业主体后再在 https://openhome.bilibili.com/doc/4/f7fc57dd-55a1-5cb1-cba4-61fb2994bf0f 核实。
- **biliup 的长期法律风险**：它同样逆向网页投稿接口，但律师函风波（2026-01、2026-07）后至今（2026-09-30）仍在活跃提交、未收到公开的关停声明；能否长期存续无保证，README 免责声明也明确「不保证稳定性、仅供个人学习研究」。
- **Iseenope/bilibili-mcp-server**（https://github.com/Iseenope/bilibili-mcp-server ，31 工具，5 star，2026-07-18 创建）：自述含动态/专栏/直播截图功能，推测也基于 bilibili-api-python，未逐一核实其依赖与风控表现，star 过少不单列。
- **XZXZZX-Ai/bilibili-mcp 的评论区只读是否稳定**：近期活跃但样本期短，未查到风控相关 Issue。
- **bilibili-mcp-js / adoresever 是否受律师函波及而主动下架**：尚未发生（截至 2026-10-01 均未归档），无法预测。
