# 多平台视频上传与一体化平台
> 调研日期：2026-10-01

## 结论
1. **视频主路线选 social-auto-upload**：三平台（B站/抖音/小红书）全覆盖、CLI + 官方 skill 对 AI 助手最友好、15k+ star 社区最大；但它走的是浏览器自动化灰色地带，小红书风控（issue #289）和 headless 登录被识别（#224）都是最近还在发生的事，必须拿小号先跑通再上主号。
2. **只想发视频、想省事就选 Spreado**：Windows 有现成 exe，`spreado login` / `spreado upload` 两条命令搞定，还带定时；但只有 4 个平台、不支持图文、不支持 B站，社区小（134 star）。
3. **AiToEarn star 最多（26.6k）、覆盖最广（含 X/YouTube/海外）**，但本质是「云服务 + 官网注册拿 API Key」的产品，发布经其服务器/开放平台中转，私有化部署也依赖授权通道（issue #560）；对在意账号数据可控的个人开发者不是首选，除非确实要分发海外平台。
4. **图文分发补一个 Wechatsync**：Chrome 插件借用已登录 Cookie 调平台官方 Web 接口、默认只存草稿，风险最低，且有 CLI/MCP/Claude Code plugin；但它完全不碰视频。
5. MCP 类小项目（social-publisher-mcp、torns/social_media_pubulish_MCP）思路对路但 star ≤1、单人维护，当参考实现看看即可；矩阵类重系统（Prism、MatrixFlow）面向多账号运营团队，单人单账号用不上。

### social-auto-upload（最主流的国产多平台视频上传工具，正全面 CLI/Skill 化重构）
- 地址：https://github.com/dreammis/social-auto-upload
- 形态：Python 库 + 命令行（`sau` CLI）+ AI 助手 skill（抖音/快手/小红书/B站四份 SKILL.md + 脚本模板，含 PowerShell 示例）；历史 Web 前后端保留但已非主线（docs/legacy-web.md）
- 覆盖平台（README 平台表，列：登录/视频/图文/定时/CLI/Skill）：
  - 抖音 ✅✅✅✅✅✅；B站 ✅✅（无图文）✅✅✅，运行时自动准备 biliup；小红书 ✅✅✅✅✅✅；快手 ✅✅✅✅✅✅；视频号 ✅✅（无图文）✅✅（无 skill）；百家号/支付宝生活号/微博/虎扑 ✅ 视频 ✅ CLI；TikTok 视频+定时 ✅（无 CLI）；YouTube 视频+CLI ✅（无定时，支持播放列表/可见性）。X（Twitter）不支持。
- 实现方式：扫码/浏览器登录存 cookie + Playwright（重构中换 patchright 提升隐蔽性）；无官方发布接口（B站例外，走 biliup）
- 定时/多账号/封面标签：定时发布覆盖抖音/B站/小红书/快手/视频号/TikTok；一个 account_name 对应一份 cookie 文件即可多账号；标签/描述 CLI 参数齐全，封面是近期修复重点（抖音封面参数未稳定生效 #259，快手封面已修 #255）
- 登录与无界面：`sau <平台> login` 扫码后 cookie 落盘，支持 headless 后台跑；但 headless 登录曾被平台识别、二维码扫码后被作废（#224），目前主线推「无头模式 + patchright」。Windows 提供 start-win.bat、docs/install.md，README 明确支持把仓库直接交给 Claude Code/OpenClaw 安装（docs/agent-bootstrap.md）
- AI 助手能否调用：能，CLI + 4 个官方 skill + agent bootstrap 提示词；无 MCP
- 开源协议：MIT
- 活跃度：15,268 star；最近 push 2026-09-02；未归档；作者 2026-03-24 公告进入密集重构期（README「近况说明」）
- 已知坑：
  - 小红书风控判定「疑似AI/自动化工具发布笔记」：https://github.com/dreammis/social-auto-upload/issues/289
  - headless 登录被识别为自动化、二维码作废：https://github.com/dreammis/social-auto-upload/issues/224
  - 抖音创作者中心改版后 login 失效：https://github.com/dreammis/social-auto-upload/issues/230 、https://github.com/dreammis/social-auto-upload/issues/283
  - B站 21566「投稿过于频繁」长时间冷却：https://github.com/dreammis/social-auto-upload/issues/210
  - Web 后端安全审计（无鉴权/路径穿越/CSRF）：https://github.com/dreammis/social-auto-upload/issues/214
- 对委托人的价值：**高** —— 三平台全覆盖且都有官方 skill，是「AI 助手驱动发布」这一需求下最现成的方案；代价是封控风险自担、页面改版时需要跟着更新。
- 出处：README（功能表/近况说明/CLI 示例）、issue 列表、`gh api repos/dreammis/social-auto-upload`

### Spreado（四平台视频上传的「傻瓜化」CLI，装完即用）
- 地址：https://github.com/BadKid90s/Spreado
- 形态：Python CLI（pip/uv 可装）+ 预编译可执行文件（Windows x64/ARM64 exe）+ AI Agent skill（skills/spreado-skill）+ Python API
- 覆盖平台：抖音、小红书、快手、视频号；**仅视频**（图文未支持，issue #9）；无 B站、无 X
- 实现方式：Playwright 浏览器自动化 + 本地 cookie；自动检测系统 Chrome/Edge，免装浏览器
- 定时/多账号/封面标签：`--schedule 2`（2 小时后）或 `--schedule "2026-12-31 18:00"` 定时；`--cookies` 指定路径实现多账号；标题/描述/标签/封面/地理位置齐全；`upload all --parallel` 多平台并行
- 登录与无界面：`spreado login <平台>` 打开浏览器扫码（抖音支持账密），cookie 存本地 cookies/ 目录，过期自动检测提示重登
- AI 助手能否调用：CLI + 官方 skill（面向 Claude/Codex/Cursor 等）；无 MCP
- 开源协议：LICENSE 文件实为 **Apache-2.0**（README 写 MIT，两处不一致）
- 活跃度：134 star；最近 push 2026-09-30；未归档；仓库里每天自动跑 e2e/selector 检查报告（reports/ 目录持续到 2026-09-30），维护习惯好
- 已知坑：
  - 「小红书自动发布会违规吗」：https://github.com/BadKid90s/Spreado/issues/12
  - exe 和 pip 安装后都无法登录：https://github.com/BadKid90s/Spreado/issues/6
  - 登录失败：https://github.com/BadKid90s/Spreado/issues/5
  - 图文发布请求（未支持）：https://github.com/BadKid90s/Spreado/issues/9
- 对委托人的价值：**高（仅视频场景）** —— Windows exe 免 Python 环境、命令最简洁、有定时；缺点是发不了 B站和图文，需要与 social-auto-upload 二选一或混用。
- 出处：README、issue 列表、LICENSE 文件内容、`gh api repos/BadKid90s/Spreado`

### Prism（多账号矩阵投放平台，自带 MCP/CLI/skill 全套 AI 接口）
- 地址：https://github.com/Laihiujin/Prism

- 定时/多账号：多账号并行 + 单账号互斥锁、定时发布、异步高并发任务队列，面向矩阵场景
- 登录与无界面：扫码后账号入库持续维护；PM2 常驻后台；Windows 有 deploy.cmd 零前置部署（自动装便携 Python/Node/Redis）
- AI 助手能否调用：能，接口最全的一档——CLI + REST API（/api/v1）+ stdio MCP + 9 份 skill
- 开源协议：Apache-2.0
- 活跃度：92 star；最近 push 2026-09-09；未归档
- 已知坑：README 自带合规声明「仅限测试、学术研究」，指纹+代理池路线明显踩平台风控红线；系统重（Redis/Celery/PM2），个人单账号维护成本高
- 对委托人的价值：**低-中** —— AI 接口形态最理想，但整个系统为多账号矩阵设计，单人三账号用它如同开卡车买莱；等委托人真做矩阵再回头看。
- 出处：README、NOTICE.txt、`gh api repos/Laihiujin/Prism`
