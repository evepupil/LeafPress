# 小红书发布自动化
> 调研日期：2026-10-01

## 结论

1. **小红书没有官方发布接口，也没有官方 MCP / AI 助手 skill**。开放平台（open.xiaohongshu.com）是电商向（商品/订单/物流），资质要求商家主体；新的登录开放平台（openaccount.xiaohongshu.com）首期只开放「用户基本信息」授权。对照知乎 zhihu-publisher 那种官方 skill，这条路在小红书**不存在**。
2. **最值得用：xpzouying/xiaohongshu-mcp**（16,072 star，2026-09-28 仍在提交，v2.5.5 发布于 2026-09-22）。功能最全（图文/视频发布、搜索、读评论、回评论、点赞收藏），有 Windows 现成二进制，README 直接给了 Claude Code 接入命令。但 Issue 里封号实例不少（#728、#715、#777 等），作者 v2.1.1 重做了浏览器指纹和拟人化，风险没有消除。
3. **skill 生态比 MCP 更适合委托人的用法**：white0dew/XiaohongshuSkills（3,472 star，2026-10-01 当天还在提交）走 CDP 驱动本机真实 Chrome，仅支持 Windows，功能覆盖最全还带数据看板导出，和委托人环境完全对口。
4. **别依赖：RedNote-MCP**（只读、2025-05 起停更）、**ReaJason/xhs**（2025-07 起停更、作者自述练手项目）、**aki66938/xhs-toolkit**（README 宣布停更约 1 年）。
5. **风险是政策性的，不是纯技术问题**：2026-03-10 小红书官方「薯管家」发布《关于打击AI托管运营账号的治理公告》，明确「直接通过AI托管工具注册、发布、互动的账号，或主页所有公开笔记均为AI托管代发的账号，平台将予以封禁处理」。任何第三方工具都在打击范围内——用测试小号先跑、控频率、发布前人工过内容，是所有项目 README 的共识建议。

## 官方能力

- **open.xiaohongshu.com（ARK 电商开放平台）**：面向商家和 ISV，接口集中在商品、库存、订单、售后、财务、物流（电子面单）、素材中心；应用类目表里没有任何内容发布类权限。资质审核要求商家主体，文档明示「必须使用店铺主帐号完成资质绑定，店铺类型不能是个人/个体店铺」。→ https://open.xiaohongshu.com/document/developer/file/32 、应用类目 https://xiaohongshu.apifox.cn/
- **openaccount.xiaohongshu.com（新的登录开放平台，OAuth 2.0 / PKCE / 设备授权）**：文档「首期能力：当前仅开放『用户基本信息』授权范围（basic_info）。更多能力将在后续版本陆续开放」，能做的只是拿到昵称头像做第三方登录。**没有发笔记、评论、搜索等任何内容接口**。→ https://openaccount.xiaohongshu.com/docs/quick-start 、https://openaccount.xiaohongshu.com/docs/oauth2-flow
- **ad-market.xiaohongshu.com/docs-center**：营销开放平台文档（聚光广告、蒲公英、私信三方、乘风），面向广告投放和商业化合作，不是创作者内容接口。→ https://ad-market.xiaohongshu.com/docs-center
- **官方 MCP / skill**：多轮检索「小红书 官方 MCP」「xiaohongshu official MCP server skill」，**未找到任何小红书官方出品的 MCP 或 AI 助手 skill**；市面全部为第三方。
- **官方态度**：2026-03-10 薯管家《关于打击AI托管运营账号的治理公告》：偶发 AI 代写代发→警告、限制分发；AI 托管工具注册/发布/互动或主页笔记全为 AI 代发→封禁。→ https://news.bjd.com.cn/2026/03/10/11623740.shtml 、https://www.21jingji.com/article/20260311/herald/5cca3e6e473c9998b318f2f3578e28ab.html

### xpzouying/xiaohongshu-mcp（社区事实标准：自托管 MCP 服务，浏览器自动化发笔记）

## 笔记硬性限制

- **标题**：≤20 字符，超出报错。官方出处：小红书小程序「xhs.postNote」文档「title … 最大长度 20 个字符，超出会触发 error」→ https://miniapp.xiaohongshu.com/doc/DC604617
- **正文**：普通图文笔记 ≤1000 字符（同一官方文档「content … 最大长度 1000 个字符，超出会触发 error」→ https://miniapp.xiaohongshu.com/doc/DC604617 ）；2025-07 起「长文」功能内测：标题仍 20 字内、正文可 6000 字以上 → https://finance.sina.com.cn/tech/roll/2025-07-04/doc-infeimam9386885.shtml
- **图片张数**：第三方口径单篇最多 **18 张**（https://allplatforms.io/rednote/ 、https://zsk.duoduodashi.com/xiaohongshu/121342.html ）；运营侧官方建议一次 6–9 张（第三方转述 https://www.ostmcn.com/article-1185.html ）。**未在小红书官方文档直接核实到 18 的出处**。
- **推荐尺寸/比例**：竖版 **3:4，1080×1440 px** 为最佳展示（信息流双列瀑布流）；同一笔记内所有图片必须统一比例 → https://allplatforms.io/rednote/ ；Auto-Redbook 等渲染工具也按 1080×1440 输出（佐证）。
- **补充**：信息流标题两行约 18–20 字后截断（第三方经验 https://www.ostmcn.com/article-1185.html ）；图文必须有至少 1 张图、图文视频不可混发（XiaohongshuSkills SKILL.md 约束）。

## 拿不准的点

- **登录态能维持多久**：没有任何项目给出可靠数字。XiaohongshuSkills 登录检查缓存 12 小时（自设策略，非平台承诺）；RedNote-MCP 靠 Cookie 文件长期复用；xiaohongshu-mcp 的指纹浏览器方案声称「测试账号持续若干天正常」（Issue #728 作者回复）。实际有效期取决于风控触发，未核实。
- **图片 18 张上限**的官方出处没找到，只有第三方口径；若要引用建议实际发一篇验证。
- **openaccount 开放平台是否接受个人主体应用**：快速接入文档只说提交「应用主体」等待审核（1–3 个工作日），没写个人能否申请，未核实。
- **white0dew/XiaohongshuSkills 的 Issue 区**没搜到封号/风控反馈（搜索关键词可能不全），不代表没风险，其 README 自带风险提示。
- autoclaw-cc/xiaohongshu-skills 2026-05-23 后无提交，是暂停维护还是完成态，仓库无说明。
