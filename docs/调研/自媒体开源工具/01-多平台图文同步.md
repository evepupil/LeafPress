# 多平台图文同步工具
> 调研日期：2026-10-01
> 委托人场景：Windows，独立开发者，技术文章，主阵地知乎，扩展小红书 / B站 / 抖音，X 可选；工具需能被 Claude Code 等 AI 助手调用。

## 结论
1. **首选 Wechatsync（v2 分支）**：2026 年初重写后是唯一一个同时覆盖「知乎文章 + 小红书长文 + 抖音图文 + B站专栏 + X」的开源工具，且 CLI、MCP、Claude Code skill 三条 AI 调用路径全都有（v2 README：https://github.com/wechatsync/Wechatsync/blob/v2/README.md）。代价是 v2 很新（2026-02 起密集发版），小红书长文还有挂着的 bug（Issue #209），发小红书前要人工核对草稿。
2. **手动操作为主就选 MultiPost**：同类里最活跃（2026-09 底仍在周更）、50+ 平台、Chrome/Edge 扩展 + Windows 桌面版都有。但它走「开源扩展 + 闭源 Agent/桌面客户端」混合路线，纯开源部分没有 MCP；AI 集成要么经官方云端 RESTful API（api.multipost.app），要么用闭源桌面客户端的本地 MCP 接口（https://api-docs.multipost.app/）。
3. **ArtiPub 别按老印象用**：原版（MongoDB + Chrome 扩展注入）早已停更，仓库已整体重写为「ArtiPub AI」，支持平台缩到知乎、掘金、CSDN、简书、SegmentFault、开源中国 6 个技术社区，没有小红书/B站/抖音/X，且重写后成熟度无第三方佐证（https://github.com/crawlab-team/artipub）。
4. **COSE 覆盖好但 AI 调不了**：doocs/cose 平台表相当全（含 B站专栏、小红书长文、抖音文章、X Articles），完全本地运行，但只能在 doocs/md 编辑器里点「发布」按钮，没有 CLI / 开放接口 / MCP，无法接进 Claude Code 工作流（https://github.com/doocs/cose）。
5. **MCP 原生的后来者（multi-platform-publisher、torns 的 Playwright MCP、unified-publish-mcp）都是 star < 10 的新仓库**，设计思路对 Agent 友好但未经规模验证，可以关注、不宜依赖。

## 闭源对照
- **蚁小二**：国内最出名的多平台分发 SaaS，按账号数订阅收费，开源社区普遍拿来当对比基准（出处：MultiPost 对比页 https://www.aosen.cc/mianfei16627.html 、Wechatsync v2 FAQ）。

- **微小宝 / 新媒体管家**：公众号运营套件附带多平台分发，闭源免费+增值，数据同样过云端（Wechatsync v2 FAQ 对比对象）。

## 拿不准的点
- **MultiPost 的 RESTful API 数据链路**：api.multipost.app 需 Bearer Token，但文档没写内容/凭据是否经官方服务器中转；其桌面客户端的本地 MCP 接口确实存在，但客户端本体闭源，Windows 版只有 Release 二进制（https://github.com/leaperone/MultiPost-Desktop-Release ）——对「不想过第三方服务器」的委托人要实测确认。
- **许可证两处打架**：doocs/cose 的 LICENSE 文件是 Apache-2.0 而 README 徽章写 MIT；xwh5/multi-publisher 的 GitHub API 返回 MIT 而 README 末尾写 Apache-2.0。均以仓库 LICENSE 文件为准，但作者未解释。
- **格式转换（代码块/表格/公式）没有系统性结论**：只有零星 Issue——COSE #254 头条 LaTeX 公式丢失、Wechatsync 2026-05-14 修复 CSDN JSON 代码块错乱、旧版「代码块到知乎不换行」。小红书/B站/抖音均为非 Markdown 富文本编辑器，公式和表格大概率要降级，没有项目给出逐平台格式保真矩阵，需实际试发验证。
- **PostBot 的逐平台能力矩阵**：README/官网只给了平台名单，知乎到底是「文章」还是仅「动态」、小红书是图文还是长文，公开资料里没写清。
- **MultiPost 的「知乎动态」是否等于知乎想法**：官方博客把「知乎动态」归入动态类，未逐项核实是否即「想法」功能。
- **Wechatsync 的 X 适配器形态**：v2 平台表列了 X (Twitter)，但没说明发的是长文、thread 还是纯文本，X 在国内网络环境下可用性也未验证。
- **ArtiPub 重写版的真实可用性**：README 叙事宏大（AI 工作流发现/自修复），但找不到重写后的第三方评测或成功案例，star 数主要是原版历史积累。
