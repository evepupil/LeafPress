# 选题、热点与数据分析
> 调研日期：2026-10-01

本文件所有 Star 数、最近提交时间、许可证均于 2026-10-01 通过 `gh api repos/<owner>/<repo>` 实际读取。凡未能读到的一律标注「未核实」。所有链接为实际访问过的页面。

## 结论

1. **追热点用 TrendRadar，不用别犹豫。** 它是本清单里唯一「热榜聚合 + 关键词过滤 + 自带 MCP Server」三件齐全、且明确为 Claude Code / Cursor 这类 AI 助手准备接入口的项目（README 有 Cursor / VSCode-Cline 的 stdio 与 HTTP 两种配置样例，MCP 工具 25 个）。GPL-3.0，自托管，Windows 有 `setup-windows.bat`。出处：https://github.com/sansan0/TrendRadar
2. **找选题最值得用的是 RSSHub（自建）把知乎/B站 + GitHub Trending + Hacker News + Product Hunt 串成一条 RSS 流，交给 AI 助手读。** 但必须自建：公共实例 `rsshub.app` 实测已被 Cloudflare 拦截（5 个路由全部返回 403 "Just a moment..."），知乎/小红书/抖音这些路由本身也都带 🚨 Strict Anti-crawling 标记，官方 FAQ 明说公共实例「can get unreliable from time to time」。出处：https://docs.rsshub.app/guide/faqs
3. **MediaCrawler 能拿到的数据最全（帖子 + 评论 + 创作者主页，7 个平台），但它是本清单里唯一「许可证直接禁止你用它」的项目。** 许可证是作者自写的 NON-COMMERCIAL LEARNING LICENSE 1.1，白纸黑字：仅限非商业学习用途、不得大规模爬取、不得用于任何商业目的。委托人做自媒体是经营性行为，用它取数存在许可证层面的直接冲突。另外它至今没有官方 MCP Server（仓库内 grep 无 MCP 实现），只有本地 FastAPI（`uv run uvicorn api.main:app --port 8080`），AI 助手要调只能自己包一层。价值高，但**建议别碰**。
4. **NewsNow 是「看得爽」，不是「喂给 AI」。** 界面漂亮、默认缓存 30 分钟、覆盖 50+ 源（含 GitHub Trending / Hacker News / Product Hunt / 知乎 / 抖音 / B站 / 快手），也有官方 MCP（npm `newsnow-mcp-server`，最新 0.0.12，MIT）。但它聚合的是**各平台热榜**，不是搜索结果，做选题的证据颗粒度不如 TrendRadar。
5. **「把多个平台的粉丝/阅读/互动拉到一张表」——没有可用的开源工具，写「没有」。** 搜到的几个候选（insprira 172⭐、Visual_MediaCrawler 71⭐、creatorhub 0⭐、polypost 1⭐）要么 Star 极少、要么已数月未更新、要么根本搜不到仓库，均不足以承担日常数据汇总。这一块目前只能靠闭源商业平台（见下文闭源对照）。
6. **DailyHotApi 建议观望。** 最近一次提交是 2026-03-11（已近 7 个月无代码更新），Issue 区大量「接口失效/403/返回空 JSON」的未关闭报告，官方示例站点 `api-hot.imsyy.top` 实测返回 `error code: 1016`。它的 MCP 支持还停留在一个未合并的 PR（#137「Mcp all in」，2026-03-30 起 open）。

**对委托人的含义**：如果「自己账号数据汇总」是硬需求，最便宜的闭源入口是蝉妈妈个人版（¥398/季）；但蝉妈妈是抖音垂类，要同时覆盖小红书还得再买千瓜（最低 ¥1,599/月）。**两项加起来明显超出独立开发者个人预算**——这也是为什么第 5 条结论是「开源目前无解，但闭源也不便宜」。

## 拿不准的点

1. **DailyHotApi 的 56 个路由里现在到底还有几个能用，没逐个验证。** 我只实测了示例站点 `api-hot.imsyy.top` 的 4 个路由（全挂），以及读了 Issue 区。自己 Docker 部署后能否跑通未验证——按任务书要求没有实际部署运行。
2. **RSSHub 自建实例上知乎/小红书/抖音路由的实际成功率，未验证。** 我只读了文档标签（Strict Anti-crawling / Puppeteer）和 Issue。文档说「只能自建」，但 Issue #20402、#20303、#18758 系列显示即便自建 + 配 Cookie + 换 IP 也照样 403。**要不要为这三条路由投入时间，建议先用一个最小自建实例试一天再决定。**
3. **MediaCrawler 许可证的边界到底在哪，属于法律判断，我不下结论。** 许可证原文只说「非商业学习用途」和「未经版权所有者书面同意不得用于任何商业用途」，没有定义「商业用途」是否包含「个人做自媒体账号」。但 README 自己的免责声明要求「用户应自行承担一切因使用本项目而可能引起的法律责任」，且 Pro 版明确在卖订阅。**建议按「不能用」处理。**
4. **MediaCrawlerPro 的实际状态无法核实。** README 链接指向 `https://github.com/MediaCrawlerPro`，但 `gh api repos/MediaCrawlerPro/MediaCrawlerPro` 返回 404（私有或组织页）。它的「AI Agent Skill 支持（OpenClaw / Claude Code / Cursor 一键安装，让 Agent 自动爬取数据）」是本清单里唯一直接满足委托人「AI 助手驱动」需求的爬虫能力，另有「自媒体内容拆解Agent」「基于评论分析AI Agent正在开发中」两项未完成功能，但仓库不可见，价格、协议、可用性全部未核实。
5. **「多平台账号数据汇总」这一项，我只搜了 GitHub 与中文搜索引擎，可能漏掉英文圈项目。** 搜出来的候选全部 Star 极低或无协议（见上文表格），因此判定「没有」。若委托人愿意接受「付费 + 半自动」，闭源方案是现成的（见闭源对照，但注意价格）。
6. **TrendRadar 的「AI 自建热榜数据源」是 2026-09 新增功能，其自建 newsnow 的配置方式我只读到 README 导航链接，未展开读官网文档。** 出处 https://trendradar.sandev.cc/zh/docs/self-hosted-sources/（未访问）。
7. **OpenGithubs/github-daily-rank 没有 LICENSE 文件。** 「无协议」不等于「可自由使用」，严格说默认保留所有权利。委托人若要引用其榜单数据到公开内容里，这一点需自行判断。
8. **`DaBaoAgent/social-media-monitor` 无法核实。** 搜索引擎返回了它的完整 README 摘要（含「三平台六账号全自动新媒体数据监控」「粉丝/获赞/笔记数」等功能描述），但 `gh api repos/DaBaoAgent/social-media-monitor` 返回 404，仓库可能已删除或改名。因此**不作为候选**列出。
9. **各平台的「封号风险」只记录了 Issue 里用户自述的案例，没有平台官方规则原文。** 小红书、抖音的社区规范/用户协议里对自动化采集的具体条款，本次未去逐条查证。
10. **新榜的具体价格、以及飞瓜数据的价格与平台清单，本次未找到公开页面，标注未核实。** 新榜声量通在阿里云市场有商品页（上架日期 2026-02-02，开票主体上海新榜信息技术股份有限公司），但页面未展示标价。
