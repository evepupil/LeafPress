## 结论

1. **小红书图文卡片：不要用 baoyu-xhs-images。** 它是「AI 生图模型出卡片」的 skill，SKILL.md 里明确写着 `⛔ Never substitute SVG, HTML, canvas, or other code-based rendering for raster image generation`，即它拒绝用代码排版渲染，卡片上的中文由生图模型画，错字/糊字风险高。委托人已经有生图 skill，这个属于重复且方向不对。**要代码排版 + 精确中文，推荐 `comeonzhj/Auto-Redbook-Skills`**（Python/Node 脚本 + HTML 模板 + Playwright 截图，8 套主题、4 种分页、默认 1080×1440、dpr 2，CSS 里中文字体优先用 `Noto Sans SC` / `Source Han Sans CN`）。⚠️ 它的代码公开可读但**仓库没有 LICENSE 文件**，商用前要问作者；另外它的自动发布部分有平台风控风险，只用渲染脚本。

2. **代码截图：优先 `charmbracelet/freeze`，备选 `carbon-now-cli`。** freeze 是单文件 Go 二进制，官方 release 里有 `freeze_0.2.2_Windows_x86_64.zip`，`--font.file` 可以内嵌 TTF 解决中文，输出 PNG/SVG/WebP。注意 freeze 在 Windows 上中文有两个未关闭的坑（见下）。Carbon 本身是 Next.js 网页应用、**没有官方 CLI**，但 `mixn/carbon-now-cli` 是活跃的第三方终端封装。

3. **技术图解：`mermaid-js/mermaid-cli` 是最稳的一条路**，`mmdc -i x.mmd -o x.png` 一行命令出图，MIT，2026-09-28 还在提交。中文要自己塞字体/CSS，官方有一个已关闭的中文不显示 issue 可参考。Excalidraw 官方出了 `excalidraw/excalidraw-mcp`（MCP 服务），但它是**交互式画布 + MCP App**，不是批量导出 PNG 的命令行工具；批量导出需要走 Excalidraw 的 `exportToSvg` 包或 Kroki 的 Excalidraw 后端。

4. **底层通用方案：`vercel/satori`（HTML/CSS → SVG）+ `sharp` 或 `resvg-js` 转 PNG**，这是 baoyu-diagram 自己就在用的组合（`skills/baoyu-diagram/scripts/main.ts` 里 `import("sharp")`）。satori 的硬性限制：**必须手动传字体文件，只支持 TTF/OTF/WOFF，不支持 WOFF2**；CJK 断行曾经有 bug（#389、#414 已 closed，但 #743 仍是 open 的 ICU4X 跟踪 issue）。中文长文排版建议直接用浏览器截图（Playwright/Puppeteer）而不是 satori。

5. **信息图/文章配图这一格，baoyu 里真正能用的是 `baoyu-diagram`**——它是唯一一个「Claude 直接手写 SVG、不调用生图模型」的图片类 skill，还自带 `scripts/main.ts` 做 SVG→@2x PNG，且明确写了中文时用 `'Noto Sans SC', 'PingFang SC'` 并加宽盒子。`baoyu-cover-image` / `baoyu-article-illustrator` / `baoyu-infographic` / `baoyu-comic` / `baoyu-slide-deck` 全都是生图模型路线。

6. **只选 1～2 个，答案如下：**
   - **首选：`comeonzhj/Auto-Redbook-Skills`（只取 `scripts/render_xhs.py`）** —— 它是本次唯一一个把「命令行批量 + HTML/CSS 精确排版 + 中文字体明确 + 1080×1440 默认 + 8 主题 4 分页模式」全部做齐的活跃方案。小红书卡片、抖音图文、知乎配图、文章插图都能靠它的 HTML/CSS 模板改尺寸复用（改 `--width/--height` 即可），一个工具覆盖委托人列的大半场景。风险：无 LICENSE、别用它的发布功能。
   - **次选：`charmbracelet/freeze`** —— 技术文章里的代码块/终端输出截图，它是 Windows 上最省事的：官方 release 有 `.zip` 单文件二进制，`--font.file` 内嵌中文字体，直接输出 PNG/SVG/WebP，无需浏览器、无需联网。风险：Windows 中文有两个未关闭的 issue（#93、#80）。
   - **图解补齐：`mermaid-js/mermaid-cli`** —— 技术文章的流程图/时序图用 `mmdc` 一行出 PNG/SVG，MIT、官方维护、2026-09 仍在提交。
   - **不推荐用 `baoyu-xhs-images`** 做带中文正文的卡片（生图路线文字不可控）。

## 拿不准的点

1. **baoyu-skills 的 26,246 Star 存疑**。这是 `gh api repos/JimLiu/baoyu-skills` 实际返回的数字（Fork 2,896，创建于 2026-01-13，8 个月 2.6 万星），数字本身读到了，但相对仓库年龄显得异常高，我没有进一步核实 star 增长曲线。同理，`carbon` 的 36,112、`excalidraw` 的 133,343 也都是直接读到的 API 值，未交叉验证。
2. **`baoyu-xhs-images` 到底能不能出「文字精确」的卡片，我没有实测**。我的判断完全基于 SKILL.md 里那两条 `⛔` 禁令（原文已读到：`⛔ Never substitute SVG, HTML, canvas, or other code-based rendering for raster image generation` 和 `⛔ Never repair rendered text by painting over a generated bitmap`）——从文本推断它走的是生图模型。委托人如果有该 skill，实际跑一张带中文代码的卡片就能验证。

3. **md2card 的「开源」程度有矛盾**。`gh api repos/ittat/md2card` 显示它是完整的 React 源码仓库（有 src/、package.json），但 `maqi1520/md2card-mcp-server` 配套的 md2card.cn 是闭源 SaaS，作者在 V2EX 说「代码仓库不开源」。这两个可能不是同一个项目（ittat 的仓库 2025-05 就停更了，md2card.cn 是后来的商业化版本）。我按「两个不同项目」处理，但没有 100% 确认。

4. **`excalidraw/excalidraw-mcp` 的协议有两处矛盾**：`gh api` 的 license 字段是 `null`（仓库根目录没有 LICENSE 文件），但 `package.json` 里写 `"license": "MIT"`。以 MIT 为准，但严格说是「未在仓库根目录声明」。

5. **Silicon 在 Windows 上的实际可用性没有验证**。README 说「If you are using Windows, I suggest you disable it [harfbuzz] to get it build easier」，但没说关掉 harfbuzz 之后中文还能不能渲染（#241 的报错正是找不到中文字体）。freeze 的 Windows 中文坑（#93、#80）也都没验证是否已在 v0.2.2 里修好——release 是 2025-04-01，而 issue 还开着。
