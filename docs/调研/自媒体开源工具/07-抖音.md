# 抖音发布工具
> 调研日期：2026-10-01

> **核实更正（2026-10-01，另派一路换模型核对官方页面，以本段为准）**
> - 企业主体、注册资本 ≥ 50 万且注册满 1 年、应用类型限创作工具 / 社区 / 硬件配套 / 游戏，与官方《抖音发布能力使用规范》逐字一致。
> - 权限表里的「普通权限」是「权限申请」一栏的取值，对应的申请方式是「管理中心申请」，官方并没有写「个人可申请」。正文里关于两处口径不一致的疑问可以关闭。
> - 个人主体只能创建小程序、小游戏、小玩法（官方《开发者入驻常见问题》），建不了投稿能力需要的移动应用或网站应用，所以个人用不了官方发布接口。

## 结论
1. **官方接口对个人开发者基本关闭**：API 直接投稿（`video.create` 等 scope）和「发布内容至抖音」（SDK/H5 投稿）都要求应用为企业主体（注册资本≥50万且注册满1年）、应用类型限创作工具/社区/硬件/游戏，个人独立开发者做自用发布工具走不通，别在这条路上花时间（见官方能力一节链接）。
2. **发视频首推 lancelin111/douyin-mcp-server**：TypeScript + Playwright 的 Skill/MCP 双形态，专为 Claude Code 等助手设计，扫码登录 + Cookie 复用，首次上传过一次短信验证后可全自动，MIT 协议、2026-06 仍在更新，对「不露脸录屏 + AI 助手驱动」的场景最贴合。
3. **发图文（多图）首选 chengyi-ai/douyin-image-post-scheduler**：目前唯一把「抖音图文批量 + 定时 + 话题校验」做成 AI 助手 Skill 的活跃项目（2026-08 更新，MIT）；同类的社交 MCP（torns）只做到「存草稿不点发布」。
4. **老牌上传脚本（withwz/douyin_upload、Superheroff、lishang520）都已停更 1～2 年**，抖音创作者中心前端早就改版，能直接用的概率低，不建议碰；kebenxiaoming/matrix（961 star）2025-12 还有提交，但依赖 Redis+MySQL 队列、面向矩阵号场景，单人账号用起来太重。
5. **所有非官方工具都是 Playwright 操作创作者中心网页**，本质是模拟真人点击，绕不开滑块/短信验证，且可能违反平台条款触发风控；README 和 Issue 里普遍要求低频发布、保留人工确认，AI 助手全自动无人值守批量发抖音在这批工具里没有安全先例。

## 官方能力
- **开发者的入驻门槛**：抖音开放平台允许「个人主体」注册入驻（需身份证实名），个人注册后获得「普通开发者」的基础能力权限（https://developer.open-douyin.com/docs/resource/zh-CN/developer/join/join-into-developer-platform 、https://developer.open-douyin.com/docs/resource/zh-CN/developer/introduction/type-and-permission ）。
- **API 直接发布视频**：`POST /api/douyin/v1/video/create_video/`，scope `video.create.bind`，支持话题、定时（存草稿后定时）、私人/公开；但页面明确标注「需要申请权限」，申请入口在「能力管理 > 能力实验室 > 代替用户发布内容到抖音需要用户授权」，且要求应用通过审核。视频创建后有平台审核期，期间仅自己可见（https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-create ）。文件上传走分片接口，建议 mp4、竖版 720p 起、带品牌水印会降权（https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-part-upload ）。
- **「发布内容至抖音」（SDK 投稿 / H5 投稿）**：从 App 或网页拉起抖音发布器，支持图文和视频两种体裁，但官方使用规范明确「仅对符合平台要求的移动/网站应用开放」：**应用主体不再向个体工商户开放，企业主体需注册资本≥50万且注册≥1年**；应用类型限创作工具、社区、硬件配套、游戏；纯营销类场景不开放。个人开发者自建的「网站应用」几乎不可能满足「正式应用 + 创作工具」的组合要求（https://partner.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue ）。
- **权限清单**：`video.create`（一键发布视频 / 一键发布单图）在权限表里属于「普通权限、默认关闭、需在管理中心申请」，个人开发者理论上能提交申请，但官方社区反馈和文档措辞（投稿能力「有一定使用门槛」）都指向审核不向个人自用工具放开（https://open.douyin.com/platform/resource/docs/accession-guide/type-and-permission 、https://developer.open-douyin.com/docs/resource/zh-CN/dop/ability/opensdk/content-management/share-and-publish-to-douyin ）。
- **小结**：官方没有「个人开发者拿 access_token 就能把视频/图文发到自己抖音号」的通道；能用的只有「分享到抖音」这类需要用户手动确认的 SDK/H5 分享，且门槛同样在企业资质。

## 拿不准的点
- **官方 API 能否给个人开发者开通 `video.create`**：权限表写的是「普通权限、管理中心申请」，字面上个人可申请，但发布能力的准入规范（企业注册资本≥50万）又把个人挡在外面；两份文档口径不完全一致，只能实测才知道，未找到官方明说「个人被拒」的页面。
- **liaogx/douyin-mcp 的许可证**：GitHub API 返回 NOASSERTION，README 提及 AGPL 字样但未逐条核对许可证原文。
- **抖音 2026 年创作者中心的最新风控强度**：各项目 Issue 里几乎没有 2026 年的封号反馈（用户量小），不能据此推断「自动发布不会被风控」；高频发布的风险没有任何一个项目给出数据。
- **zrt-ai-lab auto-douyin、torns MCP 的实际可用性**：README 描述与真实效果之间没有第三方验证，star/反馈太少，无法判断抖音前端改版后是否仍然能跑。
- **社交 MCP 对「封面自定义」的支持**：liaogx/torns 两个 MCP 的文档都没提封面字段，是「不支持」还是「文档没写」未核实。
