# 字幕与 AI 配音

> 调研日期：2026-10-01

调研方式：只读公开仓库页面、README、LICENSE、Issue 与公开评测文章；Star 数 / 最近提交日期 / 协议均通过 `gh api repos/<owner>/<repo>` 与 HuggingFace model API 实读，未安装、未下载、未运行任何被调研工具。

## 结论

1. **字幕（有显卡）**：首选 **VideoCaptioner + faster-whisper 本地引擎**。VideoCaptioner 自带 CLI 和官方 Claude Code Skill，`transcribe / subtitle / dub / synthesize / process` 一条命令跑完全流程，中文场景还能免费走必剪/剪映在线 ASR（仅中英文）；本地 `faster-whisper` 用 large-v3 在 8GB 显存上跑 batch_size=8 + int8 实测 13 分钟音频约 16 秒（官方 benchmark，RTX 3070 Ti 8GB）。中英混杂的技术名词建议再挂一个 LLM 优化步骤（VideoCaptioner 的 `subtitle` 命令就是干这个的，需要 OpenAI 兼容 API Key）。
2. **字幕（只有 CPU）**：首选 **FunASR / SenseVoiceSmall**。官方 README 明确写了 SenseVoiceSmall 是 CPU-first 路线，且提供 Windows 原生 `llama-funasr-sensevoice.exe`（GGUF，无需 Python、无需 GPU），官方声称中文 CER 约为 whisper.cpp 的 1/3；实测对照中 27 分钟中文音频 SenseVoice 用时 10.10 秒（约 161 倍实时），Whisper Large V3 Turbo 需要 2 分 4 秒。如果只想要「最省事」，直接上 VideoCaptioner 的免费必剪在线 ASR 也行，但要接受音频会上传云端。
3. **配音（有显卡）**：分两条路。想要**最像自己、情感最自然**→ **IndexTTS-2.5**（B 站开源，0.8B，官方 RTF 0.2065，官方盲测榜中文 WER 3.62 / 说话人相似度 63.83，多语言混读支持拼音和 CMU 音素纠音）；想要**商用最省心**→ **VoxCPM2**（面壁智能，2B，代码和权重都是 Apache-2.0 明确允许商用，官方标注 VRAM 约 8GB，RTX 4090 RTF ~0.30）。两者都不便宜，8GB 是下限。
4. **配音（只有 CPU）**：**不要指望本地克隆模型**。唯一现实选项是 **edge-tts**（免费调微软在线语音，纯 CPU 无压力，`edge-tts --text "..." --write-media out.mp3` 一行命令，还能顺带输出 srt），或继续用 VideoCaptioner 的 `dub` 命令（默认走 Edge TTS）。代价是：不能克隆自己的声音，且用的是微软的在线服务，商用条款要看微软 Azure 语音的授权（见「拿不准的点」）。GPT-SoVITS 官方文档说「没显卡会自动识别使用 CPU 推理」，其 v2ProPlus 在 M4 CPU 上 RTF 0.526，但那是官方数据、Windows CPU 上的实际体验未核实。
5. **协议红线（对独立开发者最重要）**：**IndexTTS 权重是 B 站自定义协议**——月活超 1 亿或年营收超 10 亿人民币才需要单独授权，普通独立开发者可以商用，但**不得用它的输出/衍生模型去改进其他 AI 模型**（非商用模型除外）；**fish-speech 代码+权重是 Fish Audio Research License，任何商用都要单独书面授权**，做教程视频变现的别碰；**F5-TTS 代码 MIT 但权重 CC-BY-NC-4.0，不可商用**；**CosyVoice3 权重是 Apache-2.0**（HF 页面实读），是这批里商用最干净的中文强模型之一。

### faster-whisper（Whisper 的 CTranslate2 高速重实现，本清单里的字幕底座）
- 地址：https://github.com/SYSTRAN/faster-whisper
- 类别：字幕（语音转文字，输出带时间戳的 segment）
- 中文效果：README 无中文专项评测。**中文有两个被反复提的已知问题**：① 输出常为繁体，需靠 `initial_prompt` 引导简体（Issue #521 https://github.com/guillaumekln/faster-whisper/issues/521 ）；② 中文识别结果可能没有标点（同一 Issue 评论区反馈）。另有「无法转录中文」（#808 https://github.com/SYSTRAN/faster-whisper/issues/808 ）、「识别结果被翻译成别的语言」（#869 https://github.com/SYSTRAN/faster-whisper/issues/869 ）、「中文上下文重复」（#595 https://github.com/SYSTRAN/faster-whisper/issues/595 ）等 Issue。中英混读技术名词没有官方评测，实践中靠 Whisper 本身的多语言能力 + 后置 LLM 纠错（如 VideoCaptioner 的 subtitle 步骤）。
- 硬件要求：官方 benchmark 实测（Large-v2，13 分钟音频）——**GPU（RTX 3070 Ti 8GB，CUDA 12.4）**：fp16 beam5 单条 1m03s / 4525MB，fp16 + batch_size=8 仅 17s / 6090MB，int8 + batch_size=8 仅 16s / 4500MB；**纯 CPU（i7-12700K 8 线程）**：small 模型 fp32 beam5 2m37s / 2257MB，int8 1m42s / 1477MB，int8 + batch_size=8 51s / 3608MB。GPU 需要 CUDA 12 + cuDNN 9（cuBLAS、cuDNN 要另装；旧版 ctranslate2 有降级方案）。
- Windows 支持：好。README 明确「与 openai-whisper 不同，**不需要系统安装 FFmpeg**」，音频解码走 PyAV（自带 FFmpeg 库）。Windows 的 NVIDIA 库可由 Purfview 的 whisper-standalone-win 提供单个压缩包（README 内链接）。另有 Windows 现成命令行封装 whisper-standalone-win 和 whisper-ctranslate2（README 推荐区列出）。
- AI 助手能否调用：**能，Python API 为主**（`pip install faster-whisper`；`WhisperModel(model_size, device="cuda", compute_type="float16")` → `model.transcribe("audio.mp3", beam_size=5)`，注意返回的是 generator，必须迭代才真正开始跑）。也有批处理 `BatchedInferencePipeline`。官方**没有自带 CLI**，CLI 要靠第三方（whisper-ctranslate2 / whisper-standalone-win / VideoCaptioner 的 `--asr faster-whisper`）。另有 OpenAI 兼容服务端 `speaches`（README 推荐区）。
- 开源协议：代码 **MIT**（`gh api` 实读）。权重是 OpenAI Whisper 的权重（HF `openai/whisper-large-v3` 实读 license = **Apache-2.0**），可商用。
- 活跃度：Star **25,658**；最近一次 push **2026-09-30**；未归档；最新 Release v1.2.1（2025-10-31）。Open issues 260。
- 已知坑：中文繁体/无标点（#521）；语言误判（#869）；中文重复幻觉（#595）。均见上。
- 对委托人的价值：**高**。它是本地字幕的地基，VideoCaptioner / WhisperX 都用它；协议干净、Windows 无需 FFmpeg。
- 出处：https://github.com/SYSTRAN/faster-whisper ｜ https://github.com/guillaumekln/faster-whisper/issues/521 ｜ https://github.com/SYSTRAN/faster-whisper/issues/808 ｜ https://huggingface.co/api/models/openai/whisper-large-v3

### FunASR / SenseVoice（阿里达摩院工业级 ASR 工具包，中文 CPU 路线最强）
- 地址：https://github.com/modelscope/FunASR ；主页 https://www.funasr.com/
- 类别：字幕（语音转文字，含 VAD、标点、说话人分离、情感/事件标签）
- 中文效果：官方 README 用三个数字说话——① 打包的 llama.cpp 版「**中文 CER 比 whisper.cpp 低约 3 倍**」；② SenseVoiceSmall 支持中/英/日/韩/粤五语；③ 官方 benchmark 对照表显示 SenseVoiceSmall 在 **27 分钟中文音频上 10.10 秒（118×）**，Whisper Large V3 Turbo 2 分 4 秒（13.1×），下载体积 827MB vs 约 1.6GB、内存占用约 700MB vs 约 1.6GB（引自 whispernotes 的第三方横评，非官方）。阿里云官方文章称 SenseVoice 中文 WER 5.4%，优于 Whisper-Base 的 8%+。**中英混杂**：官方 README 提到 SenseVoiceSmall 是五语种 checkpoint，第三方实测文章专门测了「中英混杂对话」场景（AI 硬件创业社区横评）。技术名词（Cloudflare/Docker）的专项评测未找到。
- 硬件要求：**CPU-first**。README 的 SenseVoiceSmall 示例直接用 `device="cpu"`；CPU 安装只需 `pip install torch torchaudio && pip install funasr`。GPU 需按 pytorch.org 装匹配 CUDA 的 wheel，然后 `device="cuda"`。Fun-ASR-Nano 可用 vLLM 加速（`AutoModelVLLM`）。
- Windows 支持：**很好，且是原生二进制级别**。README 明确给出 Windows PowerShell 流程：下载 `sensevoice-small-q8.gguf` + `fsmn-vad.gguf`，运行 `.\llama-funasr-sensevoice.exe -m ... --vad ... -a audio.wav`，支持 `--backend vulkan`（AMD/Intel/NVIDIA 通用）和 `--backend cuda`；官方提供 `windows-x64-cuda`（sm_86）与 `windows-x64-cuda-blackwell`（sm_120，RTX 50 系）两个包，**自带 cuBLAS DLL、静态 MSVC 运行时，不需要单独装 CUDA Toolkit**。注意 Windows 二进制需匹配 CUDA 架构。
- AI 助手能否调用：**能，三种方式**。① CLI：`funasr audio.wav --model paraformer --language zh`，批量 `funasr *.wav --output-format srt --output-dir ./output`；② Python：`AutoModel(model="iic/SenseVoiceSmall", vad_model="fsmn-vad", spk_model="cam++", device="cpu")` + `model.generate(...)`；③ **OpenAI 兼容 HTTP 服务**：`funasr-server --host 127.0.0.1 --port 8000 --model sensevoice --device cpu`，然后 `POST /v1/audio/transcriptions`（-F file / model / response_format）——README 还提示用 OpenAI 兼容接口时先看 `examples/openai_api/SECURITY.md` 再对外暴露。此外仓库描述提到 MCP serving 支持。
- 开源协议：**代码 MIT**（`gh api` 实读 `license.spdx_id = MIT`）。**模型权重是单独的 `MODEL_LICENSE`（FunASR Model Open Source License Agreement v1.1，阿里集团）**，实读原文：允许自由使用、复制、修改、分享，**但要求署名来源和作者信息并保留模型名称**；协议里没有禁止商用的条款，也没有写允许商用的明文。**SenseVoiceSmall 在 HF 上的 license 标为 `other`（license_name: model-license，指向 FunASR 的 MODEL_LICENSE）**。→ 结论：可商用但必须署名，且条款不是标准 OSI 协议，建议商用前自己读一遍 MODEL_LICENSE。
- 活跃度：Star **20,565**；最近一次 push **2026-10-01**（当天）；未归档；最新 Release v1.4.16（2026-09-18），另持续发 funasr-onnx 小版本（2026-09-09）。Open issues 仅 35（维护很勤）。仓库描述已扩展为「training, inference, streaming ASR, VAD, punctuation, speaker diarization pipelines, and OpenAI-compatible/MCP serving」。
- 已知坑：Windows 二进制包必须选对 CUDA 架构（sm_86 vs sm_120），选错会跑不起来（README 原文）；CPU 服务和 MOSS 说话人分离服务不能共用 8000 端口（README 提示）。
- 对委托人的价值：**高**（尤其只有 CPU 时）。中文准确率与速度双优，且有 Windows 原生二进制 + OpenAI 兼容接口，最适合被 AI 助手当工具调。
- 出处：https://github.com/modelscope/FunASR ｜ https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE ｜ https://huggingface.co/FunAudioLLM/SenseVoiceSmall ｜ https://developer.aliyun.com/article/1575266 ｜ https://whispernotes.app/zh/blog/sensevoice-fastest-cjk-transcription

### WhisperX（带词级时间戳和说话人分离的 Whisper 加速封装）
- 地址：https://github.com/m-bain/whisperX
- 类别：字幕（语音转文字 + 词级对齐 + 说话人分离）
- 中文效果：README 没有中文专项评测。它的强项是**时间戳精度**和 2026 年新增的 **Context-Aware Batching**（官方称改善标点和专有名词 adherence，即对 Cloudflare/Docker 这类专有名词更友好，配 arXiv 2608.31170）。中文词级对齐依赖 wav2vec2 的对齐模型，中文效果未核实。README 自己承认「Diarization is far from perfect」（说话人分离远非完美）。
- 硬件要求：官方 README 写「requires **<8GB GPU memory** for large-v2 with beam_size=5」，70x 实时（large-v2）。**纯 CPU 官方支持**：`whisperx path/to/audio.wav --compute_type int8 --device cpu`。GPU 需要先装 CUDA toolkit **12.8**（Windows 用户也有官方下载指引）。
- Windows 支持：README 明确写了 Windows 用户的 CUDA 12.8 安装指引（NVIDIA 官方下载页），但**没有 Windows 专用安装包**；`pip install whisperx` 或 `uvx whisperx`，可能还需要 ffmpeg / rust。说话人分离模型在 HF 上是 gated，需要接受协议并传 `--hf_token`。
- AI 助手能否调用：**能，CLI 为主**：`whisperx path/to/audio.wav`、`whisperx audio.wav --model large-v2 --diarize --highlight_words True`、CPU 用 `--compute_type int8 --device cpu`；也支持 `uvx whisperx` 免安装运行。Python API 可用（`whisperx.load_model(...)` → `model.transcribe(...)` → `DiarizationPipeline(token=...)` → `whisperx.assign_word_speakers(...)`）。
- 开源协议：代码 **BSD-2-Clause**（`gh api` 实读）。**权重分两块**：Whisper 权重 Apache-2.0（可商用）；**说话人分离用的 pyannote 模型 `pyannote/speaker-diarization-community-1` 是 CC-BY-4.0**（HF API 实读），CC-BY-4.0 允许商用但要求署名，且该模型在 HF 上是 gated（需登录接受条款）。另外 wav2vec2 对齐模型为 MIT/CC 系，未逐一核实。
- 活跃度：Star **24,322**；最近一次 push **2026-09-26**；未归档；最新 Release 3.8.7rc1（2026-06-26），稳定版 v3.8.6（2026-05-25）。Open issues 229。
- 已知坑：说话人分离不完美（README 原文）；diarization 需要 HF token 且模型 gated（README）；README 顶部有 Recall.ai 的赞助位（不影响功能）。
- 对委托人的价值：**中**。如果视频里只有你一个人的旁白，词级时间戳和说话人分离都用不上，直接 faster-whisper 更轻；只有当你要做「字幕逐字高亮」或多角色对话类教程时才值。
- 出处：https://github.com/m-bain/whisperX ｜ https://huggingface.co/api/models/pyannote/speaker-diarization-community-1

### IndexTTS（B 站开源，零样本语音克隆 + 情感/时长可控）
- 地址：https://github.com/index-tts/index-tts
- 类别：配音 + 声音克隆
- 中文效果：**这批里中文主观口碑最好的一档**。最新 **IndexTTS-2.5**（0.8B）官方 benchmark（Seed-TTS-eval 风格，中文）：WER 3.62 / SS 63.83，RL 版 3.55 / 67.47；对比同表 CosyVoice3-0.5B（WER 3.23 / SS 62.79）、VoxCPM2 2B（4.48 / 64.25）、Qwen3-TTS 1.7B（5.74 / 63.04）、Fish Audio S2 Pro 4B（4.14 / 55.89）。**中英混读有专门的纠音机制**：支持中文拼音、英文 CMU 音素、日语假名三种发音控制（README 与 2.5 更新日志都写明）。但社区反馈**不是没有争议**：Issue #801 是一份带 seed、带 A/B 盲测流程的中文质量回归报告，结论是 2.5 在 6 组里输给 2.0 共 5 组，作者怀疑与 2.5 把 speaker 条件从 Conformer/Perceiver 换成单个 192 维 CAMPPlus embedding、semantic codec 从 50Hz 降到 25Hz 有关（该 Issue 至 2026-08-29 提交后 0 评论、仍 open）https://github.com/index-tts/index-tts/issues/801 。另有 #565「中英文混合的文本，TTS 合成会读错带英文连字符的单词」https://github.com/index-tts/index-tts/issues/565 、#678「中文秒读成了英文 S」https://github.com/index-tts/index-tts/issues/678 、#775「英文长段落末句对齐坍塌，默认 max_text_tokens_per_segment=120 是按中文 token 密度标定的」https://github.com/index-tts/index-tts/issues/775 。→ 实操建议：**中英混读的长英文段落要按句切开**，并优先用 2.0 或先小样试听 2.5。

### VoxCPM2（面壁智能 2B 免分词器 TTS，代码+权重全 Apache-2.0）
- 地址：https://github.com/OpenBMB/VoxCPM ；主页 https://voxcpm.com ；文档 https://voxcpm.readthedocs.io
- 类别：配音 + 声音克隆（另支持 Voice Design，无需参考音频即可用自然语言描述造音色）
- 中文效果：**中英混读是它的设计目标之一**——**30 种语言无需语言标签，直接输入文本即可**；支持 **10 种中文方言**（四川话、粤语、吴语、东北话、河南话、陕西话、山东话、天津话、闽南话）。官方 benchmark：在 VoxCPM 自家表里 VoxCPM2 是 test-ZH CER 1.16% / SIM 78.0%（与 CosyVoice3 同档）；**但在 IndexTTS 官方对照表里 VoxCPM2（2B）的 test-zh 表现是 WER 4.48 / SS 64.25，弱于 IndexTTS2.5 与 CosyVoice3**。两个口径差异明显，说明各家用的是不同测试集，**建议自己拿样音 A/B**。48kHz 输出是实打实的优势（无需外挂超分）。已知长文本问题：Issue #302「Long-form voice cloning drift: prompt/reference conditioning may become self-generated latent conditioning」https://github.com/OpenBMB/VoxCPM/issues/302 —— 长音频克隆会漂移，教程视频（往往一条几分钟）要注意分段。
- 硬件要求：**官方给了明确数字**：VoxCPM2 参数 2B，**VRAM 约 8GB**，RTX 4090 RTF **~0.30**，用 Nano-vLLM 加速后 **~0.13**；上一代 VoxCPM1.5（0.6B）约 6GB / RTF 0.15，VoxCPM-0.5B 约 5GB / RTF 0.17。**纯 CPU 有官方路径**：支持 `device` 参数 `auto/cpu/mps/cuda/cuda:N`，且官方推荐用 **llama.cpp-omni**（C++ 推理引擎，原生支持 VoxCPM2 GGUF，可在 **CPU / Metal / CUDA / Vulkan** 上跑，无需 Python），官方给的 CPU 参考是「**RTF ~1.76（Q8_0）在 Apple M4 Pro / Metal**」——即 CPU/边缘端大约比实时慢不到 2 倍，可用但慢。另有 VoxCPM.cpp、audio.cpp、VoxCPM-ONNX 等社区推理后端。
- Windows 支持：**未核实**（README 没有 Windows 专项章节或一键包）。但 `pip install voxcpm` + Python 3.10~3.12 + PyTorch ≥2.5 + CUDA ≥12 是标准 Windows 可走路径；llama.cpp-omni 有 CPU/Vulkan 后端，理论上 Windows 可用（未核实其 Windows 预编译包）。
- AI 助手能否调用：**能，CLI 最规范**：`voxcpm design --text "..." --output out.wav`（纯 Voice Design）、`voxcpm design --text "..." --control "Young female voice, warm and gentle" --seed 42 --output out.wav`（带风格控制）、`voxcpm clone --text "..." --reference-audio path/to/voice.wav --output out.wav`（克隆）。Python API：`VoxCPM.from_pretrained("openbmb/VoxCPM2")` → `model.generate(...)` / `model.generate_streaming(...)`。生产部署有**官方 vLLM-Omni 服务，带 OpenAI 兼容 API**（PagedAttention）。国内可用 ModelScope 下载。
- 开源协议：**代码和权重都是 Apache-2.0，官方明确写「free for commercial use」**。`gh api` 实读 `license.spdx_id = Apache-2.0`；HF `openbmb/VoxCPM2` 的 cardData 实读 `license: apache-2.0`；README 原文「📜 **Fully Open-Source & Commercial-Ready** — Weights and code released under the Apache-2.0 license, free for commercial use」。→ **商用最省心的选项**。
- 活跃度：Star **38,250**（本清单第二）；最近一次 push **2026-09-30**（很活跃）；未归档；最新版本 VoxCPM2 于 **2026.04** 发布（README News 中，仓库未用 GitHub Release 逐版发）。Open issues 数量未单独取（搜索到的是列表子集）。创建时间 2025-09-16 —— **属于「2025 年下半年以后新出」的模型**。
- 已知坑：长音频克隆漂移（#302）；显存需求约 8GB（2B 模型，比 0.5B 级重）；Windows 支持未核实；CPU 速度官方只给了 Apple M4 Pro 数据，Windows CPU 未核实。
- 对委托人的价值：**高**。中文方言+30 语言免标签混读、Apache-2.0 全开源可商用、CLI 规范、8GB 显存门槛明确、还有 CPU 兜底路径——综合看是「长期做商用教程视频」的最优解；代价是要先自己 A/B 验证中文自然度是否够（各家 benchmark 口径冲突）。

## 拿不准的点

1. **CosyVoice 的仓库状态**：`gh api repos/FunAudioLLM/CosyVoice` 实读 `full_name = QwenAudio/CosyVoice`，说明仓库已迁移/改名到 Qwen 组织。原链接仍能跳转，但「FunAudioLLM 是否已停止维护、开发是否搬到新仓库」未核实；且该仓库最近一次 push 是 2026-05-25（本清单里最旧），Releases 接口返回空。用它之前建议先确认是否有新家。
2. **edge-tts 的商用合规性**：代码是 LGPLv3（仅 srt_composer.py 为 MIT），但真正的问题是这个工具**逆向调用微软 Edge 的在线 TTS 服务且不提供 API key**。微软 ToS 是否允许、批量商用是否会被限流或封禁，**本次未找到权威来源**。要商用建议改用 Azure 语音付费服务。
3. **剪映「免费版不可商用」的条款原文**：多篇第三方文章（FlowPix、提效录）都引用「用户协议第 7.3 条」，但本次只读到剪映官方的《"剪映"AI 功能使用规范》页面，**没有直接读到那一条原文**。引用时建议自己再核一遍剪映最新用户协议。
4. **各家 benchmark 数字互相矛盾**：同一模型在不同官方对照表里的数字差距极大（例如 Fish Audio S2 Pro 中文 WER：官方自称 0.54%，CosyVoice/IndexTTS 对照表里是 4.14；Qwen3-TTS 在 IndexTTS 表里 5.74、在 Fish Audio 表里 0.77/1.24）。**结论：不要跨表比较，也不要只看官方自测，必须自己用真实素材 A/B。**
5. **显存数字的可靠度分级**：只有 **VoxCPM2（约 8GB）** 和 **faster-whisper（GPU 4.5~6GB）** 是官方 README 给的；**IndexTTS 官方没给显存数字**，8GB 结论来自 Issue 里用户实测和社区整合包；**CosyVoice3「6G 勉强/8G 可以跑」来自第三方博客**；**GPT-SoVITS「推理 4G、训练 6G」来自官方飞书 Wiki**（未能在 GitHub README 里二次确认）。**Qwen3-TTS 和 F5-TTS 完全没找到显存数字。**
6. **纯 CPU 跑本地配音的真实体验**：GPT-SoVITS 官方给了 M4 CPU RTF 0.526 和社区 CPU 优化版链接；VoxCPM2 官方给了 Apple M4 Pro/Metal 的 RTF 1.76；**但 Windows CPU 上的实际速度一个都没有核实**。IndexTTS、CosyVoice、Qwen3-TTS、F5-TTS、fish-speech 的 CPU 路径均未核实或官方不支持。
7. **Windows 支持的分级**：确认有官方 Windows 说明/一键包的只有 **VideoCaptioner、GPT-SoVITS、FunASR（原生 exe）、WhisperX（CUDA 安装指引）、edge-tts、faster-whisper（NVIDIA 库来源说明）、IndexTTS（官方承认 DeepSpeed 难装）**；**CosyVoice、F5-TTS、fish-speech、VoxCPM2、Qwen3-TTS 的 Windows 支持本次未核实**（它们都是 Python/pip 路线，理论上能跑，但没有官方文档背书）。
8. **VideoCaptioner 的免费在线 ASR 的隐私与合规**：`bijian`（必剪）/`jianying`（剪映）是把音频发到字节的在线接口，**音频会上传云端**，且没有官方说明其商用条款。教程视频如果涉及未公开内容，建议改用本地 faster-whisper/FunASR 引擎。
9. **FunASR 权重的商用边界**：MODEL_LICENSE 明确允许使用/修改/分享、要求署名保留模型名，但**没有写「允许商用」这四个字**，也不是 OSI 标准协议。虽然按常理解读「未禁止即可用」，但严格法律判断未核实，商用前建议自己通读或咨询。
10. **IndexTTS 权重协议里「不得用于改进其他 AI 模型」的影响范围**：原文 3.4(c) 的例外是「非商用 AI 模型」。用 IndexTTS 的输出去**训练/微调你自己的商用声音模型**显然被禁；但「用它的音频做视频旁白」不在禁止之列（那是正常使用而非改进模型）。**边界情形（例如拿生成的音频做数据集训练非商用模型再转商用）未核实。**
11. **各工具最近一次提交日期的读法**：本文件「最近一次 push」取自 `gh api repos/<owner>/<repo>` 的 `pushed_at` 字段，**包含任何分支的任何提交**，不完全等于「主干最后一次功能更新」，但能反映仓库是否还活着。Star 数取自 `stargazers_count`，为 2026-10-01 查询时的快照。
