# 文转视频与代码化视频
> 调研日期：2026-10-01

## 结论

1. **做「代码演示 / 架构图动画 / 60 秒技术讲解」，首选 Remotion。** 它是唯一一个官方就提供 AI 助手 skill（`npx skills add remotion-dev/skills`，含 `/remotion-create`、`/remotion-render`、`/remotion-captions`）的项目，Claude Code 能从头写脚本、渲染到出成片。许可证对个人和 3 人以内小团队**免费商用**，委托人一个人做完全够用；只有超过 3 人的营利公司才要买 Company License。（https://www.remotion.dev/docs/ai/skills 、https://www.remotion.dev/docs/license/pricing）
2. **要数学/算法类讲解动画，用 Manim 本体 + `manim-mcp` 组合。** Manim 本身不接 AI，`paulnegz/manim-mcp` 补上了这一环：同时提供 CLI、agent 模式和 **MCP server**，Claude 可以「文字 → 代码 → 视频」直接调用；缺点是项目小（20 star）、更新停在 2026-02。
3. **MoneyPrinterTurbo / NarratoAI 这类「素材拼接型」一键成片工具，是低质判定风险最高的一类。** MoneyPrinterTurbo 的画面 100% 来自 Pexels/Pixabay 免费素材库随机拼接，Issue #680 里用户实测「给『猪八戒』生成的画面是外国人形象，与文案完全不符」，社区结论是「只能用自己的素材，几乎无解」。这类批量起号产物正是平台重点打击的对象。（https://github.com/harry0703/MoneyPrinterTurbo/issues/680）
4. **Motion Canvas 实质已停更，别新开项目用它。** Issue #1221「Is the repo dead?」仍在讨论，作者 GitHub 自 2025 年 5 月起不活跃，官网 motioncanvas.io 一度下线，最新稳定版停在 v3.17.2（2024-12-14）。社区已 fork 出 `canvas-commons/canvas-commons`（250 star，2026-09 仍在提交）。（https://github.com/motion-canvas/motion-canvas/issues/1221）
5. **纯「幻灯片/网页转视频」这条路，开源方案都不成熟。** Slidev 官方只导出 PDF/PPTX/PNG，不导出视频；`nexu-io/html-video`（4.6k star）和 `code2mp4`（8 star）是 2026 年新出的「HTML → MP4」方向，定位对 AI 助手友好，但都很新、坑未验证。若坚持这条路，更稳的做法是「Remotion 直接渲染」而不是「先做网页再转视频」。

### MoneyPrinterTurbo（一句话定位：给个主题，AI 写文案 + 免费素材库拼接成一键短视频）
- 地址：https://github.com/harry0703/MoneyPrinterTurbo
- 形态：Python + 自托管网页服务（Streamlit WebUI / Docker / Windows 一键启动包）
- 适合的视频类型：**素材拼接**（口播氛围片、批量起号），不适合代码演示或架构动画
- AI 助手能否全程驱动：**不能以 skill/MCP 方式驱动**。它是给人点的 WebUI，AI 只负责链路上的「写文案 + 生成搜索词」；未发现官方 MCP 或 Claude Code skill。可在外部用 Claude Code 调它的 Python 接口，但无现成封装。
- Windows 支持与渲染速度：**Windows 支持好**，官方有 Windows 一键启动包，README 明确写了 Windows 虚拟内存不足（WinError 1455）、ffmpeg 找不到的排错办法。渲染速度**慢**：Issue #767 用户反馈 win10/i7/16G 也慢，维护者回复「没有任何一个配置项能让它突然变快，瓶颈在媒体处理、合成、编码和上游 API 延迟」。（https://github.com/harry0703/MoneyPrinterTurbo/issues/767）
- 开源协议：MIT（gh api 读取）
- 活跃度：**127,764 star**，最近提交 **2026-10-01**（就是调研当天），未归档。是本次调研中 Star 最高的项目，但注意这个数字明显异常膨胀，不能当质量指标看。
- 已知坑：
  - 画面与文案不相关：https://github.com/harry0703/MoneyPrinterTurbo/issues/680
  - 生成慢无解：https://github.com/harry0703/MoneyPrinterTurbo/issues/767
  - 合成/合并视频失败（ffmpeg、MoviePy 相关）：https://github.com/harry0703/MoneyPrinterTurbo/issues/720 、https://github.com/harry0703/MoneyPrinterTurbo/issues/776
  - 画面来源本质：第三方拆解文指出「画面没有一个像素出自模型」，全部来自免费素材库 —— https://wangruofeng007.com/blog/2026-08/moneyprinterturbo-pipeline-deep-dive/
- 对委托人的价值：**低**。技术讲解要的是代码演示和架构图，它只会拼别人的素材，恰好踩中「搬运/低质」红线。
- 出处：https://github.com/harry0703/MoneyPrinterTurbo ；`gh api repos/harry0703/MoneyPrinterTurbo`

### Remotion（一句话定位：用 React 组件写视频，官方自带 AI 助手 skill）
- 地址：https://github.com/remotion-dev/remotion
- 形态：Node/TypeScript 库 + CLI + Studio 预览器；官方另有 `remotion-dev/skills` 提供 AI 助手 skill

- AI 助手能否全程驱动：**能，是本次调研里最完整的。** 官方文档《Prompting videos with coding agents》给出完整流程：`npx remotion skills add` 安装 skill，然后在项目里 `claude`（或 codex / kimi / opencode）直接提需求即可。官方 skill 列表包含 `/remotion-create`、`/remotion-render`、`/remotion-captions`、`/remotion-best-practices` 等。仓库里同时有 `.agents/skills` 和 `.claude/skills` 两套目录。此外社区还有 `wshuyi/remotion-video-skill`（385 star，中文作者）和 `haidrrrry/claude-remotion-skill`。（https://www.remotion.dev/docs/ai/skills 、https://www.remotion.dev/docs/ai/claude-code）
- Windows 支持与渲染速度：跨平台，Windows 可跑；渲染走 Chrome headless + FFmpeg，逐帧渲染，速度取决于时长和分辨率，官方有 Lambda 云端渲染方案可加速。
- 开源协议：**自定义许可证（GitHub 标记 NOASSERTION）**。已核实原文：个人、**3 人及以下的营利组织**、非营利组织、以及尚在评估阶段的用户，可以**免费商用**（Free License）；不满足条件才需要 Company License。禁止的是「复制/修改 Remotion 代码去卖自己的衍生版」。委托人独立开发者 → **免费可用**。（https://github.com/remotion-dev/remotion/blob/main/LICENSE.md 、https://www.remotion.dev/docs/license/pricing）
- 活跃度：**61,339 star**，最近提交 **2026-10-01**，未归档。文档站页面标注最后更新 2026-09-30，非常活跃。
- 已知坑：许可证边界必须自查（员工数 > 3 的营利公司要付费）；其余未读到集中性的严重反馈。GitHub 上有 241 个 open issue。
- 对委托人的价值：**高**。唯一「官方 skill + 免费商用 + 适合技术内容」三者都满足的方案。
- 出处：https://github.com/remotion-dev/remotion ；https://www.remotion.dev/docs/ai/skills ；https://www.remotion.dev/docs/license/pricing ；`gh api repos/remotion-dev/remotion`

### Manim（一句话定位：3Blue1Brown 那套数学动画引擎的社区维护版）
- 地址：https://github.com/ManimCommunity/manim
- 形态：Python 库 + 命令行（`manim` 命令渲染场景）
- 适合的视频类型：**数学/算法/物理原理动画讲解**，是最经典的「技术讲解动画」工具
- AI 助手能否全程驱动：**本体不能**（纯 Python 库，无 AI 集成）；需要配下面的 `manim-mcp` 才能让 Claude 全程驱动。
- Windows 支持与渲染速度：跨平台，Windows 需要装 Python + FFmpeg，数学公式要 LaTeX（Windows 上配 LaTeX 是常见痛点）。渲染慢是 Manim 公认特点，逐帧渲染 + 每帧重绘。
- 开源协议：MIT（gh api 读取）
- 活跃度：**41,177 star**，最近提交 **2026-09-29**，未归档。非常活跃（500 个 open issue 也说明问题多）。
- 已知坑：Windows 上 FFmpeg / LaTeX 环境配置是新手主要卡点；未读到集中的平台判罚反馈（Manim 是原创动画，不属于搬运）。
- 对委托人的价值：**中**。做「算法可视化讲解」它是最专业的，但纯手写代码成本高，建议配合 `manim-mcp` 用。
- 出处：https://github.com/ManimCommunity/manim ；`gh api repos/ManimCommunity/manim`

### manim-mcp（一句话定位：让 AI 助手用自然语言生成并渲染 Manim 动画的 MCP 服务）
- 地址：https://github.com/paulnegz/manim-mcp
- 形态：**MCP 服务** + CLI + LLM agent 三种形态（这是任务书点名要找的那类接口）
- 适合的视频类型：**数学/算法动画讲解**（基于 manimgl，即 3Blue1Brown 原版库）
- AI 助手能否全程驱动：**能**。README 明确写「Works as a CLI tool, an LLM-powered agent, or an **MCP server** for integration with AI assistants like Claude」。多 agent 流水线：概念分析 → 场景规划 → 代码生成 → 代码审查。内置 RAG（3,140 个 3Blue1Brown 场景示例、1,652 个 API 签名、101 个动画模板），支持 Gemini / Claude / DeepSeek，可并行生成 TTS 旁白并自动对齐时长。
- Windows 支持与渲染速度：Python 3.11+，需自装 manimgl、可选 ChromaDB/ffmpeg/LaTeX。Windows 未做特别声明，LaTeX 仍是门槛。
- 开源协议：MIT（gh api 读取）
- 活跃度：**20 star**，最近提交 **2026-02-25**，未归档。**小、新、更新已停半年**。
- 已知坑：项目太小，未形成 Issue 讨论；1 个 open issue。依赖 manimgl（非 ManimCommunity 版），两者 API 不通用，需要注意。
- 对委托人的价值：**中**。它是「AI 全程驱动 Manim」这条路上接口最规范的现成方案，值得试，但要有自己兜底维护的心理准备。
- 出处：https://github.com/paulnegz/manim-mcp

## 闭源对照

- **Sora 2 / Veo 3 / Kling / Runway**：像素级文生视频模型，画面华丽但**无法保证技术准确性**（Code2Video 论文正是拿它们当反例），不适合有明确知识点的技术讲解。Code2Video 仓库把 Veo3、Wan2.2 与自己的成片做了对比。
- **HeyGen / D-ID**：数字人口播视频，委托人明确不露脸、且要讲代码，用途不匹配。
- **剪映 / CapCut（含其 AI 成片功能）**：国内创作者主流工具，模板化和素材拼接能力强，但本质仍是人工剪辑 + 模板，不是「AI 助手写脚本直接出片」，且模板化产物同样有同质化风险。

## 拿不准的点

1. **Remotion 的「3 人以内」边界**：原文是「a for-profit organization with up to 3 employees」。委托人是独立开发者、单人，肯定在免费范围内；但若以后扩到 4 人以上营利公司，必须买 Company License。条款还提到 v5.0 会有变化（README 里指向 PR #3750），建议用之前再看一眼当时的 LICENSE.md。
2. **MoneyPrinterTurbo 的 127,764 star 无法解释**：这个数字远超同类（Remotion 6 万、Manim 4 万），我没有找到可信解释，也**没有找到任何直接说「用它的视频被平台判为低质/限流」的 Issue**。文件里「容易被当低质」的判断是基于「画面全部来自公共素材库随机拼接、与文案不相关」（Issue #680）推出的，属于**推断而非平台实证**，请勿当作官方结论引用。
3. **「平台判为低质/搬运」这类反馈，本次几乎没有找到一手证据**：我在 GitHub Issue 和中文文章里搜了 MoneyPrinterTurbo、NarratoAI，只搜到内容质量差、处理失败的技术类 Issue，没搜到创作者报告「被限流/判搬运」。B站/抖音的判定标准本身不公开，这一项**未核实**。
4. **渲染速度普遍没有权威数字**：除 MoneyPrinterTurbo 有用户抱怨慢（Issue #767）外，Remotion、Motion Canvas、Revideo、Manim、html-video 的渲染速度我都只读到定性描述（「逐帧渲染」「零依赖」），**没有找到带硬件配置的实测耗时**，因此各条里只写了机制、没写秒数。
5. **Revideo 已改名/转移**：任务书给的 `redotvideo/revideo` 会重定向到 `midrender/revideo`，homepage 变成 midrender.com。改名原因和时间未核实。
