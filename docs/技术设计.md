## 技术选型

| 技术 | 用来干什么 | 为什么选它 | 备选 |
|---|---|---|---|
| TypeScript 5（带类型检查的 JavaScript） | 全部代码，开严格模式 | 和博客同一门语言，类型能挡住大部分低级错误 | Python |
| Node.js 24（运行 JavaScript 的程序），最低 24.2 | 运行环境 | 本机已装（24.18）；自带 SQLite 模块；命令行入口用到的 `import.meta.main` 从 24.2 起才有 | Bun |
| pnpm 10（装依赖的工具） | 依赖管理，锁定精确版本 | 和博客一致 | npm |
| commander（命令行参数解析库） | `leafpress` 的各个子命令 | 最常用，稳定 | citty |
| node:sqlite（Node 自带的 SQLite，一个文件就是一个数据库） | 记录库 | 不用另装数据库服务，Windows 上也不用编译原生模块 | better-sqlite3 |
| zod（数据校验库） | 校验配置、原稿元数据、AI 交回的结果 | 和博客一致；校验失败能说清是哪个字段 | valibot |
| gray-matter（读 Markdown 文件头部元数据的库） | 读原稿的标题、标签、日期 | 和博客一致 | 手写解析 |
| unified + remark（把 Markdown 解析成结构树的库） | 找图片和流程图、补全链接、改写结构 | 和博客一致，生态最全 | markdown-it |
| puppeteer-core（用程序控制浏览器的库，本身不带浏览器）+ 本机 Edge | 流程图转图片；以后小红书卡片出图也用它 | 不用额外下载浏览器，符合本机优先用 Edge 的约定 | playwright-core |
| mermaid（官方流程图库） | 在无界面的 Edge 里把流程图画成图片 | 和博客渲染流程图用的是同一套写法 | mermaid-cli（会自带下载一个浏览器） |
| 知乎官方发布 skill + 图片上传 skill（知乎出的 Claude Code skill） | 知乎文章、想法的格式转换、传图、预览、发布 | 官方维护，知乎改规则时它跟着升级 | 自己签名调发布接口 |
| 知乎数据开放平台（知乎官方 HTTP 接口） | 搜问题、拿推荐问题；以后拉数据 | 个人可用，有免费额度 | 无 |
| FFmpeg（处理音视频的命令行工具） | 以后视频形态的转码、截封面、烧字幕 | 事实标准 | 无；首版不装 |
| Vitest（测试框架） | 单测 | 和博客一致 | node:test |
| ESLint + typescript-eslint（静态检查）+ Prettier（统一代码格式） | 门禁 | 和博客一致，零警告 | Biome |
| tsx（直接运行 TypeScript 的工具） | 开发时直接跑命令 | 不用每次先构建 | Node 自带的类型剥离 |

## 目录结构

```
LeafPress/
├── src/
│   ├── cli/          命令行入口和各子命令：只解析参数、调用下层、输出文字或 JSON
│   ├── core/         内容模型：作品、原稿、资产、版本、形态、发布记录的类型，形态目录，纯函数
│   ├── workflows/    工作流框架（步骤、暂停、恢复）和具体工作流（转写、题单、随手记）
│   ├── platforms/    平台接入：统一接口、平台登记表；每个平台一个子目录（blog、zhihu，以后 xiaohongshu、bilibili……）
│   ├── publishers/   发布方式：交给 skill、手动成品、写 git 仓库；以后加官方接口直连、外部命令行
│   ├── assets/       资产处理：图片、流程图渲染、无界面浏览器；以后加卡片、视频
│   ├── materials/    素材收集器：进度记录、review 记录、提交记录
│   ├── store/        记录库：建表与升级、各张表的读写
│   ├── config/       本地配置与凭证读取
│   └── shared/       路径、日志、错误类型、文件哈希等公共件
├── skills/           LeafPress 的 Claude Code skill 源文件，安装命令把它们链接到用户级 skill 目录
├── rules/            写作规则：知乎写法、去 AI 味规则、禁用句式
├── tests/            单测，目录和 src 一一对应
└── docs/             设计文档、模块文档、调研、进度、review
```

个人数据不放在仓库里，默认在用户目录下（环境变量 `LEAFPRESS_HOME` 可以改位置）：

```
~/.leafpress/
├── config.json       本地配置：博客仓库路径、博客网址、素材项目名单、知乎数据接口密钥
├── leafpress.db      记录库
└── runs/<运行编号>/   每次工作流运行的文件：AI 任务和结果、版本稿件、成品包、交接目录
```

知乎发布用的凭证不在这里保存，直接复用知乎官方 skill 的共享凭证文件 `~/.zhihu/openapi-credentials.json`（或环境变量 `ZHIHU_OPENAPI_APP_KEY` / `ZHIHU_OPENAPI_APP_SECRET`）。

## 工程规范

- **严格模式**：TypeScript 开 `strict`，另开 `noUncheckedIndexedAccess`（按下标取值时必须处理取不到的情况）和 `noImplicitOverride`。模块格式用 ESM。
- **门禁命令**：`pnpm gate`，依次跑格式检查、静态检查（零警告）、类型检查、单测、构建，全部通过才能提交。
- **换行**：`.gitattributes` 固定 LF，Windows 脚本保留 CRLF。
- **依赖**：版本写死，不用 `^`。
- **文件**：一个文件一个职责，超过 300 行就拆。
- **密钥**：任何日志、错误信息、命令输出都不打印密钥；配置出错时只说是哪个字段。
- **命令输出**：每个子命令都支持 `--json`，给 skill 读；默认输出给人看的中文。
- **提交信息**：`类型(范围): 中文说明`，例如 `feat(store): 建立记录库`。

## 测试策略

| 必须有单测 | 说明 |
|---|---|
| 原稿解析 | 元数据、正文、图片、流程图、站内链接都能正确取出 |
| 形态限制校验 | 标题字数、图片张数等超限时给出清楚的提示 |
| 固定转换 | 链接补全、原文链接、流程图替换成图片引用 |
| 禁用句式检查 | 规则文件里的每类句式都有正反例 |
| 记录库 | 建表、升级、增删改查、防重复发布 |
| 工作流 | 步骤推进、暂停与恢复、上游文件改动后下游作废、失败后重试 |
| 素材收集 | 只收上次之后新增的内容，不重复收 |
| 配置与凭证 | 校验错误能指出字段；任何路径下都不泄露密钥 |
| 发布结果解析 | 能从官方 skill 的结果文件里取出链接和编号，失败时不误判为成功 |

- 外部依赖（git、知乎接口、浏览器、官方 skill）在单测里用假实现代替；真实联调放在里程碑验收时做。
- 复制页、卡片的样式不写单测，肉眼看。

## 关键决策

1. **AI 步骤只在 Claude Code 里跑。** 命令行遇到 AI 步骤就写出任务文件并暂停，skill 做完再让它接着跑。这样不额外花钱，命令行本身也保持可测试。
2. **知乎文章交给官方 skill 发布。** 知乎的格式规则复杂而且会变，官方 skill 会跟着平台升级，我们只负责交稿和读结果。
3. **知乎回答走复制页。** 官方发布接口不支持发回答。
4. **原稿统一以博客仓库为准。** 博客是自己的地盘；在 Notion 写的文章也会同步进博客仓库，所以读之前先把仓库拉到最新。
5. **个人数据放用户目录。** 代码仓库里没有个人数据，以后开源不用清理。
6. **用 Node 自带的 SQLite。** 省掉在 Windows 上编译原生模块的麻烦。
7. **无界面浏览器用本机 Edge。** 不额外下载浏览器；流程图和以后的卡片出图共用一套。
8. **首版不做定时任务，也不做模拟浏览器发布。** 题单在作者问的时候再生成就够用；模拟浏览器发布的账号风险高。
