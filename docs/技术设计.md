> 这一版按「个人全栈自媒体工作台」重写：本机运行，一个程序同时提供网页和数据接口，agent 用命令行接手作品。旧版在 git 历史里。

## 技术选型

| 技术 | 用来干什么 | 为什么选它 | 备选 |
|---|---|---|---|
| TypeScript（带类型检查的 JavaScript），开严格模式 | 全部代码：命令行、本机服务、网页、共享规则 | 一门语言从头到尾；类型挡住大部分低级错误；第一阶段和原型都是它 | — |
| Node.js 24（运行 JavaScript 的程序），最低 24.2 | 命令行和本机服务的运行环境 | 本机已装；自带 SQLite 模块；第一阶段已经在用 | Bun |
| pnpm 10 工作区（一个仓库放几个包、互相引用） | 管命令行和服务、网页、共享规则三个包 | 共享规则只写一份，三处都用；一条门禁命令跑全部 | 拆成几个仓库 |
| commander（命令行参数解析库） | `leafpress` 的各个子命令 | 第一阶段已经在用，稳定 | citty |
| node:sqlite（Node 自带的 SQLite，一个文件就是一个数据库） | 记录库：作品、灵感、账号、数据快照、复盘 | 不用另装数据库服务；第一阶段已经在用；命令行和本机服务都能直接读写 | better-sqlite3 |
| Hono（很小的网页服务框架）+ @hono/node-server | 本机服务：数据接口加托管网页 | 小、专为 TypeScript 写、接口好测；托管静态网页一行就够 | Fastify、Express |
| zod（数据校验库） | 校验配置、接口收到的数据、命令行读到的文件 | 第一阶段已经在用；校验失败能说清是哪个字段 | valibot |
| Next.js 16 静态导出 + React 19 + Tailwind CSS 4 + shadcn 组件 + zustand | 网页：原型直接升级，构建成静态文件交给本机服务托管 | 原型已经做完、用户认可；静态导出不需要另起网页服务 | — |
| gray-matter + unified / remark（读 Markdown 元数据、把 Markdown 解析成结构树） | 读博客原稿；改写时的固定转换（补全链接、流程图换成图片） | 第一阶段已经在用，和博客仓库一致 | markdown-it |
| puppeteer-core（用程序控制浏览器的库，本身不带浏览器）+ 本机 Edge | 流程图转图片、生成复制页里的图；以后小红书卡片出图 | 不额外下载浏览器，本机优先用 Edge | playwright-core |
| Umami 网站统计的接口 | 拉博客的访问、访客 | 博客已经接了 Umami；用户定博客只走它 | — |
| Windows 计划任务（系统自带的定时器，用 `schtasks` 命令管理） | 每天定时拉数据 | 系统自带、不用常驻进程；电脑开着就跑，错过的下次补 | 本机服务里自己定时（要一直开着） |
| AI 工具自带的定时任务（Claude Code、Codex 的定时任务） | 要 AI 判断的定时活，比如跑灵感（以后做） | 用户定：代码能写的用计划任务，要 AI 的用 AI 定时任务 | — |
| Vitest（测试框架）、ESLint + typescript-eslint（静态检查）、Prettier（统一代码格式） | 门禁 | 第一阶段和原型都在用，零警告 | Biome |
| tsx（直接运行 TypeScript 的工具） | 开发时直接跑命令行和服务 | 不用每次先构建 | Node 自带的类型剥离 |

├── packages/

│       └── src/
│           ├── types/       作品、灵感、账号、工作流、接入、数据项、数据快照的类型
│           ├── api/         本机服务的请求和返回、用例门面的接口
│           ├── catalog/     平台目录（名字、数据项、账号要配的东西）、工作流目录（步骤、产出、要你做的事）
│           ├── dates/、format/、labels/   日期计算、数字和时间的显示、中文标签
│           ├── workflows/   按平台和来源自动配工作流、能不能用、填占位符
│           ├── works/       作品状态怎么变（接手、做完一步、代码步骤的结果、退回、反馈、拖动）、看板、转作品、任务说明
│           ├── ideas/       灵感排序、挪列、转作品后记账
│           ├── setup/       接入状态（接好了、有问题、没接完）、还缺什么、拉数据前的判断
│           ├── metrics/、report/、notices/   数据集整理、概况、走势、排行、周报、提醒
│           └── markdown/    账号档案的 Markdown 解析和一句话简介
├── src/                     命令行和本机服务（一个 Node 程序，两种用法）
│   ├── cli/                 子命令：只解析参数、调用用例、输出中文或 --json
│   ├── server/              本机服务：数据接口、托管网页、变更序号
│   ├── usecases/            用例：转作品、接手作品、推进一步、提交反馈、拉数据、算周报……命令行和接口共用
│   ├── store/               记录库：建表与升级（升级前备份）、各张表的读写
│   ├── files/               数据目录里的文件：任务文件夹、账号档案、导出备份
│   ├── platforms/           平台适配：代码步骤和拿数据工具的实现，每个平台一个子目录（定义在共享包的 catalog）
│   │   ├── general/         通用工作流的代码步骤（归档链接）
│   │   ├── blog/            博客：读仓库、导入、写稿、门禁、推送、Umami
│   │   └── zhihu/           知乎：改写交接、固定转换、复制页、数据工具（接知乎时定）
│   ├── schedule/            Windows 计划任务的安装、卸下、查看
│   ├── config/              本机配置和凭证
│   └── shared/              路径、日志、错误类型、执行外部命令、文件哈希
├── web/                     网页：原型升级而来，数据改成读本机服务
├── skills/                  LeafPress skill 源文件（教 agent 用命令行做作品），安装命令链接到用户级 skill 目录
├── rules/                   写作规则：禁用句式等
├── tests/                   命令行和服务的测试，目录和 src 对应
└── docs/                    设计文档、模块文档、调研、进度、review

个人数据不放在仓库里，默认在用户目录下（环境变量 `LEAFPRESS_HOME` 可以改位置）：

```
~/.leafpress/
├── config.json          本机配置：端口、浏览器、拉数据的时间、租约时长（账号的普通配置项进记录库）
├── credentials.json     账号的密钥：Umami 等；接口和命令行都只回答「已配置 / 未配置」
├── leafpress.db         记录库
├── accounts/<账号>.md    账号档案
├── tasks/<作品>/         任务文件夹：作品.md、状态.json、要你做的事.md、你的反馈.md、记录.log，加上各步产出
├── backups/             升级前和手动导出的备份
└── logs/                本机服务和定时任务的日志
```

## 工程规范

- **严格模式**：TypeScript 开 `strict`，另开 `noUncheckedIndexedAccess`（按下标取值时必须处理取不到的情况）和 `noImplicitOverride`；网页包沿用原型的严格配置。模块格式用 ESM。
- **门禁命令**：根目录 `pnpm gate` 依次跑三个包的格式检查、静态检查（零警告）、类型检查、单测、构建，全部通过才能提交。网页包也能单独跑自己的门禁。
- **换行**：`.gitattributes` 固定 LF，Windows 脚本保留 CRLF。
- **依赖**：版本写死，不用 `^`；新依赖要在本文件的技术选型里登记。
- **文件**：一个文件一个职责，超过 300 行就拆。
- **密钥**：任何日志、错误信息、命令输出、接口返回都不打印密钥；配置出错时只说是哪个字段。
- **命令输出**：每个子命令都支持 `--json`，给 agent 读；默认输出给人看的中文。
- **接口**：只监听 `127.0.0.1`；收到的数据先用 zod 校验；改数据的接口都走用例，不直接写表。
- **提交信息**：`类型(范围): 中文说明`，例如 `feat(store): 作品表换成一个作品一个平台`。

## 测试策略

| 必须有单测 | 说明 |
|---|---|
| 共享规则 | 作品状态怎么变、转作品一转多、自动配工作流、接入状态、数据项和走势、周报、Markdown 解析、复制给 AI 的说明（原型里已有的 113 条单测搬过来改） |
| 用例 | 转作品、接手和租约、推进一步、停下等你、反馈后回到待实现最前面、完成并归档链接、拉一次数据 |
| 记录库 | 建表、从旧表升级（升级前备份）、增删改查、变更序号 |
| 任务文件夹和档案 | 状态变化后说明文件跟着更新；档案读写 |
| 接口 | 每个接口的成功和出错（用 Hono 自带的测试方式，不起真端口） |
| 命令行 | `--json` 输出的形状、退出码 |
| 平台适配 | 博客导入、门禁结果解析、Umami 返回的解析、复制页内容；外部依赖（git、Umami、浏览器）用假实现 |
| 配置与凭证 | 校验错误能指出字段；任何路径下都不泄露密钥 |

- 真实联调（真博客仓库、真 Umami）放在里程碑验收时做。

## 关键决策

1. **本机运行，一个程序同时提供网页和接口**（用户定）。任务文件夹、agent、博客仓库、登录过的浏览器都在本机，不需要和线上同步。
2. **规则只写一份，放在共享包**。命令行（agent 用）、本机服务（网页用）都调同一套用例和规则，不会出现网页这样算、agent 那样算。
3. **记录库是唯一的事实来源，任务文件夹是它的镜像加产出**。状态只能经命令行或接口改（走用例），用例改完记录库就更新文件夹里的说明文件；agent 把产出文件直接写进文件夹。这样换哪个 agent 读文件都能接上，状态又不会被随手改乱。
4. **命令行和本机服务各自直接读写记录库**。agent 干活不用先开网页；两边同时写靠事务和作品租约保证不打架。
5. **网页每隔两秒问一次「变更序号」，有变化才重新取数据**。agent 在命令行改了状态，网页几秒内跟着变；比长连接推送简单，本机开销可以忽略。
6. **网页不设「让 AI 做」按钮**（用户定）。AI 都在 agent 里发起，网页负责看、记、处理要你动手的事。
7. **定时活分两类**（用户定）：代码能做的（拉数据）用 Windows 计划任务；要 AI 判断的（跑灵感）用 AI 工具自带的定时任务。周报打开时现算，不用定时生成。
8. **不做手填**（用户定）。数据都靠工具拉；博客只走 Umami（用户定）；知乎、小红书、B站接的时候再定拿数据的办法。
9. **平台和工作流的定义是静态数据，放共享规则包**（网页和命令行直接用）；代码步骤和拿数据工具的实现放 `src/platforms/<平台>/`，按「工作流编号 + 步骤编号」登记。AI 步骤写清做法和产出什么文件；自动步骤由命令行执行；「你来」的步骤写好要你做的事，文件夹路径自动填进去。
10. **第一阶段的代码沿用**：记录库的打开和升级、事务公共件、博客读取、配置、体检、命令行入口。旧的内容模型（原稿、版本、发布记录）换成新模型；第一阶段没有真实数据，升级时旧表备份后重建。第一阶段的工作流引擎（由引擎驱动步骤、按输入文件哈希作废重跑）不再沿用：新模型由 agent 驱动步骤，作品自己记走到第几步，租约改成作品上的令牌（见 [用例](模块设计/用例-业务用例.md)）。
11. **原型的网页直接升级**：页面、组件、令牌都不动，把写死的演示数据和浏览器存储换成读本机服务；原型里纯演示的东西（恢复初始数据、模拟 AI 一步步走）去掉。网页是静态导出，事先不知道有哪些账号，账号详情的地址改成 `/account/?id=<账号>`。
12. **密钥单独放在 `credentials.json`**，和普通配置分开；接口只返回「已配置 / 未配置 / 已过期」。
13. **手机访问以后用 Cloudflare Tunnel 加 Access 登录保护**（用户定）。本机服务默认只在本机能访问。
