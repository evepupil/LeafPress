## 检查点 6：用户体验第一版后改方向，第二版按「作品即任务」重做

**用户的意见**（体验第一版后）

- 只能看不能动。要的是低心智的产出动作：灵感转成作品、作品交给 AI、AI 自动挑工作流、要人动手时停下来等我。
- 四件核心的事：多账号管理、灵感获取、作品管理、任务管理；任务管理就在作品页，不另开页面。
- **作品和平台一比一**：灵感转作品时选几个平台就生成几个作品；已发的博客也是作品，转知乎时生成一个来源是这篇博客的新作品，工作流自动配成「博客转知乎」。
- 要人动手的地方要通用：页面上写「要你做的事」，下面一个反馈框；人回到 agent 说「继续」，agent 读反馈、归档链接、标记完成。
- 所有中间状态放进每个作品的任务文件夹，任何 agent 读它就能接手。
- 灵感页保留，专门产出灵感；卡片要能点开编辑、能拖。作品页最左一列叫「待实现」。卡片都要能编辑（AI 从这里读）。
- 工作流和工具分开；定时工作流（拉数据、跑灵感）一直在跑、看得到结果。公众号插画整条不做。

**我替用户做的判断**

- 作品页做首页，四列：待实现（AI 的待做，按先后排队）→ 进行中 → 等你处理 → 已完成；去掉总览页和工具页，新增工作流页。
- 你提交反馈后作品回到「待实现」最前面，等 AI 继续：agent 只要读「待实现」就能接上，不用另外查进行中。
- 拖到「进行中」等于让 AI 做；拖到「已完成」当作你自己做完了；已完成的不能拖回去。
- 作品和灵感的改动存进浏览器（localStorage），刷新不丢；头像菜单加「恢复初始数据」。粉丝、阅读、排行、周报仍读数据快照，不跟着页面改动变。
- 页面上的「让 AI 做」按真实规则一步步走（每步 0.9 秒），停在要你动手的步骤或者做完；以后接 agent 时走同一套规则。
