# 本机服务 · 接口与托管

> 模块定位：`leafpress serve` 起的本机服务：托管网页的静态文件，提供网页要的数据接口，只在本机能访问 · 对应代码：`src/server/` · 所属里程碑：[M1 底座](../roadmap.md#m1-底座)、[M2 博客](../roadmap.md#m2-博客)（导入接口） · 状态：已完成 · 最近更新：2026-10-09

## 职责与边界

- 管：路由、请求体校验、把用例的结果和错误翻成 HTTP、托管 `web/out`、只许本机访问、开发时允许网页开发服务器跨端口调用、起停服务。
- 不管：业务（全在 `UseCases` 里）。路由里只有「解析 → 调一个用例 → 返回」。
- 服务本身不存状态：关掉再开不丢任何东西。

## 结构与数据流

```
浏览器 ──► 127.0.0.1:3210
             ├─ /api/*   ──► guard（只许本机、跨端口只许开发地址）──► 校验请求体 ──► UseCases ──► JSON
             └─ 其余     ──► web/out 里的静态文件（/accounts/ → accounts/index.html；找不到 → 404.html）
```

| 文件 | 内容 |
|---|---|
| `app.ts` | `createServerApp(deps)`：组装 Hono 应用（测试直接用它的 `request()`，不起端口） |
| `guard.ts` | Host、Origin 检查和开发时的跨端口许可 |
| `errors.ts` | 错误转 HTTP |
| `schemas.ts` | 请求体的 zod 定义（和 `@leafpress/core` 的请求类型一一对应） |
| `routes/works.ts`、`ideas.ts`、`accounts.ts`、`data.ts`、`system.ts` | 各组路由 |
| `static.ts` | 托管静态网页 |
| `serve.ts` | `startServer(options)`：打开 AppContext、建 UseCases、监听端口 |

新依赖：`hono`、`@hono/node-server`（版本写死，登记进技术设计的选型表——表里已有这两项）。

### 接口

```ts
import type { UseCases } from "@leafpress/core";

export interface ServerDeps {
  usecases: UseCases;
  /** 本服务的端口：Host 检查和同源判断用 */
  port: number;
  /** 网页静态文件的目录；不传或目录不存在时，非 /api 的请求返回一页「网页还没构建」 */
  webRoot?: string;
  /** 开发模式：允许网页开发服务器（http://127.0.0.1:3211、http://localhost:3211）跨端口调用 */
  dev?: boolean;
  /** 出 500 时记一笔（不含请求体） */
  logError?: (message: string) => void;
}
export function createServerApp(deps: ServerDeps): Hono;

export interface StartServerOptions {
  home: string;
  port?: number;      // 缺省 3210；命令行把配置里的 server.port 传进来；传 0 时自动挑一个空闲端口（测试用）
  dev?: boolean;
  webRoot?: string;   // 缺省：仓库根目录下的 web/out（defaultWebRoot() 按本文件编译前后的位置往上找，全局安装后也对）
}
/** 「打开数据目录并建 UseCases」的工厂：本机服务不直接依赖用例层，命令行把真的实现（openApp + createUseCases）传进来 */
export interface UseCasesFactoryResult {
  usecases: UseCases;
  close(): void;
  logError(message: string): void;
}
export type CreateUseCases = (home: string) => UseCasesFactoryResult;
export interface RunningServer {
  url: string;        // http://127.0.0.1:<端口>/
  close(): Promise<void>;
}
/** 端口被占用时抛 USAGE「端口 <端口> 被占用：可能已经开着了，直接打开 http://127.0.0.1:<端口>/」 */
export function startServer(options: StartServerOptions, createUseCases: CreateUseCases): Promise<RunningServer>;
```

`startServer` 用工厂打开数据目录（命令行传入的工厂里，`warn` 和 `logError` 都追加写到 `<数据目录>/logs/server.log`，每行带时间），`@hono/node-server` 只监听 `127.0.0.1`。关闭时先停止接新连接，给在途请求 2 秒宽限，再强制断开剩下的连接（闲置的长连接、没发数据的连接），最后关掉用例工厂。

### 路由

GET 直接返回数据；改数据的返回 `{ ok: true, version, ...结果 }`（`version` 是改完以后的 `usecases.version()`）；出错返回 `{ ok: false, error: { code, message, hint? } }`。

| 方法和路径 | 用例 | 成功返回 |
|---|---|---|
| GET `/api/version` | `version()` | `Version` |
| GET `/api/bootstrap` | `bootstrap()` | `Bootstrap` |
| GET `/api/dataset` | `dataset()` | `MetricsDataset` |
| GET `/api/works/:id` | `showWork(id)` | `WorkDetail` |
| POST `/api/works` | `createWorks(body)` | `{ ok, version, works }` |
| PATCH `/api/works/:id` | `updateWork(id, body)` | `{ ok, version }` |
| POST `/api/works/:id/move` | `moveWork(id, body)` | `{ ok, version }` |
| POST `/api/works/:id/feedback` | `submitFeedback(id, body.text)` | `{ ok, version }` |
| DELETE `/api/works/:id` | `deleteWork(id)` | `{ ok, version }` |
| POST `/api/works/:id/open-folder` | `openWorkFolder(id)` | `{ ok, path }` |
| POST `/api/ideas` | `addIdeas([body])` | `{ ok, version, idea }` |
| PATCH `/api/ideas/:id` | `updateIdea(id, body)` | `{ ok, version }` |
| POST `/api/ideas/:id/move` | `moveIdea(id, body)` | `{ ok, version }` |
| DELETE `/api/ideas/:id` | `deleteIdea(id)` | `{ ok, version }` |
| POST `/api/accounts` | `addAccount(body)` | `{ ok, version, account }` |
| PATCH `/api/accounts/:id` | `updateAccount(id, body)` | `{ ok, version }` |
| PUT `/api/accounts/:id/profile` | `saveProfile(id, body.profile)` | `{ ok, version }` |
| PUT `/api/accounts/:id/settings/:key` | `setSetting(id, key, body.value)` | `{ ok, version }` |
| POST `/api/accounts/:id/import`（M2） | `importPosts(id)`，没有请求体 | `{ ok, version, summary }`（summary：新增、跳过、草稿、读不了的文章、新作品） |
| POST `/api/data/pull` | `pullData(body)` | `{ ok, version, outcomes, note }` |
| PUT `/api/notes/:week` | `saveNote(week, body)` | `{ ok, version }` |
| POST `/api/export` | `exportBackup()` | `{ ok, version, dir }` |

- 请求体用 zod 严格校验（多余字段报错）；不合法 → 400，code `USAGE`，message 列出「字段路径：问题」（多余字段写出字段名，例如「请求体：不认识的字段 accountid」），不回显值。
- 路径里的编号先过 `^[a-z0-9][a-z0-9-]*$`，不合法直接 404。
- 改数据的请求必须是 `Content-Type: application/json`（DELETE 和没有请求体的 POST 除外），否则 415。

### 错误转 HTTP

| 错误码 | HTTP |
|---|---|
| `USAGE` | 400 |
| `NOT_FOUND` | 404 |
| `STATE_CONFLICT`、`STEP_OUTPUT_INVALID` | 409 |
| 其余 `LeafPressError` | 500 |
| 不是 `LeafPressError` | 500，message「内部错误：<原 message>」，不带调用栈；`logError` 记一笔 |

### 只许本机访问（guard）

- `Host` 必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`，否则 403（防止别的网站用 DNS 重绑定调到本机服务）。
- 带 `Origin` 的请求：Origin 必须是本服务自己（`http://127.0.0.1:<端口>`、`http://localhost:<端口>`），开发模式下再加 `http://127.0.0.1:3211`、`http://localhost:3211`；否则 403。
- 开发模式下对这两个开发地址回 CORS 头（含 OPTIONS 预检，允许 GET、POST、PATCH、PUT、DELETE 和 Content-Type 头）；头在路由处理完之后写进最终响应，成功和出错的返回都带（网页开发时才看得到出错原因）；非开发模式不回任何 CORS 头。

### 托管静态网页

- `/` → `index.html`；`/xxx/` → `xxx/index.html`；`/xxx`（没有扩展名、不以 / 结尾）→ 先找 `xxx.html`，再找 `xxx/index.html`；有扩展名的按文件找，按扩展名给 Content-Type。
- 路径规范化后必须还在 `webRoot` 里面，否则 404。
- 找不到 → `404.html`，状态码 404。
- `_next/static/` 下的文件加长缓存头（`Cache-Control: public, max-age=31536000, immutable`），其余 `no-cache`。

## 关键决策

1. **网页和接口同一个端口**：网页用相对路径调接口，开发时才用环境变量指到 3210；以后开 Cloudflare Tunnel 只要映射一个端口。
2. **只听 127.0.0.1，还要查 Host 和 Origin**：本机服务能改数据、能打开文件夹，不能让浏览器里别的网站借道调用。
3. **GET 不包 ok 外壳，改数据的都带新的变更序号**：网页改完数据立刻知道新序号，不用等下一次轮询。
4. **路由里没有业务**：所有判断在用例里，命令行和网页的行为一定一致。

## 验证方式

单测在 `tests/server/`：

1. 每条路由：用假的 `UseCases`（只记录调用参数、返回固定值），断言调对了用例、参数对、返回形状对。
2. 错误转 HTTP 的五种情况；请求体多一个字段、少一个必填字段、类型不对都是 400 且 message 不含值；编号不合法 404；不是 JSON 415。
3. guard：Host 不对 403；Origin 是别的网站 403；开发模式下 3211 的预检和响应头；非开发模式没有 CORS 头。
4. 静态文件：用临时目录造 `index.html`、`accounts/index.html`、`_next/static/a.js`、`404.html`，断言上面每条规则；`/../secret` 之类拿不到 `webRoot` 外的文件；没有 webRoot 时回「网页还没构建」。
5. 集成：真实的 `startServer`（临时数据目录、端口取 0 或随机空闲端口）+ 真的 HTTP 请求：加账号 → 加灵感 → 转作品 → `GET /api/bootstrap` 里能看到 → `GET /api/version` 的 seq 变大；同一个端口再起一次报「端口被占用」。

`pnpm gate` 全部通过。
