# 共享规则 · 接入与数据统计

> 模块定位：账号接入状态、拉数据前的判断、从数据快照算账号概况 / 走势 / 排行 / 周报、提醒、Markdown 档案解析（纯函数） · 对应代码：`packages/core/src/`（setup、metrics、report、notices、markdown） · 所属里程碑：[M1 底座](../roadmap.md#m1-底座) · 状态：已完成 · 最近更新：2026-10-09
>
> 同层的另一份：[共享规则 · 类型与作品流转](共享规则-类型与作品流转.md)（类型、目录、日期、格式、作品流转都在那份）。规则来源：网页原型 `web/src/lib/setup.ts`、`metrics.ts`、`report.ts`、`board.ts`（提醒部分）、`markdown.ts`、`web/src/data/series.ts`，搬过来后改成「数据从参数传进来」。

## 职责与边界

- 管：接入状态和还缺什么；拉数据前哪些号跳过、哪些直接失败；把记录库里的原始快照整理成网页要的数据集；从数据集算账号概况、走势、排行、周报；提醒；账号档案的 Markdown 解析和一句话简介。
- 不管：真的去拉数据（平台适配的数据工具）、读写记录库（用例）。
- 只客观算数：不设目标、不分栏目、不给建议。

## 结构与数据流

```
记录库：account_days（账号每天）、work_snapshots（作品每天的累计数）
        │  用例读出最近 DATASET_DAYS 天（加上窗口前每个作品最后一条，当起点）
        ▼
metrics/build.ts  buildDataset ──► MetricsDataset（账号每天、作品每天新增）
        │  经 GET /api/dataset 给网页；命令行也能直接算
        ▼
metrics/summary.ts、series.ts、rank.ts、report/、notices/  ──► 页面上的数
```

- 统计函数的「今天」「数据到哪天」「本周一」都从数据集来：`today = ds.today`、`latestDay = ds.latestDay`。**看数据的「本周」是 `weekStartOf(ds.latestDay)`**（今天是周一时，数据只到上周日，「本周」就是上一周，区间不会反过来）；只有「本周发了几篇」用 `weekStartOf(ds.today)`（今天发的也算本周）。
- 统计函数都收一个 `MetricsInput`：

```ts
export interface MetricsInput {
  dataset: MetricsDataset
  accounts: Account[]
  works: Work[]
}
```

### setup：接入状态

```ts
/**
 * 账号的 settings 怎么来（用例调它，从记录库和凭证文件拼）：只认平台 setupItems 里定义了的键，顺序同定义。
 * 普通项：values 里有非空值 → ok 并带 value，否则 missing；密钥项：secrets 里有这个键 → ok（不带 value），否则 missing；
 * expired 里有这个键 → expired，reason 为它的值（盖过 ok）。
 */
export function settingViews(platform: PlatformInfo, input: { values: Record<string, string>; secrets: ReadonlySet<string>; expired: Record<string, string> }): SettingView[]

/** 定义和状态合起来，顺序同定义 */
export function setupItems(platform: PlatformInfo, settings: SettingView[]): SetupItemView[]

/**
 * 数据获取现在的情况：平台没有 dataTool → missing；最近一次拉取失败 → failed（failReason、fixHint 取拉取记录）；
 * 其余 → ok（拉过就带 lastPullAt）。mode、provider 取 dataTool；schedule 原样带上。
 */
export function dataSourceView(platform: PlatformInfo, pull: PullRecord | undefined, schedule?: string): DataSourceView

/** platform 由调用方传（用例从注入的平台目录取，测试可以换成带配置项的平台） */
export function setupView(account: Account, platform: PlatformInfo, input: { pull?: PullRecord; schedule?: string }): SetupView
```

`setupView` 的规则：

- `workflows` = `workflowsFor(平台)`；`usableWorkflows` = 其中 `isUsable` 的；`hasPlatformWorkflow` = 有没有 platform 不是 "any" 的。
- `gaps` 按这个顺序：没有专用工作流 →「还没有<平台名>专用的作品产出工作流」；专用工作流里用不了的 →「「<工作流名>」要先配：<没配好的配置项名，用、隔开>」；数据拉取失败 →「数据拉取失败：<原因>」；工具还没做 →「拿数据的工具还没做」；每个不是 ok 的配置项 →「<配置项名><未配置 | 已过期>」。
- `state`：数据拉取失败或有配置项过期 → broken；否则没有专用工作流、或专用工作流一个都用不了、或工具还没做、或有配置项没配 → unfinished；否则 ready。

### 拉数据前的判断

```ts
export type PullAction = { accountId: string; action: "skip" } | { accountId: string; action: "blocked"; reason: string } | { accountId: string; action: "pull" }
/** 平台没有 dataTool → skip；usedFor 为 data 的配置项有不是 ok 的 → blocked，reason「<配置项名>未配置」或「<配置项名>已过期」（取第一个）；其余 → pull */

export function pullNote(outcomes: PullOutcome[], accounts: Account[]): string
```

### metrics/build：整理数据集

```ts
export const DATASET_DAYS = 182
export function buildDataset(input: {
  today: DayKey
  accounts: Account[]
  works: Work[]
  accountDays: AccountDayRecord[]
  workSnapshots: WorkSnapshotRecord[]
}): MetricsDataset
```

- `latestDay = addDays(today, -1)`，窗口起点 `start = addDays(today, -DATASET_DAYS)`。
- **作品每天新增**（`workDays`）：按作品分组、按日期排好。主数据 = 平台第一个数据项；互动 = 平台标了 interaction 的数据项之和（缺的键当 0）。
  - 第 i 条（i ≥ 1）且日期在窗口内：新增 = 这条减上一条，小于 0 当 0；两项都是 0 的天不写。
  - 第 0 条：作品有 `publishedAt`、`publishedAt <= 这条的日期 <= publishedAt + 1 天`、并且在窗口内 → 新增就是它的累计数（从 0 开始算）；否则只当起点，不写（发布前的快照也只当起点）。
  - 找不到账号或平台的作品跳过。
- **账号每天**（`daily`）：窗口内（`start`..`latestDay`）有 account_days 记录的账号才有键。从窗口内第一条记录那天到 `latestDay`，一天一条：
  - `followers` = 那天的记录的 followers，没有记录为 null；
  - `reads` = 记录里的 reads 不是 null 就用它，否则 = 这个号所有作品那天的 `workDays.reads` 之和；`interactions` 同理；
  - `posts` = 这个号已完成、`publishedAt` 是那天的作品数。

### metrics：概况、排行、走势

全部照原型 `metrics.ts` 的算法，改成从 `MetricsInput` 取数据。逐个说明不同的地方：

```ts
export function followersOn(ds: MetricsDataset, accountId: string, day: DayKey): number | null
// 改：数据不保证每天都有粉丝数。取日期不晚于 min(day, latestDay)、followers 不是 null 的最后一个点；没有返回 null
/** 统计里一律用它：followersOn 有值就用；没有（那天还早于第一次拉到粉丝数）就用第一次拉到的粉丝数（当作那之前没变）；这个号从没拉到过粉丝数为 0 */
export function followersAt(ds: MetricsDataset, accountId: string, day: DayKey): number
export type FlowKey = "reads" | "interactions" | "posts"
export function sumFlow(ds: MetricsDataset, accountId: string, start: DayKey, end: DayKey, key: FlowKey): number
export function shortTitle(title: string): string
export function accountLabel(account: Account): string                 // 「一叶之桐（知乎）」
export function metricsOf(platform: PlatformId): MetricDef[]
export function metricText(work: Work, platform: PlatformId, key: string): string  // 没有 totals 或平台没有这一项 →「—」，否则 formatCount
export function reachAndInteractions(work: Work, platform: PlatformId): { reach: number; interactions: number }
/** 已发：已完成且有 publishedAt（不管有没有数据），可选按账号 */
export function publishedWorks(works: Work[], accountId?: string): Work[]
/** 能排行：已发且有 totals */
export function rankableWorks(works: Work[], accountId?: string): Work[]
export interface RankedWork { work: Work; account: Account; reach: number; interactions: number; growth: number; rate: number | null }
export function rankedWork(ds: MetricsDataset, work: Work, account: Account): RankedWork  // growth = workDays 里 latestDay 前 7 天（含）的 reads 之和；没有 totals 时 reach、interactions 为 0
export type RankBy = "reach" | "interactions" | "growth"
export function topWorks(input: MetricsInput, by: RankBy, limit?: number, accountId?: string): RankedWork[]  // 只排 rankableWorks；排序规则同原型
export interface AccountSummary { /* 字段同原型 AccountSummary */ }
export function accountSummary(input: MetricsInput, account: Account): AccountSummary
export type MetricId = "followers" | "reads" | "interactions" | "posts"
export type RangeId = "4w" | "12w"
export interface SeriesPoint { key: string; label: string; title: string; value: number; compare: number | null }
export interface MetricResult { metric: MetricId; value: number; change: number | null; points: SeriesPoint[] }
export function metricSeries(input: MetricsInput, scope: string, metric: MetricId, range: RangeId): MetricResult  // scope 为 "all" 或账号编号
```

和原型不同的规则：

0. **粉丝数一律用 `followersAt`**：概况的 7 天 / 30 天变化、每周增减、走势的粉丝线、周报的期初期末都用它。账号在窗口中途才第一次拉到粉丝数时，之前的变化算 0，不会把「没数据」当成 0 粉丝算出一大截增长。
1. `accountSummary` 的 `works`、`lastPublishedAt`、`daysSincePublish`、`postsThisWeek` 用 `publishedWorks`（没数据的号发了作品也算）；`hasData` = 数据集里这个号有点；粉丝相关的数在没有数据时为 0。
2. `metricSeries` 的 posts：直接按作品的 `publishedAt` 数（范围内所有账号，不管有没有数据）；followers、reads、interactions 从 `daily` 算。
3. `stale`：运营中（stage active）且 `daysSincePublish > 14`；从没发过的号不算断更。

### report：周报

```ts
/** 从 weekStartOf(addDays(today, -1)) 起往前 count 周，新的在前（今天是周一时，第一周是上一周） */

  week: DayKey
  end: DayKey
  complete: boolean
  rows: WeekRow[]

  published: RankedWork[]

```

算法和小结的句子照原型 `report.ts`。不同的地方：`posts` 和 `published` 用 `publishedWorks`（没数据的号也算）；断更那句里「粉丝」用平台的 `audienceLabel`；`note` 从传入的 notes 里按周找。

### notices：提醒

```ts
export type NoticeKind = "waiting" | "data" | "stale"
export type NoticeTone = "risk" | "progress"
export interface Notice { id: string; kind: NoticeKind; tone: NoticeTone; title: string; detail: string; href: string; at: IsoTime }
export function notices(input: { works: Work[]; accounts: Account[]; pulls: PullRecord[]; today: DayKey }): Notice[]
/** 网页里的链接：作品详情、账号详情 */
export function workHref(workId: string): string      // `/?open=<编号>`
export function accountHref(accountId: string): string // `/account/?id=<编号>`（编号做 URL 编码）
```

- data：账号最近一次拉取失败 → 标题「<账号名>数据拉取失败」，detail 为原因，href `/data/#sources`，at 为拉取时间，tone risk。
- stale：运营中的号、最近一次发布超过 14 天 → 标题「<账号名> <n> 天没更新」，detail「上次发布在<formatDay>」，href 账号详情，at 为最后发布的那个作品的 updatedAt，tone risk。
- waiting：等你处理的作品 → 标题是作品标题，detail「<平台名> · <waitingLabel>」（waitingLabel 要工作流，取 `workflowById`，找不到用「等你处理」），href 作品详情，at 为 updatedAt，tone progress。
- 排序：data、stale、waiting，同类按 at 新的在前。

## 关键决策

1. **数据集由服务端整理、统计在网页算**：记录库里只存「每天的累计数」，新增在整理时算；网页拿到最近半年的整理结果，切换时间段、切账号都在本地算，不用每次请求。半年的数据只有几百 KB，只在拉过数据后才重取。
2. **账号层面的数可以直接来自平台，也可以由作品加起来**：博客的 Umami 能给全站访问（含首页），知乎只能给单篇，两种都接得住。
3. **发了作品就算发布，不管有没有数据**：还没接数据的平台用通用工作流发出去的作品，也算进「本周发了几篇」和「几天没更新」。
4. **账号详情改成 `/account/?id=` 的地址**：网页是静态导出，事先不知道有哪些账号，没法给每个账号生成一个页面。
