# 网页 · 工作台

> 模块定位：原型升级来的网页工作台：页面和交互不变，数据全部从本机服务取，改动都调接口 · 对应代码：`web/` · 所属里程碑：[M1 底座](../roadmap.md#m1-底座)、[M2 博客](../roadmap.md#m2-博客)（导入文章、定时拉数据的状态）、[M3 知乎](../roadmap.md#m3-知乎) · 状态：已完成 · 最近更新：2026-10-09
>
> 视觉规范见 [前端设计](../前端设计.md)；逐区块规格见 `web/DESIGN.md`、`web/design/*.md`；原型阶段的记录见 [网页 · 原型](网页-原型.md)。接口见 [本机服务](本机服务-接口与托管.md)，规则见 [共享规则 · 类型与作品流转](共享规则-类型与作品流转.md)、[共享规则 · 接入与数据统计](共享规则-接入与数据统计.md)。

## 职责与边界

- 管：7 个页面的显示和交互；从本机服务取数据、每 2 秒问一次变更序号；改数据时调接口（拖动这类先在本地改界面，再等服务端确认）；连不上服务时的提示。
- 不管：业务规则（共享规则包）、存储（本机服务和记录库）。网页里不再有任何演示数据、不再写浏览器存储。

## 结构与数据流

```
页面挂载 ──► DataSync：GET /api/bootstrap、GET /api/dataset ──► useData（zustand，不持久化）
               │  每 2 秒 GET /api/version（页面在后台时停）
               ├─ seq 或 profilesStamp 变了 ──► 重取 bootstrap
               └─ snapshotSeq 变了 ──► 重取 dataset
组件 ──► 选择器（useWorks、useAccounts、useDataset……）+ 共享规则的纯函数（排序、进度、统计）
用户操作 ──► actions（先本地改界面）──► 接口 ──► 成功：用返回的 version 触发重取；失败：重取覆盖本地改动 + 提示条说原因
```

### 数据层（`src/state/`）

```ts
// api.ts：只有它碰 fetch
/** 开发时由环境变量指到本机服务（http://127.0.0.1:3210），正式用同源（空串） */
export const API_BASE: string
export class ApiError extends Error { code: string; hint?: string; status: number }
export function getJson<T>(path: string): Promise<T>
/** 改数据：JSON 请求体；失败时抛 ApiError（message、hint 取服务端的） */
export function send<T>(method: "POST" | "PATCH" | "PUT" | "DELETE", path: string, body?: unknown): Promise<T>

// data.ts：全部服务端数据放一个 store
interface DataState {
  status: "loading" | "ready" | "error"
  /** 连不上或出错时的说明；有旧数据时照样显示旧数据 */
  error?: { message: string; hint?: string }
  boot?: Bootstrap
  dataset?: MetricsDataset
  version?: Version
  load(): Promise<void>
  /** 按 version 判断重取哪些；传 force 时全取 */
  sync(next?: Version, force?: boolean): Promise<void>
  /** 本地先改（拖动、排序用），之后的重取会覆盖它 */
  patchBoot(fn: (boot: Bootstrap) => Bootstrap): void
}
export const useData: UseBoundStore<StoreApi<DataState>>
// 选择器（没加载完时返回空数组 / undefined）
export function useWorks(): Work[]
export function useIdeas(): Idea[]
export function useAccounts(): Account[]
export function useAccount(id: string | undefined): Account | undefined
export function usePulls(): PullRecord[]
export function useNotes(): WeeklyNote[]
export function useSchedules(): ScheduleView[]
export function usePaths(): DataPaths | undefined
/** 今天：取 bootstrap 的 today；没加载完时用本地日期 */
export function useToday(): DayKey
/** 统计用：dataset、accounts、works 三样都到了才有值 */
export function useMetricsInput(): MetricsInput | undefined
```

`actions/`（每组一个文件：works、ideas、accounts、data、system），每个动作：调接口 → 成功时用返回的 `version` 调 `sync` → 返回结果；失败时 `sync(undefined, true)` 拿回服务端的真实状态，再把 `ApiError` 往外抛给调用处显示提示条。拖动作品和灵感（换列、排先后）先用共享规则的 `moveWork` / `reorderTodo` / `moveIdea` / `reorderIdeas` 在本地 `patchBoot`，再调接口。

| 动作 | 接口 |
|---|---|
| `createWorks(input)` | POST `/api/works`，返回新作品 |
| `updateWork(id, patch)` | PATCH `/api/works/:id` |
| `moveWork(id, status, beforeId)` | POST `/api/works/:id/move` |
| `submitFeedback(id, text)` | POST `/api/works/:id/feedback` |
| `deleteWork(id)` | DELETE `/api/works/:id` |
| `openFolder(id)` | POST `/api/works/:id/open-folder` |
| `loadWorkDetail(id)` | GET `/api/works/:id`（复制给 AI、任务文件夹的文件列表用） |
| `addIdea`、`updateIdea`、`moveIdea`、`deleteIdea` | 灵感的四个接口 |
| `addAccount`、`updateAccount`、`saveProfile`、`setSetting` | 账号的四个接口 |
| `pullNow(accountIds?)` | POST `/api/data/pull`，返回 note |
| `importPosts(accountId)` | POST `/api/accounts/:id/import`，返回导入结果（新增、已有、草稿、读不了的篇数）（M2） |
| `saveNote(week, note)` | PUT `/api/notes/:week` |
| `exportBackup()` | POST `/api/export`，返回文件夹 |

**忙标记**（`state/busy.ts`，M2）：要跑很久的动作（拉数据、导入）在全局记一个「正在做」的标记，按钮读它显示加载并禁用。这样切到别的页面再回来按钮仍是忙的，不会点出第二个请求；四个拉数据按钮（数据页「现在拉一次」、数据来源「重试」、接入「现在拉一次」、工作流页「现在拉取」）共用一个标记，一个在拉时其余也忙。导入按账号各记一个。

**定时任务的显示规则**（`state/schedules.ts`，M2）：服务端不管装没装都给出「每天几点」，网页只在计划任务装上时显示它（数据页顶部、数据来源每个账号、接入里的「什么时候拉」）；没有拿数据工具的平台（知乎等）不显示。

`features/shell/data-sync.tsx`：挂在外壳里，挂载时 `load()`；每 2 秒问一次版本（`document.hidden` 时停，回到前台立刻问一次）；连续失败时 `status` 变 error。

### 页面要改的地方

总的原则：页面结构、区块、文案、令牌都照原规格（`web/design/*.md`），只换数据来源；下面是逐页的增删。

**外壳**
- 加载中：用已有的 `shell-skeleton.tsx`；连不上服务：在内容区顶部显示一条提示（「连不上本机服务」+ 一句怎么办：「在终端运行 leafpress serve」+「重试」按钮），有旧数据时照样显示旧数据。
- 头像菜单：去掉「恢复初始数据」；加「导出备份」（成功提示「已导出到 <文件夹>」）。「交给 AI」里的任务文件夹路径用 `paths.tasks` 的真实路径。
- 命令面板：去掉「让 AI 挑一个做」。
- 提醒：用共享规则的 `notices`。侧栏数字照旧从数据算。

**作品**
- 去掉「让 AI 做」「让 AI 继续」按钮、`running` 状态和「AI 在做」的转圈；进行中的卡片和详情显示「agent 在做」以及租约到期时间（`lease.expiresAt`，用相对时间）；有 `error` 时在详情里显示「出错了：<原因>」。

- 卡片和详情的数据格按平台数据项（博客只剩访问、访客）。

**灵感**
- 去掉「跑灵感」一块（定时跑灵感 M4 才做；`schedules` 里有 `idea-harvest` 时再显示，M1 永远不显示）。

**账号**
- 账号详情的链接一律用共享规则的 `accountHref(id)`。

### 开发方式

- `web/package.json` 的 `dev` 改成 `next dev -p 3211`；开发时另开一个终端跑 `leafpress serve --dev`（3210），网页用环境变量 `NEXT_PUBLIC_LEAFPRESS_API=http://127.0.0.1:3210` 调接口（写进 `web/.env.development`，进仓库，里面没有密钥）。

## 关键决策

1. **一个 store 放全部服务端数据，按变更序号整块重取**：本机数据量小，整块重取比逐条同步简单可靠；agent 在命令行改了状态，网页两秒内跟上。
2. **拖动先改界面再确认**：拖放要跟手；服务端拒绝时（比如作品刚被 agent 接手）重取覆盖并提示原因。
3. **统计在网页算**：dataset 一次拿半年，切时间段、切账号不用再请求。
4. **账号详情用查询参数**：静态导出没法为事先不知道的账号生成页面。
