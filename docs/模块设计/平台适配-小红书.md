# 平台适配 · 小红书

> 模块定位：把小红书接上：图文卡片工作流（AI 写卡片稿和文案 → 代码排版成卡片图 → 作者在手机上发 → 归档链接）、卡片出图、归档小红书链接；拿数据和账号配置等作者定 · 对应代码：`src/platforms/xiaohongshu/`、`packages/core/src/catalog/`（小红书的工作流） · 所属里程碑：[M5 小红书](../roadmap.md#m5-小红书) · 状态：进行中 · 最近更新：2026-10-18
>
> 依据：侦察（小红书数据的拿法、图文卡片规格和做法、笔记链接写法，见 [进度流水](../进度/2026-10-16.md)）。用户授权主控无人值守推进，**要作者拍板的三件事先不做**：
> - 拿数据的办法；
> - 卡片的视觉方向，先用一套素净的默认样式；第一轮样张只换了颜色，作者让重新设计，重新调研后提了三个版式不同的方向，等作者挑；
> - 账号要配什么，目前没有要配的。

## 职责与边界

- **管**：
  - 小红书图文卡片工作流的定义；
  - 卡片稿和文案的格式与检查；
  - 卡片出图：网页模板加本机 Edge 截图；
  - 发布稿预览页；
  - 归档小红书链接。
- **不管**：
  - 发布：作者在手机上发；
  - 拿数据：等作者定，侦察结论见下文「待作者定」；
  - 视频笔记。

## 卡片规格（侦察结论）

| 项 | 取值 |
|---|---|
| 尺寸 | 3:4 竖图，1080×1440，一篇统一 |
| 张数 | 封面 1 + 要点 4～8 + 总结 1；硬上限 18 |
| 安全区 | 四边留 96 像素不放字 |
| 标题 | 20 字以内 |
| 正文 | 1000 字以内；外链点不了，也可能被判违规，**不放链接** |
| 话题标签 | 3～8 个，写在正文末尾，`#话题` 用空格分开 |

## 工作流（共享规则包 `catalog/`）

`xhs-cards`「图文卡片」，平台 `xiaohongshu`，`from: "any"`，`requires: []`：

| # | 编号 | 步骤 | 谁做 | 产出 | 要点 |
|---|---|---|---|---|---|
| 1 | `draft` | 写卡片稿和文案 | AI | `卡片.md`、`文案.md` | 先整份读账号档案、要求和来源（转来的作品读原稿）；格式照下文 |
| 2 | `render` | 排版卡片 | 代码 | `卡片/01.png…`、`小红书发布稿.html` | 先检查两份稿子，不合格就失败并逐条说原因；再出图和预览页 |
| 3 | `publish` | 你在手机上发 | 你 | — | ask 见下文 |
| 4 | `archive` | 归档链接 | 代码 | — | 认小红书链接，短链跳转一次换编号 |

**draft 的 instructions**（照写进目录）：「先整份读账号档案、要求和来源（转来的作品先读原稿）。把内容写成小红书图文卡片稿，存到 {folder}/卡片.md：封面一张、要点 4～8 张、总结一张，格式照下面的样子；再写笔记文案存到 {folder}/文案.md：第一行 `# 标题`（20 字以内），正文 1000 字以内，不放链接，最后一行 3～8 个话题标签（`#话题` 用空格分开）。」加上卡片稿的格式样例。

**publish 的 ask**：「卡片图在 {folder}/卡片/，文案在 {folder}/文案.md；也可以在网页上点「打开发布稿」看图、复制文案。把图传到手机，在小红书发图文笔记，发完把分享链接（整段分享文字也行）贴在下面；要改就写要改哪里。」

### 卡片稿 `卡片.md` 的格式

```markdown
# 封面这一句：勾人的一句话（18 字以内）
副标题一行（可选，24 字以内）

---

## 要点标题（16 字以内）
- 一条一行，每页最多 5 条
- 每页正文合计 120 字以内

---

## 总结：标题
- 同要点页
```

- 页与页之间用单独一行 `---` 分开。
- 第一页必须是封面，以 `# ` 开头。
- 最后一页的标题以「总结」开头。
- 其余是要点页，以 `## ` 开头。
- 页数 3～18。

## 卡片出图（`src/platforms/xiaohongshu/cards/`）

接口由主控定，代码在 `cards/types.ts`：
- `parseCardDeck(text)`：解析并检查卡片稿，返回卡片组或逐条错误；
- `renderCardHtml(deck, index, theme)`：生成一页卡片的完整 HTML；
- `CardRenderer.render(deck, outDir)`：把整组卡片截成 `01.png`、`02.png`……，返回文件名和用时。

- **出图**：
  - 本机 Edge 无头模式，经调试协议操作；
  - `--headless=new`、独立的临时用户目录，不碰作者正在用的 Edge；
  - 设备仿真设成 1080×1440、缩放 1；
  - 等字体加载完（`document.fonts.ready`）再截。
- **一次出图只起一个 Edge**，所有卡片截完就关掉，确认没有残留进程。超时 60 秒，期间调 `heartbeat`。
- **Edge 的位置**：按常见安装路径找，找不到就失败：「找不到 Edge：卡片出图要用本机的 Edge 浏览器」。
- **默认样式**（占位，等作者挑视觉方向后替换）：
  - 白底 `#FFFFFF`，正文 `#1A1A1A`，强调色 `#FF2442`；
  - 字体用系统的「Microsoft YaHei」，不加载网络字体；
  - 字号：封面标题 80px、要点标题 60px、正文 40px，行高 1.6；页码 28px，右下角。
  - 样式集中在一个主题对象里，换方向只改它。
- **实测要求**：实现时量冷启动、每张、9 张总用时，写进本文档「当前实现」。

## 两个代码步骤（`src/platforms/xiaohongshu/steps/`）

**排版卡片 `render`**：
1. 读 `卡片.md`、`文案.md`，按上面的规则检查。不合格时 `{ kind: "fail", error }`，把每一条问题列出来，AI 改完重跑：
   - 页数、各处字数、标签个数；
   - 文案里不能有 `http`。
2. 用 `CardRenderer` 出图到 `{folder}/卡片/`，先清掉旧图。
3. 生成 `小红书发布稿.html`：图片内嵌成 data URL，按顺序竖排；下面是文案；有「复制文案」按钮，`text/plain` 写剪贴板，带 `execCommand` 降级。
4. 结果 `{ kind: "done", note: "出了 N 张卡片" }`。

**归档链接 `archive`**：从当前反馈或最近一条历史反馈里找链接：
- 长链：`xiaohongshu.com/explore/<编号>`、`/discovery/item/<编号>`，有没有 `www` 都认。编号是 24 位十六进制，后面必须是结尾、`/`、`?`、`#`。
- 短链：`xhslink.com/...`，用 `ctx.fetch(短链, { redirect: "manual" })` 跳转一次，从 `location` 里取编号；取不到就 ask：「短链没认出来，在浏览器里打开笔记，把地址栏的链接贴在下面」。
- 分享文字整段贴进来时，从里面取出链接；链接后面的全角逗号不算链接。
- 结果：`{ kind: "done", url: "https://www.xiaohongshu.com/explore/<编号>", publishedAt: today, sourceRef: "xiaohongshu/note/<编号>" }`。`xsec_token` 等参数不存。

## 网页

等你处理的面板里，「打开复制页」推广成「打开发布稿」：任务文件夹里有以 `发布稿.html` 结尾的文件（知乎、小红书）时显示，新标签打开。

## 待作者定

1. **拿数据**：官方没有给个人作者的接口。可选：
   - a. 作者在创作服务平台手动导出表格，LeafPress 导入；
   - b. 用本机 Edge 复用作者的登录状态读创作中心数据。登录状态约 6 天失效，用户协议禁止未经许可读取统计平台数据，有封号风险；
   - c. 先不拉。
2. **卡片的视觉方向**：
   - 第一轮（2026-10-16）出了默认、纸感、醒目、深色技术四套样张（[样张目录](../前端设计/示意图/小红书卡片/)），四套版式完全一样、只换了颜色；封面标题挤在上方三分之一、下半张空着，要点页条数少时下面空一大块。作者让重新设计。
   - 第二轮（2026-10-18）先调研再设计，结论和来源见 [小红书卡片版式参考](../调研/小红书卡片版式参考.md)。提出三个版式不同的方向：**大字报**、**杂志编辑**、**终端**；另有五条不管选哪个都要改的（标题放大移到视觉中心、内页按内容多少调字号、固定页眉页脚、卡片稿能标强调词、换思源字体）。等作者砍掉不要的，再出方向图挑定。
3. **账号配置**：目前没有要配的，定了拿数据的办法再补。

## 关键决策

1. **卡片稿用 Markdown，出图交给代码**：AI 只管写内容，版式、尺寸、安全区由模板保证，每张都一样规整，换样式也只改模板。
2. **不设「确认要点」这一步**：卡片稿短，作者在「你在手机上发」那一步看预览，要改就写在反馈里，退回重写。和知乎不同，知乎长文先确认大纲。
3. **短链跳转一次换编号**：不跳就不知道是哪篇；只取跳转地址，不读页面内容。

## 当前实现

图文卡片工作流、卡片出图、发布稿预览、归档都已实现；拿数据、视觉方向、账号配置等作者定。

| 文件 | 内容 |
|---|---|
| `cards/types.ts` | 共用接口（主控定）：卡片组、样式、出图器 |
| `cards/parse.ts` | 解析和检查卡片稿 |
| `cards/html.ts` | 一页卡片的 HTML：三种页的版式、安全区、页码、文字转义、超长单词换行 |
| `cards/edge.ts`、`edge-locate.ts`、`edge-process.ts`、`cdp.ts` | 本机 Edge 出图：找 Edge、起停和清理进程树、调试协议连接（每个请求 15 秒超时）、设备仿真定尺寸截图 |
| `steps/copy.ts` | 解析和检查文案 |
| `steps/render.ts`、`preview.ts` | 排版步骤、发布稿预览页（复制用的原文存成 JSON，尖括号和换行原样进剪贴板） |
| `steps/archive.ts` | 归档：长链、短链跳转、分享整段文字；主机名和编号都有边界 |
| `steps/index.ts` | `createXhsHandlers({ renderer })`，登记表用本机 Edge 出图器 |

**实测出图用时**（真起 Edge）：
- 3 张：冷启动约 1.9 秒，每张约 0.9 秒，共 5.3 秒；
- 9 张：冷启动约 1.9 秒，每张约 0.8 秒，共 9.6 秒。

**一轮独立评审**（换 GPT 家评 GLM 写的）挑出 12 条，都已修：
- 出图读了 Edge 不提供的尺寸字段，出图失败；
- Edge 进程树清理不检查结果；
- 调试协议请求没有超时；
- 等页面就绪等不到时照样截图；
- 超长英文单词被截掉；
- 发布稿文件名只认后缀，有执行任意网页的风险，改成只认两个固定名字；
- 归档链接的主机名和编号没有边界；
- 预览页复制文案丢换行；
- 标签行、标题标记、空要点页检查不严。

主控另外改了一处：复制原文在 script 块里被写成了 `&lt;`，复制出来会是字面的 `&lt;`，改成 JSON 的 `<`。

**真起 Edge 的测试**（`*.edge.test.ts`）单独用 `vitest.edge.config.ts` 顺序跑，`pnpm gate` 里排在其余测试之后：和几百个测试并行跑时，会把要开数据库的测试拖到超时。

## 验证方式

单测在 `tests/platforms/xiaohongshu/`：

1. **卡片稿解析**：格式正确、页数不对、各处超字数、缺封面、缺总结、标签个数、文案里有链接。
2. **卡片 HTML**：三种页的结构、安全区、页码、长文本不溢出（超长时检查已经拦下）。
3. **出图**（`tests/platforms/xiaohongshu/render.edge.test.ts`，只在 Windows 上）：真起 Edge 出 3 张和 9 张，尺寸 1080×1440，跑完没有残留进程（只认这次的临时根目录）。
4. **排版步骤**：检查失败时的错误列表、出图后的文件、预览页里有图和文案、重复执行先清旧图。用假的出图器。
5. **归档**：长链各种写法、带查询串、分享整段文字、短链跳转成功和失败（假 fetch）、编号后面跟字母不算。
6. **端到端**（`tests/integration/m5-xiaohongshu.edge.test.ts`）：临时数据目录里用真实用例层和登记表，小红书作品写稿、真起 Edge 排版、不合格稿子报错、贴分享文字和短链归档、读发布稿。

`pnpm gate` 全过。不碰作者的真实数据和账号。
