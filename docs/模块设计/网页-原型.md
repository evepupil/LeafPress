# 网页 · 原型

> 模块定位：自媒体工作台的可点击网页原型，用来体验、提意见、排实现优先级 · 对应代码：`web/` · 所属里程碑：[原型阶段，排期待定（见 roadmap 当前进度）](../roadmap.md#leafpress-roadmap) · 状态：已完成（第二版「作品即任务」+ 账号改成档案和接入，等用户体验） · 最近更新：2026-10-08
>
> 视觉规范见 [前端设计](../前端设计.md)；逐区块规格见 `web/DESIGN.md`、`web/design/*.md`。

## 职责与边界

- 管：7 个页面的界面和交互（作品、灵感、账号、账号详情、工作流、数据、周报），演示数据，作品和灵感的增删改、拖动、转作品，作品按工作流往前走的规则，账号档案和接入配置，以及从数据快照算出来的统计（账号概况、走势、排行、周报）。
- 不管：真实数据的读写、平台接口、真正调用 AI。页面上的「让 AI 做」按真实规则一步步走，但每一步只是改状态；「现在拉一次」按接入里的配置判断拉不拉得到，不真的去拉。
- 和命令行的关系：原型和 `src/` 完全隔开，有自己的依赖和门禁；LeafPress 根目录的 `pnpm gate` 不检查 `web/`。以后命令行和 MCP 读写的作品、灵感、任务文件夹、账号档案，规则照这里的 `work-engine`、`setup` 来。

## 结构与数据流

```
 ① web/src/data/     演示数据：4 个账号（档案、接入配置、数据获取）、4 个平台各自的数据项、64 个作品、17 条灵感、
        │            6 个发布工作流、3 个定时工作流、14 个工具；演示时刻固定为 2026-10-08 09:30
        ▼
 ② web/src/lib/      work-engine 作品怎么往前走 · board 看板排序筛选和提醒 · metrics 数据快照统计 · report 周报
        │            · setup 接入状态和拉一次数据 · markdown 档案解析
        ▼
 ③ web/src/state/    zustand：作品、灵感、账号上改过的东西（都存 localStorage）、定时运行、界面开关、跨数据的动作
        ▼
 ④ web/src/features/ 外壳 + 各页区块；web/src/components/ 共享组件（拖动、转作品弹窗、Markdown 排版、状态图形……）
```

1. **数据**：作品就是任务，一个作品只对应一个账号（一个平台）。作品有状态（待实现、进行中、等你处理、已完成）、所用工作流、走到第几步、要你做的事、你的反馈、来源（灵感、另一个作品、博客导入、直接新建）。每个作品有一个任务文件夹 `~/.leafpress/tasks/<编号>/`。
2. **各平台的数据项不一样**：知乎是浏览、点赞、收藏、评论、分享；博客是访问、访客（Umami）和评论（giscus）；B站是播放、点赞、投币、收藏、分享、弹幕、评论；小红书是浏览、点赞、收藏、评论、分享。第一项是主数据，合计「浏览」时用它；标了互动的加起来是「互动」。作品的数据按平台自己的数据项显示。
3. **账号**：一份随便写的 Markdown 档案（定位、写给谁、文风、禁用词、对标、目标、调整记录都写在里面，以后放在 `~/.leafpress/accounts/<编号>.md`）；一块「接入」：作品产出的工作流、数据获取的工具、这个号要配的东西。
4. **规则**（全是纯函数）：
   - 让 AI 做：待实现 → 进行中，一步一步走；走到「你来」的步骤停下，作品改成等你处理，把那一步写好的话（文件夹路径填进去）放进「要你做的事」。
   - 提交反馈：回到待实现最前面；AI 接手时把你那一步记为完成，接着往下；走完最后一步时，能自动发布的直接拿到链接，要你投递的从反馈里取链接归档。
   - 转作品：选几个账号生成几个作品，工作流按「平台 + 来源」自动配（博客 → 博客写稿；知乎且来源是博客作品 → 博客转知乎；知乎其余 → 知乎写作；小红书 → 转小红书卡片；B站 → 录屏成片）。
   - 复制给 AI：一段任务说明（平台、状态、工作流、任务文件夹、来源、要求、步骤勾选、要你做的事、你的反馈），最后附整份账号档案。
   - 接入状态：有问题（数据拉取失败、密钥过期）> 没接完（没有能用的工作流、拿数据的工具还没做、有配置没填）> 接好了。拉一次数据：拿数据的工具还没做的号跳过；拉数据要的配置都配好才拉得到。
5. **存储**：作品、灵感、账号上改过的东西（档案、配置、拉取结果）存在浏览器 localStorage（键 `leafpress:works`、`leafpress:ideas`、`leafpress:accounts`），页面挂载后再读，首屏和静态页面一致；头像菜单「恢复初始数据」全部清掉。
6. **两份数据分开**：粉丝、浏览、排行、周报读数据快照（`src/data` 生成的每日数据，相当于每天定时拉回来的），不跟着页面上的改动变；拿数据的工具还没做的号（B站、小红书）没有任何数据。看板、详情、侧栏数字、提醒、接入状态读页面上的状态。

## 关键决策

1. **先做原型再定需求**：用户不想先写需求，要一个能直接体验的界面，再按它排实现顺序。
2. **外观照搬 DeverDesk**：同一套技术栈和令牌，外壳、组件直接复制。
3. **作品即任务，作品和平台一比一**（用户定）：灵感一转多，落下来的作品始终一个平台一份，进度和数据各算各的，算账清楚；已发的博客文章也是作品。
4. **要人动手的地方做成通用面板**（用户定）：不管哪个工作流哪一步，页面上都是「要你做的事 + 反馈框」，内容来自工作流步骤的说明；页面不为某个平台写专门的按钮。
5. **反馈后回到待实现最前面**：agent 只读「待实现」就能接上要继续的作品，不用另外查进行中。
6. **任务文件夹是交接点**：中间产物、要你做的事、你的反馈、记录都在 `~/.leafpress/tasks/<编号>/`，任何能读文件的 agent 都能接手；页面的「复制给 AI」给的是同一份说明。
7. **账号档案是一份自由写的 Markdown**（用户定）：对标、栏目、调整记录这类预设的结构用不上，写在一份文档里还能写别的；agent 整份读就了解这个号。
8. **不设目标、不分栏目、不给建议**（用户定）：栏目分不清、作品也没绑定栏目；页面只显示客观数据，要分析让 AI 用工具拉数据自己分析。
9. **没有手填，按平台一个一个接**（用户定）：要手填还不如自己去平台上看；每个平台接的时候做两件事——作品产出的工作流、数据获取的工具（没有官方接口也自己做），这个平台的账号要配什么也在那时定。「加账号」暂时保留原样，到时候一口气补齐。
10. **数据和规则写成代码并配单测**：几路并行实现时数字不会对不上；页面规格里的期望值都从单测来。
11. **演示时刻固定**：截图和交互检查每次结果一样；页面上的新动作从演示时刻往后每次推一分钟。

## 当前实现

- 作品（首页）：四列看板（拖动换列、待实现里拖动排先后、已完成先显示 20 个）、列表视图、平台筛选和搜索、卡片菜单；已完成卡片写平台自己的两项数据；详情抽屉可改标题、要求、工作流、链接，带等你处理面板、你的反馈、按平台数据项摆的数据格、步骤、任务文件夹、转出去的作品、记录；视图栏「让 AI 挑一个做」「新建作品」。
- 灵感：速记、跑灵感（定时工作流状态、现在跑一次）、三列看板（收件箱、值得写、已转作品；可拖、可点开编辑、可转作品）。
- 账号：卡片（档案第一段做简介、接入状态、粉丝和近 7 天浏览、本周发了几篇、手上的活）、接入情况表（四个号的作品产出、数据获取、能拿到什么、还缺什么横着比）、加账号（暂时保留原样）。
- 账号详情：账号头（只放客观的数）、档案（Markdown，可编辑）、走势、接入（作品产出、数据获取和「现在拉一次」、要配的东西可填写）、作品列表。
- 工作流：6 个发布工作流（每一步谁来做）、定时工作流、自动配规则、14 个工具。
- 数据：走势、分账号（数据还没接的号写明）、作品排行（看全部时列主数据和互动，只看一个号时按这个平台的数据项摆）、数据来源（没有手填，失败可重试）。
- 周报：客观小结、分账号、这周发的、我的复盘、往期；没有目标和建议。
- 外壳：侧栏数字跟着页面变（数据异常跟着拉取结果变）；搜索；提醒；头像菜单（交给 AI、快捷键、恢复初始数据、打开博客）；快捷键 N 记灵感、C 新建作品。
- 验收：网页单测 113 条；交互检查 88 项全部通过（含改档案后卡片简介跟着变、填好 Umami 密钥后重新拉成功、博客变成接好了、提醒里的拉取失败消失），10 个页面运行时错误和告警为 0；桌面 1440 与手机 375 截图无横向溢出。

已知限制：

- 「让 AI 做」只是按规则改状态，不会真的调用 AI，也不会真的生成任务文件夹里的文件。
- 「现在拉一次」只按配置判断拉不拉得到，不会真的去拉，数据快照里的数字不会变。
- 手机上浏览器不支持拖动，挪列、排到最前靠卡片菜单。
- 从详情里的作品小标签、搜索结果跳到另一个作品时，作品页的看板 / 列表和平台筛选会回到默认。

## 待扩展项

- 按平台一个一个接（重排 roadmap 时定顺序）：每个平台做作品产出工作流、数据获取工具，定下这个平台账号要配的东西，再补齐「加账号」。
- 命令行和 MCP：`leafpress works`（列待实现）、`leafpress work show/next/continue`，读写同一份作品、任务文件夹和账号档案，规则复用 `work-engine`。
- 接真数据：`web/src/data/*` 换成读记录库或在线版接口；`DEMO_NOW` 换成当前时间；「拉作品数据」「跑灵感」接真的定时任务。
- 在线版：照 DeverDesk 部署到 Cloudflare（D1 存数据、定时任务拉数据和出周报），并提供 MCP。
- 暗色主题。
