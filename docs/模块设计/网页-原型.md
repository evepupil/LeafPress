# 网页 · 原型

> 模块定位：自媒体工作台的可点击网页原型，用来体验、提意见、排实现优先级 · 对应代码：`web/` · 所属里程碑：[原型阶段，排期待定（见 roadmap 当前进度）](../roadmap.md#leafpress-roadmap) · 状态：已完成（第二版「作品即任务」，等用户体验） · 最近更新：2026-10-08
>
> 视觉规范见 [前端设计](../前端设计.md)；逐区块规格见 `web/DESIGN.md`、`web/design/*.md`。

## 职责与边界

- 管：7 个页面的界面和交互（作品、灵感、账号、账号详情、工作流、数据、周报），演示数据，作品和灵感的增删改、拖动、转作品，作品按工作流往前走的规则，以及从数据快照算出来的统计（账号概况、走势、栏目、排行、周报）。
- 不管：真实数据的读写、平台接口、真正调用 AI。页面上的「让 AI 做」按真实规则一步步走，但每一步只是改状态；「现在拉一次」这类按钮用提示条给出合理结果。
- 和命令行的关系：原型和 `src/` 完全隔开，有自己的依赖和门禁；LeafPress 根目录的 `pnpm gate` 不检查 `web/`。以后命令行和 MCP 读写的作品、灵感、任务文件夹，规则照这里的 `work-engine` 来。

## 结构与数据流

```
 ① web/src/data/     演示数据：4 个账号、64 个作品、17 条灵感、6 个发布工作流、3 个定时工作流、12 个工具
        │            演示时刻固定为 2026-10-08 09:30
        ▼
 ② web/src/lib/      work-engine 作品怎么往前走 · board 看板排序筛选和提醒 · metrics 数据快照统计 · report 周报
        ▼
 ③ web/src/state/    zustand：作品、灵感（存 localStorage）、定时运行、界面开关、跨数据的动作（转作品、恢复）
        ▼
 ④ web/src/features/ 外壳 + 各页区块；web/src/components/ 共享组件（拖动、转作品弹窗、状态图形……）
```

1. **数据**：作品就是任务，一个作品只对应一个账号（一个平台）。作品有状态（待实现、进行中、等你处理、已完成）、所用工作流、走到第几步、要你做的事、你的反馈、来源（灵感、另一个作品、博客导入、直接新建）。每个作品有一个任务文件夹 `~/.leafpress/tasks/<编号>/`。
2. **规则**（`work-engine.ts`，全是纯函数）：
   - 让 AI 做：待实现 → 进行中，一步一步走；走到「你来」的步骤停下，作品改成等你处理，把那一步写好的话（文件夹路径填进去）放进「要你做的事」。
   - 提交反馈：回到待实现最前面；AI 接手时把你那一步记为完成，接着往下；走完最后一步时，能自动发布的直接拿到链接，要你投递的从反馈里取链接归档。
   - 转作品：选几个账号生成几个作品，工作流按「平台 + 来源」自动配（博客 → 博客写稿；知乎且来源是博客作品 → 博客转知乎；知乎其余 → 知乎写作；小红书 → 转小红书卡片；B站 → 录屏成片）。
   - 复制给 AI：生成一段任务说明（平台、状态、工作流、任务文件夹、来源、要求、步骤勾选、要你做的事、你的反馈）。
3. **存储**：作品和灵感存在浏览器 localStorage（键 `leafpress:works`、`leafpress:ideas`），页面挂载后再读，首屏和静态页面一致；头像菜单「恢复初始数据」清掉。
4. **两份数据分开**：粉丝、阅读、排行、周报读数据快照（`src/data` 生成的每日数据，相当于每天定时拉回来的），不跟着页面上的改动变；看板、详情、侧栏数字、提醒读页面上的作品和灵感。

## 关键决策

1. **先做原型再定需求**：用户不想先写需求，要一个能直接体验的界面，再按它排实现顺序。
2. **外观照搬 DeverDesk**：同一套技术栈和令牌，外壳、组件直接复制。
3. **作品即任务，作品和平台一比一**（第二版，用户定）：灵感一转多，落下来的作品始终一个平台一份，进度和数据各算各的，算账清楚；已发的博客文章也是作品。
4. **要人动手的地方做成通用面板**（第二版，用户定）：不管哪个工作流哪一步，页面上都是「要你做的事 + 反馈框」，内容来自工作流步骤的说明；页面不为某个平台写专门的按钮。
5. **反馈后回到待实现最前面**：agent 只读「待实现」就能接上要继续的作品，不用另外查进行中。
6. **任务文件夹是交接点**：中间产物、要你做的事、你的反馈、记录都在 `~/.leafpress/tasks/<编号>/`，任何能读文件的 agent 都能接手；页面的「复制给 AI」给的是同一份说明。
7. **数据和规则写成代码并配单测**：几路并行实现时数字不会对不上；页面规格里的期望值都从单测来。
8. **演示时刻固定**：截图和交互检查每次结果一样；页面上的新动作从演示时刻往后每次推一分钟。

## 当前实现

- 作品（首页）：四列看板（拖动换列、待实现里拖动排先后、已完成先显示 20 个）、列表视图、平台筛选和搜索、卡片菜单；详情抽屉可改标题、要求、栏目、工作流、链接，带等你处理面板、你的反馈、数据、步骤、任务文件夹、转出去的作品、记录；视图栏「让 AI 挑一个做」「新建作品」。
- 灵感：速记、跑灵感（定时工作流状态、现在跑一次）、三列看板（收件箱、值得写、已转作品；可拖、可点开编辑、可转作品）。
- 账号、账号详情：按新模型改；账号卡片加「手上的活」（待实现 · 进行中 · 等你处理，点了去作品页只看这个平台）；账号详情的作品列表读页面上的作品，等你处理的排最前。
- 工作流：6 个发布工作流（每一步谁来做）、定时工作流、自动配规则、工具。
- 数据、周报：按作品排行；数据来源加定时拉取的运行记录。
- 外壳：侧栏数字跟着页面变；搜索（操作、作品、灵感、页面、账号、工作流）；提醒；头像菜单（交给 AI、快捷键、恢复初始数据、打开博客）；快捷键 N 记灵感、C 新建作品。
- 验收：网页单测 107 条；交互检查 83 项全部通过，10 个页面运行时错误和告警为 0；桌面 1440 与手机 375 截图无横向溢出。

已知限制：

- 「让 AI 做」只是按规则改状态，不会真的调用 AI，也不会真的生成任务文件夹里的文件。
- 手机上浏览器不支持拖动，挪列、排到最前靠卡片菜单。
- 从详情里的作品小标签、搜索结果跳到另一个作品时，作品页的看板 / 列表和平台筛选会回到默认。

## 待扩展项

- 命令行和 MCP：`leafpress works`（列待实现）、`leafpress work show/next/continue`，读写同一份作品和任务文件夹，规则复用 `work-engine`。
- 接真数据：`web/src/data/*` 换成读记录库或在线版接口；`DEMO_NOW` 换成当前时间；「拉作品数据」「跑灵感」接真的定时任务。
- 在线版：照 DeverDesk 部署到 Cloudflare（D1 存数据、定时任务拉知乎数据和出周报），并提供 MCP。
- 暗色主题。
