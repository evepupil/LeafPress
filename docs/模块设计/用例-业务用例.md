# 用例 · 业务用例

> 模块定位：一件业务一个用例：转作品、接手、做完一步、执行代码步骤、反馈、拖动、灵感、账号、拉数据、周报、导出。命令行和本机服务都只通过它办事 · 对应代码：`src/usecases/` · 所属里程碑：[M1 底座](../roadmap.md#m1-底座) · 状态：已完成 · 最近更新：2026-10-09

## 职责与边界

- 管：把共享规则、记录库、数据目录、凭证、平台适配组合成一件件业务；事务；租约令牌的比对和续期；改完记录库后更新任务文件夹；把规则的失败翻成统一错误。
- 不管：状态怎么变（共享规则）、怎么存（记录库）、命令行和接口的参数解析与输出（入口层）。
- 对外只暴露 `UseCases` 门面（接口已由主控写在 `packages/core/src/api/usecases.ts`，照它实现，不得改）。

### AppContext（`context.ts`，照抄）

```ts
import type { PlatformId, PlatformInfo } from "@leafpress/core";
import type { CredentialStore } from "../config/credentials.js";
import type { HomePaths } from "../config/home.js";
import type { LeafPressConfig } from "../config/schema.js";
import type { PlatformRuntime } from "../platforms/types.js";
import type { ExecFn } from "../shared/exec.js";
import type { Store } from "../store/types.js";

export interface AppContext {
  store: Store;
  paths: HomePaths;
  config: LeafPressConfig;
  credentials: CredentialStore;
  platforms: PlatformRuntime;
  /** 平台目录：缺省是共享包的 PLATFORMS；测试可以换成带配置项的平台。用例里要平台信息一律从这里取 */
  catalog: Record<PlatformId, PlatformInfo>;
  exec: ExecFn;
  fetch: typeof fetch;
  /** 现在（测试注入） */
  now(): Date;
  /** 新的租约令牌（测试注入）；缺省 8 位小写字母和数字 */
  newToken(): string;
  /** 不影响结果的问题（比如任务文件夹写失败），命令行写到标准错误，本机服务写日志 */
  warn(message: string): void;
}

export interface OpenAppOptions {
  home: string;
  now?: () => Date;
  newToken?: () => string;
  exec?: ExecFn;
  fetch?: typeof fetch;
  platforms?: PlatformRuntime;
  catalog?: Record<PlatformId, PlatformInfo>;
  warn?: (message: string) => void;
}

/** 建数据目录（不存在时）、读配置、打开记录库（会自动升级）、打开凭证文件、建平台适配 */
export function openApp(options: OpenAppOptions): AppContext;
export function closeApp(app: AppContext): void;
```

### 公共规则

- **时间**：`at = toIsoTime(app.now())`、`today = dayOfDate(app.now())`，一个用例里只取一次。
- **账号拼装**：`Account` = 记录库的行 + `readProfile` + `settingViews(平台, { values: settings.values, secrets: credentials.keys, expired: settings.expired })` + `profilePath`。
- **错误**：在 `src/shared/errors.ts` 的错误码里加 `NOT_FOUND`、`STATE_CONFLICT`；删掉代码里已经没人用的旧错误码。规则返回的 `STATE_CONFLICT` → `LeafPressError("STATE_CONFLICT")`，`INVALID` → `LeafPressError("USAGE")`，message 用规则给的 reason。找不到 →「没有这个作品：<编号>」「没有这个账号：<编号>」「没有这条灵感：<编号>」。
- **事务**：所有「读 → 按规则算 → 写」都在一个 `store.transaction` 里，读也在事务里读（防止命令行和本机服务同时改同一个作品时丢更新）。
- **任务文件夹**：改了作品的用例在事务提交**之后**，对每个改过的作品调 `syncTaskFolder(app, id)`：在 `withTaskLock` 里重新读作品、账号、工作流（读最新提交的状态，不用事务前的对象），算 `taskContext`（files 用 `listTaskFiles`）和 `taskState`，`writeTaskMirror`。写失败或拿锁超时只 `app.warn`，不让用例失败。删除作品不动文件夹。
- **抹密钥**：代码步骤和数据工具返回的文字（`CodeOutcome` 的 error、ask、note，`DataPullOutcome` 的 reason、fixHint、note）、它们抛出的异常 message，在写进记录库、任务文件夹、返回值之前，一律用 `redactSecrets` 把这个账号在凭证文件里的全部密钥值抹掉。平台适配的实现不可信：外部库的报错可能带着密钥。
- **步骤占位符**：`vars = { folder: taskFolderPath(...), platform: 平台名, account: 账号名 }`。
- **排序位置**：排到最前用 `topOrder(全部作品)`，排到最后用 `bottomOrder(全部作品)`。

| `submitFeedback(id, text)` | 规则 `submitFeedback`，order = topOrder |
| `deleteWork(id)` | 删记录库里的作品（连带记录、反馈、快照）；灵感的 workIds 自动少一个；任务文件夹留着 |

### 作品（agent 用）

**令牌和租约**：

- 接手时 `lease = { since: at, expiresAt: toIsoTime(now + config.lease.minutes 分钟) }`，令牌 `app.newToken()`，只在返回值里出现这一次。
- 推进作品的用例（step、run、back、release）先核对：作品是进行中（否则 STATE_CONFLICT「作品现在是<状态>，不在进行中」）、记录库里的令牌等于传入的（否则 STATE_CONFLICT「令牌对不上：这个作品已经被别人接手或挪走了」，hint「运行 leafpress work show <编号> 看现在的情况」）。租约过期但令牌对得上照样放行（没人接管就继续）。
- 推进后仍是进行中就续期：`expiresAt` 重新从现在算，令牌不变；不是进行中就清掉令牌。

| 用例 | 规则 |
|---|---|
| `startWork({ id, force })` | 事务里读作品：待实现 → 规则 `startWork`；进行中 → 租约已过期或带 force 时 `startWork(..., takeover: true)` 换新令牌，否则 STATE_CONFLICT「这个作品正在被别的 agent 做（<since 的 月日 时分> 接手，租约到 <expiresAt 的 月日 时分>）」，hint「如果就是你自己（比如对话被压缩、令牌丢了），加 --force 接管」；等你处理 → STATE_CONFLICT「这一步要作者来做：<waitingLabel>」，hint「作者在网页上写反馈后，作品会回到待实现」；已完成 → STATE_CONFLICT「这个作品已经完成了」。工作流对这个账号用不了（`isUsable` 为假）→ STATE_CONFLICT「「<工作流名>」要先配：<没配好的配置项名>」，hint「在网页的账号详情 · 接入里填」。规则结果是进行中才发令牌 |
| `startNext({ accountId })` | 事务里用 `pickNext`（canStart = 工作流能用，可按账号筛）挑一个再按 `startWork` 接手；挑不到返回 undefined。挑和接手在同一个事务里，两个 agent 同时 next 不会挑到同一个 |
| `stepWork(id, token, { force })` | 核对令牌；当前是 AI 步骤且 produces 里有文件不在任务文件夹 → 不带 force 时 `STEP_OUTPUT_INVALID`「这一步要产出 <文件、文件>，任务文件夹里还没有」，hint「放进 <文件夹> 后再运行；确定不需要就加 --force」；然后规则 `completeAiStep` |
| `runWork(id, token)` | 分三段：① 事务里核对令牌、当前是代码步骤、续期，找实现（找不到 INTERNAL）；② 事务外执行实现（可能很久）：`heartbeat` 在小事务里核对令牌后续期，实现抛错转成 `{ kind: "fail", error }`（LeafPressError 用它的 message，其他异常「内部错误：<message>」，不带调用栈）；③ 事务里重新读作品：令牌、状态、步骤都没变才 `applyCodeResult`，否则 STATE_CONFLICT「执行期间作品被挪走了，这次的结果没有记下」 |
| `backWork(id, token, n)` | 核对令牌；n 从 1 起，转成规则的 target = n - 1；规则 `backToStep` |
| `releaseWork(id, token)` | 核对令牌；规则 `releaseWork`，order = topOrder |

返回值的 `message`：

- 接手：进行中 →「接手了：<步骤名>」；规则里先把你那一步记为完成的 →「读了你的反馈，接着做：<步骤名>」；直接停在等你处理 →「这一步要作者来做，已停在等你处理：<步骤名>」；直接完成 →「已完成」。
- 做完一步 / 执行 / 退回：进行中且下一步是 AI →「下一步：<步骤名>（AI）」；是代码 →「下一步：<步骤名>（自动），运行 leafpress work run <编号>」；等你处理 →「停在等你处理：<waitingLabel>」；已完成 →「已完成」加「，链接：<url>」（有的话）；代码步骤出错 →「出错了：<error>」。

### 数据与周报

- `pullData({ accountIds })`：不传就是全部账号；传了的都要存在。按 `pullPlan(accounts, app.catalog)`：skip 不记；blocked 记一条失败的拉取记录（reason 为规则给的）；pull 逐个账号调数据工具（一个号出错不影响别的号，抛异常按失败算「内部错误：…」）：
  - 成功：一个事务里写 `putAccountDay`（reads、interactions 没给就是 null）、`putWorkSnapshot`（不属于这个账号的作品编号跳过并 warn）、拉取记录（status ok，note 用工具的）。
  - 失败：拉取记录（failed、reason、fixHint）；有 expiredKey 时 `settings.markExpired`。
  - 返回 `{ outcomes, note: pullNote(...) }`。M1 没有任何数据工具，结果是 `{ outcomes: [], note: "没有能拉的账号" }`。
- `dataset()`：`today` 取现在；读 `[today - DATASET_DAYS, today - 1]` 的快照；`buildDataset`。
- `saveNote(week, input)`：week 必须是周一（`weekStartOf(week) === week`，否则 USAGE）；三段原样保存，updatedAt = at。

### 整体

- `bootstrap()`：`now`、`today`、`version()`、`paths`（home、tasks、accounts、backups）、全部作品、灵感、账号、每个账号最近一次拉取、复盘笔记、`schedules: []`（M2 起有定时任务）。
- `version()`：`{ ...store.meta.version(), profilesStamp: profilesStamp(paths) }`。
- `exportBackup()`：`exportBackup(paths, store, config, app.now())`。

## 关键决策

1. **门面接口放共享包**：命令行和本机服务只认 `UseCases`，可以和用例同时开发，测试时换假实现。
2. **读也在写事务里**：命令行和本机服务是两个进程，`BEGIN IMMEDIATE` 让同一时刻只有一个在改，读到的就是最新的。
3. **代码步骤分三段执行**：执行可能很久（推送、跑门禁），不能占着写锁；回来时核对令牌和步骤，作品在这期间被挪走就不记结果，不会把旧结果写到新状态上。
4. **令牌只给一次**：agent 丢了令牌就用 `--force` 接管，作者在网页上也能把作品挪回待实现；令牌只防「两个 agent 同时做一个作品」，不当密钥用。
5. **任务文件夹在提交后写**：记录库是事实来源；文件写失败不回滚业务，下次作品有变化时自然补上。

单测和集成测试 17 个，完整写稿流程一次 0.24 秒；两个进程同时 next 的测试用多进程、多轮、加屏障。经一轮独立评审（Claude 家的模型，副本里做了删校验的变异实验），修了 10 处：拉数据一个账号出错中断整批、账号编号格式、数据集复制了规则、运行期间换掉的旧密钥漏抹、周报日期不合法时 500、平台名「constructor」能写进库，以及几处测试测不出东西。

另由主控亲自做了 skill 的端到端验收：一个只读 skill 说明的 agent 接手作品、按档案写稿、停在「你去发布」；网页提交反馈后它接着做完并归档链接。

**已知限制**：同一个令牌同时执行两次代码步骤，代码步骤会被执行两次（第二次的结果因为核对不上不会写进去）。要 agent 自己并发调用才会发生，skill 要求按顺序调用；M2 有推送类步骤时再加执行锁。

## 验证方式

单测在 `tests/usecases/`：每个用例用临时数据目录 + 真实的记录库和文件，`now`、`newToken` 注入，代码步骤和数据工具用测试里造的假 `PlatformRuntime`（真实的通用写稿实现也要跑一遍）。必须覆盖：

1. 灵感转作品：一条灵感转三个账号，三个作品编号、order、工作流对；灵感变成已转作品、workIds 三个；三个任务文件夹都有 `作品.md`、`状态.json`、`记录.log`。
2. **完整流程**（通用写稿 + 真实的归档实现）：startNext 拿到令牌 → stepWork 缺 `稿子.md` 报 STEP_OUTPUT_INVALID → 写入文件后 stepWork → 等你处理、`要你做的事.md` 出现 → submitFeedback「发布了 https://zhuanlan.zhihu.com/p/1」→ 回到待实现最前面、`你的反馈.md` 有一段 → startWork（「读了你的反馈，接着做：归档链接」）→ runWork → 已完成、url、publishedAt、`状态.json` 是 done、`要你做的事.md` 已删。
3. 令牌：同一作品第二次 startWork 报 STATE_CONFLICT（message 带接手时间）；带 force 接管后旧令牌 stepWork 报「令牌对不上」；把时钟拨过租约后不带 force 也能接管；网页把进行中的作品挪回待实现后，agent 的令牌失效。
4. 两个 agent 同时 next（用两个子进程，各自 openApp 同一个数据目录，同时调 startNext）：拿到的是两个不同的作品；只有一个待实现作品时一个拿到、一个返回 undefined。
5. runWork：假实现返回 fail → 仍进行中、error 写上、任务说明里有「出错了」；返回 ask → 等你处理、步骤不动；实现执行期间（在实现里调 moveWork）作品被挪走 → STATE_CONFLICT 且结果没写进去；实现里调 heartbeat 后租约到期时间变晚。
6. moveWork：待实现里重排（beforeId 前后、放最后）；进行中挪到等你处理清掉令牌；已完成挪不出来。
