# 数据目录 · 任务文件夹与档案

> 模块定位：数据目录里的文件：每个作品的任务文件夹（说明文件跟着记录库更新）、账号档案、导出备份、在资源管理器里打开文件夹 · 对应代码：`src/files/` · 所属里程碑：[M1 底座](../roadmap.md#m1-底座) · 状态：进行中 · 最近更新：2026-10-08

## 职责与边界

- 管：任务文件夹的位置和里面五个说明文件的写法；列出任务文件夹里 agent 放进来的产出；账号档案的读写；档案的最后修改时间；导出备份；打开文件夹。
- 不管：说明文件的内容从哪来（用例用共享规则算好传进来）；agent 写的产出文件（这里只列出、只检查在不在，不改）。
- 任务文件夹是记录库的镜像加产出：状态以记录库为准，说明文件写坏了、被删了，下次作品有变化时会重新写出来。

## 结构与数据流

```
用例改完记录库（事务提交后）
   │  taskContext / taskState 算好内容
   ▼
writeTaskMirror ──► ~/.leafpress/tasks/<作品编号>/
                      作品.md          给 agent 和人看的完整说明（同「复制给 AI」）
                      状态.json        机器读：状态、第几步、当前步骤、要你做的事、租约到期时间
                      要你做的事.md    只在等你处理时有
                      你的反馈.md      你提交过的全部反馈
                      记录.log         作品的记录
                      <产出文件>        agent 和代码步骤写的：稿子.md、复制页.html……
网页 / agent 改档案 ──► ~/.leafpress/accounts/<账号编号>.md
```

| 文件 | 导出 |
|---|---|
| `task-folder.ts` | `MIRROR_FILES`、`taskFolderPath`、`writeTaskMirror`、`listTaskFiles`、`missingFiles`、`TaskMirror` |
| `profiles.ts` | `profilePath`、`readProfile`、`writeProfile`、`profilesStamp` |
| `export.ts` | `exportBackup` |
| `open-folder.ts` | `openFolder` |
| `atomic.ts` | `writeFileAtomic`（写临时文件再改名；内容没变就不写） |
| `lock.ts` | `withTaskLock` 和通用的目录锁（凭证文件也用同一套做法，可以共用） |
| `ids.ts` | `assertSafeId`（编号只许 `^[a-z0-9][a-z0-9-]*$`，否则抛 `LeafPressError("INTERNAL")`，防止拼出数据目录以外的路径） |

### 接口

```ts
import type { FeedbackEntry, TaskState, WorkLog } from "@leafpress/core";
import type { HomePaths } from "../config/home.js";
import type { LeafPressConfig } from "../config/schema.js";
import type { ExecFn } from "../shared/exec.js";

export const MIRROR_FILES = ["作品.md", "状态.json", "要你做的事.md", "你的反馈.md", "记录.log"] as const;

export interface TaskMirror {
  workId: string;
  /** 作品.md 的全文（taskContext 的结果） */
  context: string;
  /** 状态.json 的内容 */
  state: TaskState;
  /** 等你处理时要你做的事；没有就删掉 要你做的事.md */
  ask?: string;
  feedback: FeedbackEntry[];
  log: WorkLog[];
}

export function taskFolderPath(paths: HomePaths, workId: string): string;   // <tasksDir>/<workId>
/** 建文件夹（不存在时），写五个说明文件；每个文件都是原子写，内容没变的不写 */
export function writeTaskMirror(paths: HomePaths, mirror: TaskMirror): void;
/** 任务文件夹里除说明文件以外的文件，递归，相对路径用 / 分隔，跳过 . 开头的文件和文件夹，按路径排序；文件夹不存在返回 [] */
export function listTaskFiles(paths: HomePaths, workId: string): string[];
/** names 里哪些在任务文件夹里不存在（names 是相对路径） */
export function missingFiles(paths: HomePaths, workId: string, names: readonly string[]): string[];

export function profilePath(paths: HomePaths, accountId: string): string;   // <accountsDir>/<accountId>.md
/** 文件不存在返回空串 */
export function readProfile(paths: HomePaths, accountId: string): string;
/** 原子写；去掉末尾多余空白后，非空时以一个换行结尾，空时写空文件 */
export function writeProfile(paths: HomePaths, accountId: string, text: string): void;
/** accounts 目录里 .md 文件最晚的修改时间（毫秒，取整）；目录不存在返回 0 */
export function profilesStamp(paths: HomePaths): number;

/**
 * 导出到 <backupsDir>/export-<YYYYMMDD-HHmmss>/：leafpress.db（用 backupTo 一致地复制）、accounts/ 下全部档案、
 * config.json（用传进来的 config 重新写，不复制原文件：第 1 版的原文件可能带着密钥）。
 * 不导出 credentials.json 和 config.v1.json.bak。同一秒导出两次时第二次在文件夹名后加 -2。
 */
export function exportBackup(paths: HomePaths, store: { backupTo(target: string): void }, config: LeafPressConfig, now: Date): { dir: string };

/**
 * 同一个作品的说明文件串行写：在锁里执行 fn（fn 里重新读记录库的最新状态再写）。
 * 锁是 <任务文件夹>/.lock 目录（mkdir 成功即拿到）；拿不到每 50 毫秒重试，最多 5 秒；存在超过 30 秒当作上次异常退出留下的，删掉再拿。
 * 拿锁超时抛 STORE_FAILED（用例会转成 warn）。
 */
export function withTaskLock<T>(paths: HomePaths, workId: string, fn: () => T): T;

/** 在系统的文件管理器里打开：Windows 用 explorer.exe（它成功时退出码也是 1，不看退出码），macOS 用 open，Linux 用 xdg-open */
export function openFolder(exec: ExecFn, path: string, platform?: NodeJS.Platform): Promise<void>;
```

### 说明文件的写法

- `作品.md`：`mirror.context` 加末尾换行。
- `状态.json`：`JSON.stringify(state, null, 2)` 加末尾换行。
- `要你做的事.md`：`mirror.ask` 加末尾换行；没有 ask 时删掉这个文件（不存在不报错）。
- `你的反馈.md`：每条一段，段与段空一行：

```
## 2026-10-08 09:30（你去发布）

发布了，链接是 https://zhuanlan.zhihu.com/p/1
```

  没有反馈时删掉这个文件。时间取 `at` 的前 16 个字符、把 `T` 换成空格。
- `记录.log`：每条一行 `2026-10-08 09:30  <text>`（两个空格隔开），末尾换行。

## 关键决策

1. **说明文件由用例写，产出由 agent 写**：两边不碰对方的文件；说明文件的内容永远从记录库算出来，换哪个 agent 看到的都一样。
2. **原子写、没变不写、按作品加锁**：agent 可能正开着这些文件；写一半不会被读到，没变化不改修改时间。命令行和本机服务可能同时更新同一个作品的说明文件，锁里重新读记录库的最新状态再写，后写的一定是最新的。
3. **编号先查格式再拼路径**：作品和账号编号都由 LeafPress 生成，但接口传进来的编号还是要防一手。
4. **导出不带密钥**：备份可能被拷到别处；密钥丢了重新填就行。

## 验证方式

单测在 `tests/files/`，用临时目录：

1. `writeTaskMirror`：五个文件的内容逐字对上；再写一次内容不变时修改时间不变；ask 和反馈没有时对应文件被删掉；文件夹不存在时自动建。
2. `listTaskFiles`：排除说明文件和 . 开头的、子文件夹里的文件用 / 拼、排序；`missingFiles`。
3. 档案：读不存在的文件为空串；写入规范化末尾换行；`profilesStamp` 随写入变大、目录不存在为 0。
4. `exportBackup`：文件夹里有库（能打开，数据一致）、档案、配置（数据目录里放一份带 `zhihu.developerAccessSecret` 的第 1 版配置，导出的 config.json 里没有这个值），没有凭证文件和 config.v1.json.bak；同一秒两次。
7. `withTaskLock`：两个子进程对同一个作品各做 20 次「拿锁 → 读计数文件 → 加一 → 写回」，最后是 40；过期的锁被清掉。
5. `openFolder`：用假的 exec 断言三个平台各自调用的命令和参数；Windows 上退出码 1 不报错。
6. `assertSafeId`：`../x`、`a/b`、空串、大写被拒。

`pnpm gate` 全部通过。
