# 平台适配 · 登记表与通用工作流

> 模块定位：代码步骤和拿数据工具的实现怎么登记、怎么找；通用写稿工作流的「归档链接」 · 对应代码：`src/platforms/`（types、registry、general） · 所属里程碑：[M1 底座](../roadmap.md#m1-底座) · 状态：已完成 · 最近更新：2026-10-09
>
> 平台和工作流的**定义**（名字、数据项、步骤、要配的东西）是静态数据，在共享规则包的 `catalog/`（见 [共享规则 · 类型与作品流转](共享规则-类型与作品流转.md)）；这里只放**实现**。博客读取（`src/platforms/blog/`）在 M2 接回来，见 [平台接入 · 接入框架与博客](平台接入-接入框架与博客.md)。

## 职责与边界

- 管：代码步骤的实现（按「工作流编号 + 步骤编号」登记）、拿数据工具的实现（按平台登记）、启动时检查定义里的每个代码步骤都有实现；M1 的通用写稿「归档链接」。
- 不管：作品状态怎么变（共享规则）、什么时候调（用例）。实现只返回结果，不碰记录库。

## 结构与数据流

```
用例 runWork ──► runtime.codeStep(工作流, 步骤) ──► 实现(ctx) ──► CodeOutcome ──► 共享规则 applyCodeResult
用例 pullData ──► runtime.dataTool(平台) ──► pull(ctx) ──► 快照 ──► 记录库
```

| 文件 | 导出 |
|---|---|
| `types.ts` | 下面的接口（照抄） |
| `registry.ts` | `createPlatformRuntime()`、`missingHandlers(runtime, workflows)` |
| `general/archive.ts` | `archiveLink`：通用写稿的「归档链接」 |
| `general/index.ts` | `GENERAL_HANDLERS`：`{ "general-write/archive": archiveLink }` |

### 接口（`src/platforms/types.ts`，照抄）

```ts
import type { Account, CodeOutcome, DayKey, Work, WorkflowDef, WorkflowStep, WorkTotals } from "@leafpress/core";
import type { ExecFn } from "../shared/exec.js";

/** 代码步骤拿到的东西 */
export interface CodeStepContext {
  work: Work;
  account: Account;
  workflow: WorkflowDef;
  step: WorkflowStep;
  /** 任务文件夹（绝对路径，已存在） */
  folder: string;
  today: DayKey;
  now: Date;
  /** 这个账号的普通配置值 */
  setting(key: string): string | undefined;
  /** 这个账号的密钥；只许传给平台接口，不许写进返回值、记录、文件 */
  secret(key: string): string | undefined;
  exec: ExecFn;
  /** 步骤要跑很久时调，给租约续期 */
  heartbeat(): void;
}

export type CodeStepHandler = (ctx: CodeStepContext) => Promise<CodeOutcome>;

/** 拿数据工具拿到的东西 */
export interface DataPullContext {
  account: Account;
  /** 这个账号的全部作品（工具按链接或原稿编号对上作品） */
  works: Work[];
  today: DayKey;
  now: Date;
  setting(key: string): string | undefined;
  secret(key: string): string | undefined;
  exec: ExecFn;
  fetch: typeof fetch;
}

export interface DataPullResult {
  /** 账号每天的数：粉丝；平台能直接给出账号当天的主数据和互动时也带上 */
  account: { day: DayKey; followers: number | null; reads?: number; interactions?: number }[];
  /** 作品每天结束时的累计数 */
  works: { workId: string; day: DayKey; totals: WorkTotals }[];
  /** 成功时给人看的一句话，例如「入库 32 个作品」 */
  note?: string;
}

export type DataPullOutcome =
  | { ok: true; result: DataPullResult }
  /** expiredKey：平台拒绝了某个配置项（比如密钥失效），用例会把它标成过期 */
  | { ok: false; reason: string; fixHint?: string; expiredKey?: string };

export interface DataTool {
  pull(ctx: DataPullContext): Promise<DataPullOutcome>;
}

export interface PlatformRuntime {
  codeStep(workflowId: string, stepId: string): CodeStepHandler | undefined;
  dataTool(platform: Account["platform"]): DataTool | undefined;
}
```

### 登记表

```ts
/** 登记 M1 的全部实现：通用写稿的代码步骤；还没有拿数据的工具 */
export function createPlatformRuntime(): PlatformRuntime;
/** 定义里有、实现里没有的代码步骤，返回「<工作流编号>/<步骤编号>」列表 */
export function missingHandlers(runtime: PlatformRuntime, workflows: readonly WorkflowDef[]): string[];
```

用例在执行代码步骤前找不到实现时报 `INTERNAL`「「<工作流名>」的「<步骤名>」还没有实现」。单测断言 `missingHandlers(createPlatformRuntime(), WORKFLOWS)` 为空，以后加工作流忘了写实现会立刻发现。

### 通用写稿 ·「归档链接」

- 读 `ctx.work.feedback`；没有就读 `feedbackHistory` 的最后一条。用共享规则的 `extractUrl` 取第一个网址。
- 取到 → `{ kind: "done", url, publishedAt: ctx.today }`。
- 取不到 → `{ kind: "ask", ask: "没在你的反馈里找到链接。把发布后的链接填在下面；还没发就先去发。" }`。
- 不碰网络、不读写文件。

## 关键决策

1. **定义和实现分开放**：定义是静态数据，网页要显示，放共享包；实现要跑命令、联网、读密钥，只能在本机的 Node 里，放这里。
2. **实现只返回结果**：状态怎么变全由共享规则决定，实现里不出现「改成等你处理」这类逻辑，以后加平台不会把规则写散。
3. **拉数据失败带上是哪个配置项被拒**：用例据此把配置项标成过期，接入状态自动变成「有问题」。

## 当前实现

`types.ts`（接口照规格）、`registry.ts`（`createPlatformRuntime`、`missingHandlers`）、`general/archive.ts`（归档链接）。单测 7 个。取链接用共享规则的 `extractUrl`：评审发现链接后面紧跟中文会被吞进去，已改成只取 ASCII 网址字符并去掉末尾标点。
