# 配置 · 配置与凭证

> 模块定位：确定数据目录和里面每个文件的位置、读写本机配置、读写账号密钥（凭证文件）、把文本里的密钥抹掉 · 对应代码：`src/config/` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基)、[M1 底座](../roadmap.md#m1-底座)（配置第 2 版、凭证文件） · 状态：已完成（M1 改造） · 最近更新：2026-10-09

## 职责与边界

- 管：数据目录在哪、目录里各文件的路径；`config.json` 的格式、默认值、读写、旧版本升级；`credentials.json`（账号密钥）的读写；抹密钥。
- 不管：账号的普通配置值（在记录库）、任何网络请求。
- 底线：**任何错误信息、日志、命令输出、接口返回里都不出现密钥的值**。

## 结构与数据流

| 文件 | 导出 | 说明 |
|---|---|---|
| `home.ts` | `resolveHome(options?)`、`homePaths(home)`、`HomePaths` | 数据目录：显式传入 > 环境变量 `LEAFPRESS_HOME` > `<用户目录>/.leafpress`，返回绝对路径 |

| `credentials.ts` | `openCredentials`、`CredentialStore` | 账号密钥的读写 |
| `redact.ts` | `redactSecrets` | 抹密钥（第一阶段已有，不改） |

第一阶段的 `credential-types.ts`（知乎凭证状态）没人用了就删掉。

### 数据目录

```ts
export interface HomePaths {
  home: string;
  configFile: string;      // <home>/config.json
  credentialsFile: string; // <home>/credentials.json
  dbFile: string;          // <home>/leafpress.db
  accountsDir: string;     // <home>/accounts      账号档案 <账号编号>.md
  tasksDir: string;        // <home>/tasks         任务文件夹 <作品编号>/
  backupsDir: string;      // <home>/backups
  logsDir: string;         // <home>/logs
}
```

第一阶段的 `runsDir` 删掉。`homePaths` 只算路径，不建目录。

### 配置第 2 版（`config.json`）

```json
{
  "version": 2,
  "server": { "port": 3210 },
  "browser": { "executablePath": "<可选>" },
  "schedule": { "dataPullAt": "06:00" },
  "lease": { "minutes": 120 }
}
```

| 字段 | 规则 | 默认值 |
|---|---|---|
| `version` | 字面量 2 | 必填 |
| `server.port` | 整数 1024～65535 | 3210 |
| `browser.executablePath` | 非空字符串，可选 | 无 |
| `schedule.dataPullAt` | `HH:mm`（00:00～23:59） | `"06:00"` |
| `lease.minutes` | 整数 5～1440，agent 接手一个作品后多久没动静算超时 | 120 |

所有对象 `z.strictObject`，整段缺省时补默认值（zod 4 要显式给内部缺省，第一阶段踩过）。

### 读写规则

```ts
/** 文件不存在 → 默认配置（不报错）；第 1 版 → 在内存里转成第 2 版（只保留 browser.executablePath），不写文件；校验不过 → CONFIG_INVALID */
export function loadConfig(home: string): LeafPressConfig;
/** 只看不改：文件在不在、是第几版 */
export function inspectConfig(home: string): { exists: boolean; version?: number };
/** 先校验，再写临时文件后改名；两空格缩进、末尾换行 */
export function writeConfig(home: string, config: LeafPressConfig): void;
/** 第一阶段已有：不存在才写，返回 { created, path } */
export function writeConfigIfAbsent(home: string, config: LeafPressConfig): { created: boolean; path: string };
/** 是第 1 版就先复制成 config.v1.json.bak（已存在就加时间戳），再写成第 2 版；不是第 1 版什么都不做 */
export function upgradeLegacyConfig(home: string): { upgraded: boolean; backupPath?: string };
```

- `CONFIG_INVALID` 的 message 逐条列出「字段路径：问题」，**不出现任何字段的值**（沿用第一阶段）。JSON 写坏时不附原始异常。
- 第 1 版的识别：是合法 JSON、`version` 为 1。第 1 版里的 `blog`、`materials`、`zhihu` 字段一概忽略，不读出来、不输出（`zhihu.developerAccessSecret` 是密钥）。博客仓库路径等不迁移：M2 接博客时在博客账号的接入里重新填，`init` 升级时提示一句。
- 升级备份 `config.v1.json.bak` 原样保留在数据目录里（和凭证文件同一个地方，同样只有自己能看）；**任何导出、输出都不能直接复制 config.json 原文件**，要用 `loadConfig` 的结果重新写（第 2 版里没有密钥字段）。

### 凭证文件（`credentials.json`）

```json
{ "version": 1, "accounts": { "blog-2": { "umami-key": "…" } } }
```

```ts
export interface CredentialStore {
  /** 这个账号存了哪些密钥（只给键） */
  keys(accountId: string): Set<string>;
  get(accountId: string, key: string): string | undefined;
  /** value 去首尾空白后不能为空（空的用 remove） */
  set(accountId: string, key: string, value: string): void;
  remove(accountId: string, key: string): void;
}
export function openCredentials(file: string): CredentialStore;
```

- 每次调用都重新读文件（命令行和本机服务两个进程都会写，不缓存）。
- **写要加跨进程锁**：`set`、`remove` 的「读 → 改 → 写临时文件 → 改名」整段在锁里做。锁是 `<凭证文件>.lock` 目录（`mkdir` 成功即拿到锁，用完删掉）；拿不到每 50 毫秒重试，最多 5 秒，超时报 `STORE_FAILED`「凭证文件正被别的进程占用」；锁目录存在超过 30 秒当作上次异常退出留下的，删掉后再拿。
- 新建凭证文件和临时文件时文件权限给 `0o600`（Windows 上会被忽略，类 Unix 系统上只有自己能读）。
- 文件不存在当作空；不是合法 JSON 或形状不对 → `CONFIG_INVALID`「凭证文件格式不对：<路径>」，hint「检查这个文件，或者删掉后重新填密钥」，不附原始异常、不带内容。
- 账号的密钥都删光了就把这个账号的键也删掉。

## 关键决策

1. **配置文件可以没有**：所有字段都有默认值，第一次用不用先 init；`leafpress init` 只负责建目录、写一份默认配置、建库。
2. **账号配置分两处**：普通值进记录库（网页改了即时生效、有变更序号），密钥单独放 `credentials.json`，和普通配置分开，方便以后加文件权限或换成系统钥匙串。
3. **第 1 版配置读时转换、显式升级时才改文件**：体检要能只读地运行。
4. **所有函数收注入的路径和环境**：测试不碰真实的用户目录。

## 当前实现

| 文件 | 内容 |
|---|---|
| `home.ts` | 数据目录和八个路径 |
| `schema.ts` | 配置第 2 版，全部字段有默认值 |
| `load.ts` | 读（不存在给默认、第 1 版在内存里转换）、写、显式升级（备份 `config.v1.json.bak` 后权限收成 0o600） |
| `credentials.ts` | 凭证文件：每次重新读，写在目录锁里，权限 0o600 |
| `redact.ts` | 抹密钥（第一阶段已有） |

Windows 上别的进程开着目标文件时，改名和读取会报 EPERM / EBUSY：读写都带递增退避的重试（总共约 2 秒），用尽后报 `STORE_FAILED`，不抛裸错误。真实子进程测试：两个进程同时各写 20 个键全部保留；把锁临时去掉时 400 键的并发测试会变红。经一轮独立评审（Claude 家的模型，在本机复现了改名失败和过期锁竞态），已修。

## 验证方式

单测在 `tests/config/`，用临时目录。必须覆盖：

1. `resolveHome` 三种来源的优先级；`homePaths` 每个路径。
2. `loadConfig`：文件不存在给默认；第 2 版正常；整段缺省补默认；未知字段、端口越界、时间格式不对报 `CONFIG_INVALID` 且 message 不含字段值；JSON 写坏；第 1 版转换（带一个值很特别的 `zhihu.developerAccessSecret`，断言转换结果和任何错误里都没有它）。
3. `writeConfig` 原子写；`writeConfigIfAbsent` 不覆盖；`upgradeLegacyConfig` 备份和改写、第 2 版不动、备份文件名冲突时加时间戳。
4. 凭证：增、改、删、删光后账号键消失、文件不存在当空、格式不对报错且 message 和 hint 不含文件内容；**两个子进程同时各写 20 个不同的键，最后 40 个键都在**；锁目录过期被清掉；拿锁超时报错。
5. 不泄露：用值很特别的密钥跑所有函数的所有分支，断言返回值（除 `get`）、message、hint 都不含它。
6. `redactSecrets` 已有测试保留。

`pnpm gate` 全部通过。
