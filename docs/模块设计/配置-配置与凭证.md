# 配置 · 配置与凭证

> 模块定位：确定数据目录、读写本地配置、检查和读取凭证 · 对应代码：`src/config/` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基) · 状态：开发中 · 最近更新：2026-10-05

## 职责与边界

- 管：LeafPress 数据目录在哪；`config.json` 的格式、默认值、读写；知乎发布凭证和知乎数据接口密钥的检查与读取；把文本里的密钥抹掉。
- 不管：凭证的申请和写入（由知乎官方 skill 负责写共享凭证文件）；任何网络请求。

## 结构与数据流

| 文件 | 导出 | 说明 |
|---|---|---|
| `src/config/home.ts` | `resolveHome(options?)`、`homePaths(home)` | 数据目录：显式传入 > 环境变量 `LEAFPRESS_HOME` > `<用户目录>/.leafpress`，一律返回绝对路径。`homePaths` 返回 `{ home, configFile, dbFile, runsDir }`，分别是 `<home>/config.json`、`<home>/leafpress.db`、`<home>/runs` |
| `src/config/schema.ts` | `ConfigSchema`、`LeafPressConfig` | zod 定义，见下 |
| `src/config/load.ts` | `loadConfig(home)`、`writeConfigIfAbsent(home, config)` | 读配置、首次写配置 |
| `src/config/credentials.ts` | `checkZhihuOpenApi`、`loadZhihuOpenApi`、`checkZhihuDeveloper`、`loadZhihuDeveloper`、`CredentialStatus` | 凭证检查与读取 |
| `src/config/redact.ts` | `redactSecrets(text, secrets)` | 抹掉文本里的密钥 |

### 配置格式（`<home>/config.json`）

```json
{
  "version": 1,
  "blog": {
    "repoPath": "C:\\code\\yeton-blog",
    "contentDir": "content/posts",
    "remote": "origin",
    "branch": "main",
    "primaryLocaleDir": "zh",
    "siteUrl": "https://example.com"
  },
  "materials": { "projects": [] },
  "zhihu": { "developerAccessSecret": "<可选>" },
  "browser": { "executablePath": "<可选>" }
}
```

zod 规则（zod 4）：

| 字段 | 规则 | 默认值 |
|---|---|---|
| `version` | 字面量 1 | 必填 |
| `blog.repoPath` | 非空字符串 | 必填 |
| `blog.contentDir` | 非空字符串，相对博客仓库根目录 | `"content/posts"` |
| `blog.remote` | 非空字符串 | `"origin"` |
| `blog.branch` | 非空字符串 | `"main"` |
| `blog.primaryLocaleDir` | 非空字符串，原稿默认取哪个语言目录 | `"zh"` |
| `blog.siteUrl` | 合法网址，可选 | 无 |
| `materials.projects` | 非空字符串数组 | `[]`，整个 `materials` 缺省时也是 `{ "projects": [] }` |
| `zhihu.developerAccessSecret` | 非空字符串，可选 | 整个 `zhihu` 缺省为 `{}` |
| `browser.executablePath` | 非空字符串，可选 | 整个 `browser` 缺省为 `{}` |

所有对象都用严格模式（`z.strictObject`）：出现未知字段直接报错，防止拼错字段名后静默失效。

### 读写规则

- `loadConfig(home)`：文件不存在抛 `CONFIG_MISSING`，hint 为「先运行 leafpress init」；不是合法 JSON 或校验不过抛 `CONFIG_INVALID`，message 逐条列出「字段路径：问题」，例如 `blog.siteUrl：不是合法网址`。**错误信息里不得出现任何字段的值**（字段可能是密钥）。返回值已带上默认值。
- `writeConfigIfAbsent(home, config)`：先用 `ConfigSchema` 校验；目录不存在就建；文件已存在则不动，返回 `{ created: false, path }`；否则写入（两空格缩进、末尾换行），返回 `{ created: true, path }`。写入先写临时文件再改名，避免写一半。

### 凭证规则

`CredentialStatus` 形状：

```ts
interface CredentialStatus {
  name: "zhihu-openapi" | "zhihu-developer";
  state: "ok" | "missing" | "incomplete" | "conflict" | "invalid";
  source?: "env" | "file" | "config"; // state 为 ok 时，实际采用的来源
  detail: string; // 中文说明，不含任何密钥
}
```

**知乎发布凭证**（和知乎官方 skill 共用，规则照官方文档）：

- 两个来源：环境变量 `ZHIHU_OPENAPI_APP_KEY` / `ZHIHU_OPENAPI_APP_SECRET`；共享文件 `<用户目录>/.zhihu/openapi-credentials.json`，内容为 `{ "ZHIHU_OPENAPI_APP_KEY": "...", "ZHIHU_OPENAPI_APP_SECRET": "..." }`。
- 一个来源「完整」= 两个值都是非空字符串。
- 判定顺序：
  1. 环境变量完整、文件也完整、两边值不同 → `conflict`，detail 只能说明两个来源的名字和各自的 APP_KEY（APP_KEY 是知乎用户名，可以显示），不得出现 APP_SECRET。
  2. 环境变量完整 → `ok`，source `env`。
  3. 文件完整 → `ok`，source `file`。
  4. 文件存在但不是合法 JSON 或字段不对，而且环境变量也不完整 → `invalid`。
  5. 只有某个来源设置了一半 → `incomplete`，detail 说明缺哪一项（只说名字）。
  6. 都没有 → `missing`，detail 写明去 `https://www.zhihu.com/playground/zhihu-publisher` 申请。
  - 环境变量只设了一半、文件完整时，按第 3 条判 `ok`（来源 file），detail 补一句「环境变量只设置了一半，已忽略」。
- `checkZhihuOpenApi({ env, homedir })` 返回状态，不返回任何凭证值。
- `loadZhihuOpenApi({ env, homedir })` 返回 `{ appKey, appSecret, source }`；状态不是 `ok` 时抛 `CREDENTIAL_MISSING`（missing / incomplete / invalid）或 `CREDENTIAL_CONFLICT`（conflict），错误信息同样不含密钥。

**知乎数据开放平台密钥**：

- 两个来源：环境变量 `ZHIHU_DEVELOPER_ACCESS_SECRET`；配置里的 `zhihu.developerAccessSecret`。
- 两边都有且不同 → `conflict`；有一边 → `ok`（环境变量优先）；都没有 → `missing`，detail 写明去 `https://developer.zhihu.com/` 登录后在个人中心生成。
- `checkZhihuDeveloper({ env, config })`、`loadZhihuDeveloper({ env, config })` 规则同上。

**抹密钥**：`redactSecrets(text, secrets)` 把每个长度不小于 4 的密钥在文本里的所有出现都替换成 `<redacted>`，先替换长的；空串和短于 4 的忽略。

## 关键决策

1. 知乎发布凭证不另存一份，直接读官方 skill 的共享凭证文件：只需要配一次，两边永远一致。
2. 配置用严格模式：拼错字段名会立刻报错。
3. 所有函数都接受注入的 `env` 和 `homedir`，测试时不碰真实环境。

## 验证方式

单测放在 `tests/config/`，用临时目录（`fs.mkdtemp`），不碰真实的用户目录。必须覆盖：

1. `resolveHome` 三种来源的优先级，返回绝对路径。
2. `loadConfig`：文件缺失、JSON 损坏、未知字段、`siteUrl` 不合法、缺省字段补默认值、正常读取。
3. 校验失败时 message 里不出现任何字段值：用一个故意写错类型、值很特别的配置验证。
4. `writeConfigIfAbsent`：首次写入；已存在时不覆盖。
5. 知乎发布凭证：上面判定顺序的每一条都有用例，含「环境变量一半 + 文件完整」。
6. 知乎数据接口密钥：环境变量、配置、两边不同、都没有。
7. **不泄露**：用值很特别的密钥（比如 `SECRET-zz9-unique`）跑所有凭证函数的所有分支，断言返回的 detail、抛出的错误的 message 和 hint 都不包含这个值。
8. `redactSecrets`：多次出现、多个密钥、长短覆盖、短于 4 的不处理。

`pnpm gate` 全部通过。
