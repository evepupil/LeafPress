# 内容模型 · 核心类型

> 模块定位：全项目共用的数据形状和公共件 · 对应代码：`src/core/`、`src/shared/errors.ts`、`src/shared/hash.ts`、`src/platforms/types.ts`、`src/workflows/types.ts` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基) · 状态：已完成 · 最近更新：2026-10-05

## 职责与边界

- 管：作品、原稿、资产、版本、发布记录的类型；形态目录和形态限制；平台接入接口；工作流接口；统一错误类型；内容哈希。
- 不管：任何读写、网络、命令执行。这里只有类型、常量和纯函数，不依赖任何其他层。

## 结构与数据流

| 文件 | 内容 |
|---|---|
| `src/core/formats.ts` | 形态目录 `FORMATS`（长文、回答、短帖、图文卡片、横版视频、竖版视频）、`FormatConstraints` 形态限制 |
| `src/core/content.ts` | `Work` 作品、`Source` 原稿、`Asset` 资产、`Variant` 版本、`Publication` 发布记录、`PublishMode` 发布方式 |
| `src/platforms/types.ts` | `PlatformAdapter` 平台接入、`PlatformCapability` 能力、`SourceProvider` 原稿来源、`SourceSummary` / `ParsedSource` 原稿摘要与完整原稿、`SyncResult` 拉取结果、`PublishTarget` 发布目标 |
| `src/workflows/types.ts` | `WorkflowDefinition` 工作流、`StepDefinition` 步骤、`StepOutcome` 步骤结果、`WaitRequest` 等待请求、`ResumeInput` 恢复输入、`RunStore` 存储接口、`RunRecord` / `StepRecord` 记录、`RunReport` 运行报告 |
| `src/shared/errors.ts` | `LeafPressError`（带错误码 `code` 和修复建议 `hint`） |
| `src/shared/hash.ts` | `sha256`、`sha256File`（文件不存在返回 `"absent"`） |

## 关键决策

1. **平台编号不写死。** `PlatformId` 就是字符串，由平台登记表校验。加平台不用改内容模型。
2. **形态写死成一张表。** 形态决定资产处理的种类（文字、图片、视频），数量少、变化慢，写死能让编译器帮忙检查。
3. **版本带「发布目标」`targetKey`。** 防重复发布按「原稿 + 平台 + 形态 + 目标」判断。长文的目标是空串，回答的目标是问题编号，所以一篇原稿可以回答多个不同的问题，同一个问题却不会答两次。
4. **原稿和资产都记内容哈希。** 内容没变就不重复处理、不重复上传；原稿改了能被发现。
5. **错误信息不带密钥。** `LeafPressError` 的 message 和 hint 都给人看，绝不包含密钥的值。
