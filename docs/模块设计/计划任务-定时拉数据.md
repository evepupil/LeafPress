# 计划任务 · 定时拉数据

> 模块定位：用 Windows 计划任务（系统自带的定时器）每天跑一次 `leafpress data pull`，错过了开机补跑；装上、卸下、查看状态 · 对应代码：`src/schedule/`、`src/cli/commands/schedule.ts` · 所属里程碑：[M2 博客](../roadmap.md#m2-博客) · 状态：进行中 · 最近更新：2026-10-09
>
> 依据：侦察报告（微软官方文档：任务定义文件、`schtasks`、`Get-ScheduledTask`）。用户定：代码能做的定时活用电脑的计划任务。

## 职责与边界

- 管：生成任务定义和启动脚本、注册和删除计划任务、查任务状态、记最近一次定时运行的结果、给网页和体检的状态。
- 不管：拉数据本身（用例 `pullData`）。

## 结构与数据流

```
leafpress schedule install
   ├─ 写 <数据目录>/schedule/run-data-pull.ps1（隐藏窗口启动 node，等它结束，退出码照传）
   ├─ 写任务定义 XML（临时文件）→ schtasks /Create /TN LeafPressDataPull /XML <文件> /F
   └─ 写 <数据目录>/schedule.json：installed、时间、装上的时间
每天 06:00（错过了开机补跑）
   └─ 计划任务 → powershell -WindowStyle Hidden -File run-data-pull.ps1
         └─ node <入口> data pull --scheduled --home <数据目录>
               └─ 拉完把结果记进 schedule.json（lastRunAt、lastResult、lastNote）
网页 / 接入：读 schedule.json（快，不调系统）
leafpress schedule status、体检：再问一次系统（Get-ScheduledTask，慢一点但准）
```

| 文件 | 内容 |
|---|---|
| `src/schedule/task-xml.ts` | `buildTaskXml(input)`：生成任务定义 |
| `src/schedule/wrapper.ts` | `buildWrapperScript(input)`：生成启动脚本 |
| `src/schedule/windows.ts` | `installTask`、`removeTask`、`queryTask`（调 `schtasks`、PowerShell，exec 可注入） |
| `src/schedule/state.ts` | `readScheduleState(paths)`、`writeScheduleState(paths, state)`、`recordScheduledRun(paths, run)` |
| `src/schedule/index.ts` | `installSchedule`、`removeSchedule`、`scheduleStatus` |

### 接口

```ts
export const DATA_PULL_TASK = "LeafPressDataPull";

export interface ScheduleState {
  version: 1;
  dataPull: {
    installed: boolean;
    /** HH:mm */
    at: string;
    installedAt?: IsoTime;
    lastRunAt?: IsoTime;
    lastResult?: "ok" | "failed";
    lastNote?: string;
  };
}

/** 文件不存在时 { version: 1, dataPull: { installed: false, at: <配置的时间> } } */
export function readScheduleState(paths: HomePaths, defaultAt: string): ScheduleState;
export function recordScheduledRun(paths: HomePaths, run: { at: IsoTime; result: "ok" | "failed"; note: string }): void;

export interface InstallInput {
  paths: HomePaths;
  /** HH:mm */
  at: string;
  /** 运行 LeafPress 的 node：process.execPath */
  nodePath: string;
  /** 命令行入口的绝对路径（构建后的 dist/cli/main.js） */
  entryPath: string;
  exec: ExecFn;
  now: Date;
}
export function installSchedule(input: InstallInput): Promise<{ taskName: string; at: string }>;
export function removeSchedule(input: { paths: HomePaths; exec: ExecFn }): Promise<{ removed: boolean }>;

export interface TaskStatus {
  installed: boolean;
  /** Ready、Running、Disabled…（系统给的英文值） */
  state?: string;
  lastRunAt?: IsoTime;
  nextRunAt?: IsoTime;
  /** 上次运行的结果代码，0 是成功 */
  lastResult?: number;
}
export function scheduleStatus(input: { exec: ExecFn }): Promise<TaskStatus>;
```

### 任务定义（照侦察给的模板）

- 触发器：每天 `at`（`CalendarTrigger`，`StartBoundary` = 今天 + `T<at>:00`，`DaysInterval` 1）。
- 身份：当前用户（`<USERDOMAIN>\<USERNAME>`），`LogonType` 为 `InteractiveToken`（只在你登录时运行，不存密码），`RunLevel` 为 `LeastPrivilege`（不要管理员）。
- 设置：`StartWhenAvailable` 为 true（错过了尽快补跑）、`MultipleInstancesPolicy` 为 `IgnoreNew`、不因电池停止、`ExecutionTimeLimit` 为 `PT1H`。
- 动作：`powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -WindowStyle Hidden -File "<启动脚本>"`，工作目录是数据目录。
- 文件编码：`schtasks /XML` 要的编码以实测为准（通常是带 BOM 的 UTF-16 LE）；XML 里的路径做转义。

启动脚本：`Start-Process -FilePath <node> -ArgumentList '"<入口>" data pull --scheduled --home "<数据目录>"' -WindowStyle Hidden -Wait -PassThru`，退出码照传；路径里的单引号、空格、中文都要正确转义。

### 命令

| 命令 | 做什么 | 给人看的输出 |
|---|---|---|
| `leafpress schedule install [--at HH:mm]` | 时间缺省取配置 `schedule.dataPullAt`；已装就更新 | 「已装上：每天 06:00 拉一次数据（错过了开机补跑）」 |
| `leafpress schedule remove` | 删任务、删启动脚本、状态改成没装 | 「已卸下」；本来就没装：「没有装」 |
| `leafpress schedule status` | 问系统 + 读状态文件 | 装没装、下次运行、上次运行和结果、最近一次定时拉取的说明；状态文件说装了但系统里没有时提示「计划任务被删了，运行 leafpress schedule install 重新装」 |
| `leafpress data pull --scheduled` | 照常拉；拉完写 `recordScheduledRun`；有账号失败时退出码 1 | 同 `data pull` |

`--json` 都给结构化结果。`install`、`remove` 只在 Windows 上可用，别的系统报 `USAGE`「定时拉数据目前只支持 Windows」。

### 网页和体检

- `bootstrap().schedules`：`[{ id: "data-pull", name: "拉作品数据", summary: "每天拉一次各账号的数据；拿数据的工具还没做的平台跳过。", when: "每天 <at>", installed, lastRunAt, lastResult, lastNote }]`，只读状态文件。
- 接入里数据获取的「什么时候拉」：装了写「每天 06:00」，没装不写。
- 体检加一项 `schedule`：装了且系统里有 → ok（写下次运行时间）；没装 → warn（建议 `leafpress schedule install`）；状态文件说装了但系统里没有 → warn。

## 关键决策

1. **只在你登录时运行、不存密码**：不需要管理员，也不用把 Windows 密码交给任务；代价是电脑开着但没登录时不跑，开机登录后会补跑。
2. **隐藏窗口用 PowerShell 包一层**：直接跑 node 会弹黑窗口。
3. **网页读状态文件，不调系统**：网页每次取数都调 PowerShell 太慢；准确状态在 `schedule status` 和体检里查。
4. **任务名用英文**：`LeafPressDataPull`，中文说明写在任务描述里，避免中文系统下命令行编码出问题。

## 验证方式

单测在 `tests/schedule/`：

1. `buildTaskXml`：各字段（触发器、身份、StartWhenAvailable、动作、工作目录），路径带空格、中文、`&` 时的转义。
2. `buildWrapperScript`：参数引号、单引号转义。
3. 状态文件：读不存在、写、记一次运行。
4. `installTask` / `removeTask` / `queryTask`：假的 exec 断言调用的命令和参数；系统返回各种结果（没装、装了、上次失败）时的解析。
5. **真实注册一次**（只在 Windows 上跑，`describe.skipIf`）：用一个带随机后缀的测试任务名（`LeafPressDataPullTest-<随机>`）真的注册、查询、删除，`finally` 里保证删掉；断言查询到的触发时间、StartWhenAvailable、登录类型。
6. 命令：`schedule install/remove/status` 和 `data pull --scheduled` 的输出、退出码（用假的 exec）。
