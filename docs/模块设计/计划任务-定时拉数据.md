# 计划任务 · 定时拉数据

> 模块定位：用 Windows 计划任务（系统自带的定时器）每天跑一次 `leafpress data pull`，错过了开机补跑；装上、卸下、查看状态 · 对应代码：`src/schedule/`、`src/cli/commands/schedule.ts` · 所属里程碑：[M2 博客](../roadmap.md#m2-博客) · 状态：已完成 · 最近更新：2026-10-09
>
> 依据：侦察报告（微软官方文档：任务定义文件、`schtasks`、`Get-ScheduledTask`）。用户定：代码能做的定时活用电脑的计划任务。

## 职责与边界

- 管：生成任务定义和启动脚本、注册和删除计划任务、查任务状态、记最近一次定时运行的结果、给网页和体检的状态。
- 不管：拉数据本身（用例 `pullData`）。

## 结构与数据流

```
leafpress schedule install
   ├─ 写 <数据目录>/schedule/run-data-pull.ps1（隐藏窗口启动 node，等它结束，退出码照传）
   ├─ 写任务定义 XML（临时文件）→ 在 PowerShell 里跑 schtasks /Create /TN LeafPressDataPull-<哈希> /XML <文件> /F
   └─ 写 <数据目录>/schedule.json：installed、时间、装上的时间
每天 06:00（错过了开机补跑）
   └─ 计划任务 → powershell -WindowStyle Hidden -File run-data-pull.ps1
         └─ node <入口> data pull --scheduled --home <数据目录>
               └─ 拉完把结果记进 schedule.json（lastRunAt、lastResult、lastNote）
网页 / 接入：读 schedule.json（快，不调系统）
leafpress schedule status、体检：再问一次系统（Get-ScheduledTask，慢一点但准）
```

| 文件 | 内容 |
|---|---|
| `src/schedule/task-xml.ts` | `buildTaskXml(input)`：生成任务定义 |
| `src/schedule/wrapper.ts` | `buildWrapperScript(input)`：生成启动脚本 |
| `src/schedule/windows.ts` | `installTask`、`removeTask`、`queryTask`、`describeLastResult`（exec 可注入） |
| `src/schedule/query-script.ts` | 查任务的 PowerShell 脚本：只有「找不到这个任务」才算没装，别的错误照实报 |
| `src/schedule/schtasks.ts` | 在 PowerShell 里跑 schtasks，输出转成 UTF-8 再交回（中文系统上 schtasks 输出的是 GBK，直接读会乱码） |
| `src/schedule/powershell.ts` | 跑一段 PowerShell 并把结果用 base64 传回，避开控制台编码 |
| `src/schedule/ps-literal.ts` | 把路径写成 PowerShell 单引号字符串（英文单引号和中文弯引号 ‘ ’ ‚ ‛ 都要写两遍） |
| `src/schedule/state.ts` | `readScheduleState(paths)`、`writeScheduleState(paths, state)`、`recordScheduledRun(paths, run)` |
| `src/schedule/index.ts` | `installSchedule`、`removeSchedule`、`scheduleStatus` |

### 接口

```ts
/** 任务名带数据目录的短哈希：不同数据目录（真实目录、验收用的临时目录、测试）各装各的，互不覆盖 */
export function taskNameFor(home: string): string; // `LeafPressDataPull-<sha256(绝对路径转小写) 前 8 位>`

export interface ScheduleState {
  version: 1;
  dataPull: {
    installed: boolean;
    /** HH:mm */
    at: string;
    installedAt?: IsoTime;
    lastRunAt?: IsoTime;
    lastResult?: "ok" | "failed";
    lastNote?: string;
  };
}

/** 文件不存在时 { version: 1, dataPull: { installed: false, at: <配置的时间> } } */
/** 文件坏了（写了一半、格式不对）也不抛错，按「没装」返回 */
export function readScheduleState(paths: HomePaths, defaultAt: string): ScheduleState;
/** 只改最近运行的三个字段；读最新的再写，写临时文件后改名 */
export function recordScheduledRun(paths: HomePaths, run: { at: IsoTime; result: "ok" | "failed"; note: string }): void;

export interface InstallInput {
  paths: HomePaths;
  /** HH:mm */
  at: string;
  /** 运行 LeafPress 的 node：process.execPath */
  nodePath: string;
  /** 命令行入口的绝对路径（构建后的 dist/cli/main.js） */
  entryPath: string;
  exec: ExecFn;
  now: Date;
  /** 缺省 taskNameFor(paths.home)；测试传带随机后缀的名字 */
  taskName?: string;
}
export function installSchedule(input: InstallInput): Promise<{ taskName: string; at: string }>;
export function removeSchedule(input: { paths: HomePaths; exec: ExecFn; taskName?: string }): Promise<{ removed: boolean }>;

export interface TaskStatus {
  installed: boolean;
  /** Ready、Running、Disabled…（系统给的英文值） */
  state?: string;
  enabled?: boolean;
  /** 从没运行过时没有（系统给的是 1999-11-30） */
  lastRunAt?: IsoTime;
  nextRunAt?: IsoTime;
  /** 上次运行的结果代码：0 成功；267011 从没运行过；267009 正在运行；其余是失败 */
  lastResult?: number;
  /** 任务描述里记的数据目录、动作里的 node 和入口路径（体检核对它们还在不在） */
  home?: string;
  nodePath?: string;
  entryPath?: string;
}
export function scheduleStatus(input: { exec: ExecFn; taskName: string }): Promise<TaskStatus>;
/** 系统结果代码的中文说法：成功、还没运行过、正在运行、失败（代码 n；大于 0xFFFF 的写十六进制，如 0x800710E0，方便查） */
export function describeLastResult(code: number | undefined): string;
```

### 任务定义（照侦察给的模板）

- 触发器：每天 `at`（`CalendarTrigger`，`DaysInterval` 1）；`StartBoundary` 取**下一个还没到的** `at`（装的时候已经过了 06:00 就从明天开始，避免一装上就立刻补跑一次）。
- 描述：「LeafPress 每天拉作品数据（数据目录：<绝对路径>）」，`scheduleStatus` 从这里读回数据目录。
- 身份：当前用户（`<USERDOMAIN>\<USERNAME>`），`LogonType` 为 `InteractiveToken`（只在你登录时运行，不存密码），`RunLevel` 为 `LeastPrivilege`（不要管理员）。
- 设置：`StartWhenAvailable` 为 true（错过了尽快补跑）、`RunOnlyIfNetworkAvailable` 为 true、失败重试（`RestartOnFailure`：间隔 `PT30M`、最多 3 次；拉数据有账号失败时命令退出码是 1）、`MultipleInstancesPolicy` 为 `IgnoreNew`、不因电池停止、`ExecutionTimeLimit` 为 `PT1H`。
- 动作：`powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -WindowStyle Hidden -File "<启动脚本>"`，工作目录是数据目录。
- 文件编码：`schtasks /XML` 要的编码以实测为准（通常是带 BOM 的 UTF-16 LE）；XML 里的路径做转义。

启动脚本：`Start-Process -FilePath <node> -ArgumentList '"<入口>" data pull --scheduled --home "<数据目录>"' -WindowStyle Hidden -Wait -PassThru -RedirectStandardOutput <数据目录>\logs\data-pull.out.log -RedirectStandardError <数据目录>\logs\data-pull.err.log`，退出码照传；路径里的单引号、空格、中文都要正确转义。**脚本文件存成带 BOM 的 UTF-8**（Windows PowerShell 5.1 读没有 BOM 的脚本按系统编码 GBK，中文路径会乱）。node 起不来（路径失效、被拦截）时，把「无法启动 node（路径）：原因」写进错误日志再 `exit 1`，计划任务才会记失败、按设置重试；每次先确保日志文件夹在。

### 命令

| 命令 | 做什么 | 给人看的输出 |
|---|---|---|
| `leafpress schedule install [--at HH:mm]` | 时间缺省取配置 `schedule.dataPullAt`；先确认命令行入口和 node 都在（没构建过的源码目录会报「先运行 pnpm build 再装」）；装没装以系统查询为准，已装就更新 | 「已装上：每天 06:00 拉一次数据（只在你登录时运行，错过的在登录后补跑）」 |
| `leafpress schedule remove` | 以系统查询为准；顺序：先结束正在跑的这次（`schtasks /End`），再删任务，再删启动脚本，最后把状态改成没装 | 「已卸下」；本来就没装：「没有装」 |
| `leafpress schedule status` | 问系统 + 读状态文件 | 装没装、下次运行、上次运行和结果、最近一次定时拉取的说明；状态文件说装了但系统里没有时提示「计划任务被删了，运行 leafpress schedule install 重新装」 |
| `leafpress data pull --scheduled` | 照常拉；**整段包在 try/finally 里**，不管成功、失败、中途抛错都写 `recordScheduledRun`；有账号失败时退出码 1 | 同 `data pull` |

`--json` 都给结构化结果。`install`、`remove` 只在 Windows 上可用，别的系统报 `USAGE`「定时拉数据目前只支持 Windows」。

### 网页和体检

- `bootstrap().schedules`：`[{ id: "data-pull", name: "拉作品数据", summary: "每天拉一次各账号的数据；拿数据的工具还没做的平台跳过。", when: "每天 <at>", installed, installedAt, lastRunAt, lastResult, lastNote }]`，只读状态文件（`src/usecases/schedule-view.ts`，bootstrap 和账号接入共用）。
- 接入里数据获取的「什么时候拉」：装了写「每天 06:00」，没装不写。
- 体检加一项 `schedule`：装了且系统里有、启用着、任务里的 node 和入口和数据目录都还在 → ok（写下次运行时间）；没装 → warn（建议 `leafpress schedule install`）；状态文件说装了但系统里没有、任务被禁用、路径不在了 → warn（各写清楚）。
- 提醒：装了定时、但上次运行超过 36 小时 → 提醒「定时拉数据超过一天半没跑了」，detail「上次运行在 <月日 时分>」（电脑一直没登录、任务坏了都能看出来）；由共享规则的 `notices` 读 `schedules` 算。拿「今天 0 点」和上次运行比（共享规则不读当前时刻，保持纯函数）；装上后还没运行过的，拿装上的时刻比；重新装上的从装上那刻重算。

## 关键决策

1. **只在你登录时运行、不存密码**：不需要管理员，也不用把 Windows 密码交给任务；代价是电脑开着但没登录（比如重启后停在登录界面）时不跑，登录后补跑。提示文字里也这样写。
2. **隐藏窗口用 PowerShell 包一层**：直接跑 node 会弹黑窗口。
3. **网页读状态文件，不调系统**：网页每次取数都调 PowerShell 太慢；准确状态在 `schedule status` 和体检里查。
4. **任务名用英文**：`LeafPressDataPull`，中文说明写在任务描述里，避免中文系统下命令行编码出问题。

## 当前实现

- 装、卸、查、命令、体检、网页状态、36 小时没跑的提醒都已实现，按上面的规格。
- 系统上的实测结论：
  - 任务定义文件用带 BOM 的 UTF-16 LE 能注册；
  - 「找不到任务」时 PowerShell 5.1 给的是 `CimJobException`（类别 ObjectNotFound），代码认这一种和 `CimException`；
  - 上次运行结果是无符号 32 位数，按 64 位整数读，否则 0x8 开头的代码会让查询本身报错；
  - schtasks 的报错经 PowerShell 转成 UTF-8 后不乱码，例如「注册计划任务失败：错误: 任务 XML 包含来自意外命名空间的元素或属性。」。
- 一轮独立评审（Claude 家的模型）挑出 6 处，都已修好：
  - 上次运行结果溢出；
  - node 起不来时脚本以 0 退出；
  - 路径里的中文弯引号；
  - 没构建就装；
  - 查询出错被当成没装；
  - 注册失败不带原因。

## 验证方式

单测在 `tests/schedule/`：

1. `buildTaskXml`：各字段（触发器、身份、StartWhenAvailable、动作、工作目录），路径带空格、中文、`&` 时的转义。
2. `buildWrapperScript`：参数引号、单引号转义。
3. 状态文件：读不存在、写、记一次运行。
4. `installTask` / `removeTask` / `queryTask`：假的 exec 断言调用的命令和参数；系统返回各种结果（没装、装了、上次失败）时的解析。
5. **真实注册一次**（只在 Windows 上跑，`describe.skipIf`）：用一个带随机后缀的测试任务名（`LeafPressDataPullTest-<随机>`）真的注册、查询、删除，`finally` 里保证删掉；断言查询到的触发时间（是下一个还没到的时间）、StartWhenAvailable、RunOnlyIfNetworkAvailable、登录类型、描述里的数据目录；启动脚本文件开头是 UTF-8 BOM。
6. 命令：`schedule install/remove/status` 和 `data pull --scheduled` 的输出、退出码（用假的 exec）；装之前入口或 node 不在时报用法错误、不注册。
7. 真实 PowerShell 下的几项（只在 Windows 上跑）：
   - 启动脚本在 node 路径不存在时退出码是 1、错误日志有原因；
   - 含弯引号的路径能原样读回；
   - 查询脚本对不存在的任务返回没装；
   - 故意不合法的任务定义注册失败时，原因是正常中文。

`tests/schedule/` 和命令行相关共 92 个测试；测完系统里没有任何 `LeafPressDataPull*` 任务。`pnpm gate` 全部通过。
