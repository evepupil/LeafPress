# 命令行 · 入口与命令

> 模块定位：`leafpress` 命令：给 agent 推进作品、加灵感、转作品，给作者初始化、体检、起本机服务、导出、装 skill · 对应代码：`src/cli/`、`src/assets/browser.ts` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基)（入口和输出约定）、[M1 底座](../roadmap.md#m1-底座)（新命令）、[M2 博客](../roadmap.md#m2-博客)（查数据、周报、定时任务） · 状态：已完成 · 最近更新：2026-10-09

## 职责与边界

- 管：参数解析；把用例的结果变成给人看的中文或给 agent 读的 JSON；退出码；体检；装 skill；起本机服务。
- 不管：业务规则（全在 `UseCases`），命令里只组装和输出。

## 结构与数据流

| 文件 | 说明 |
|---|---|
| `main.ts` | 入口（第一阶段已有）：`buildProgram()`、`main(argv)`、统一错误处理和退出码。**每个命令的实现都用动态 import 按需加载**，`main.ts` 只登记命令名、参数和说明 |
| `context.ts` | `createCliContext(globalOptions, deps?)`：按需建数据目录路径、配置、`AppContext`（`openApp`）、`UseCases`（`createUseCases`）、找 Edge；`close()` 关闭 |
| `output.ts` | 显示宽度、截断、表格、JSON（第一阶段已有） |
| `commands/<命令>.ts` | 每组命令一个文件：`register(program, getContext)`、`execute*`（只返回数据）、`render*`（数据变成文字） |
| `commands/doctor.ts`、`doctor-inspections.ts` | 体检（第一阶段已有，按下面改） |

测试时 `createCliContext` 可以注入假的 `UseCases`。

### 全局约定（沿用第一阶段）

- 全局选项 `--home <目录>`、`--json`；`--version` 读 `package.json`。
- 退出码：成功 0；出错 1；用法错误 2（参数不对、`USAGE`）。用法错误的 message 写具体原因。
- 出错时给人看：标准错误两行「错误：<message>」「提示：<hint>」；`--json` 时标准输出 `{ "ok": false, "error": { code, message, hint } }`。
- 成功时 `--json` 输出 `{ "ok": true, ...结果 }`。
- 不是 `LeafPressError` 的异常：「内部错误：<message>」，hint「设置环境变量 LEAFPRESS_DEBUG=1 可以看到详细信息」。
- 用例的 `warn` 写到标准错误「注意：<内容>」（`--json` 时也写标准错误，不混进 JSON）。
- 只读命令（`works`、`work show`、`ideas`、`accounts`、`account show`、`data show`、`report`、`doctor`）在数据目录或记录库还不存在时，不顺手建出来：`doctor` 照常体检，其余报 `USAGE`「还没初始化」，hint「先运行 leafpress init」。
- 命令结束前一定关闭记录库。

| `skill install [--force]` | 把仓库里的 `skills/leafpress/` 复制到 `<用户目录>/.claude/skills/leafpress/`，以及 `CODEX_HOME`（缺省 `<用户目录>/.codex`）存在时的 `<CODEX_HOME>/skills/leafpress/`。目标已存在且不带 `--force` 时跳过并说明 | 每个目标一行「已装到 <路径>」或「已存在，加 --force 覆盖：<路径>」 | `{ ok, targets: [{ path, action }] }` |

参数校验：`--status` 只认 todo、doing、waiting、done（灵感是 inbox、promising、converted）；`<第几步>` 是正整数；`--platform` 只认四个平台编号；不认识的值报用法错误并列出可选值。

收自由文字的参数（`work feedback` 的反馈、`ideas add` 的一句话）可以不加引号写多个词；文字以 `-` 开头时在前面加 `--`（`leafpress work feedback z-1 -- "- 把第二段删掉"`），报「未知选项」时提示里会说这一点。表格里的长文本压平换行、按显示宽度截断。`--stdin` 读到的 JSON 先去掉 UTF-8 BOM。

#### `data show` 和 `report` 的 JSON 给 agent 看时的瘦身

`json-slim.ts`：共享规则算出来的结果里，账号带档案全文，作品带记录和反馈历史，几个账号就超过 agent 工具 30K 字的输出上限。JSON 里账号收成 `{ id, name, platform }`，作品收成 `{ id, title, url, publishedAt }`，其余的数照旧。另一条规矩：拿不到的数写 null，不写 0——粉丝拿不到的号（`followersKnown` 为 false），它的 `followers`、`followers7d`、`followers30d`、`weeklyGain`（概况）和 `followersStart`、`followersEnd`、`delta`（周报行）一律换成 null，`data show` 里选中的账号都拿不到粉丝数时 `series.followers` 为 null，`report` 一个账号都拿不到时 `totals.delta` 为 null。走势的点只留 `{ label, start, end, value, compare }`（图上悬停提示用的 `title` 和标签、起止日期重复，不带）。`data show` 的顶层还有 `hasData`：选中的账号都没有数时为 false，此时没有 `series` 和 `top`。

## 体检

| 编号 | 检查项 | 规则 |
|---|---|---|
| `node` | Node 版本 | 低于 24.2 为 error |
| `config` | 配置 | 不存在为 ok（说明「用默认配置」）；第 1 版为 warn（建议 `leafpress init` 升级）；校验不过为 error（照搬 message 和 hint） |
| `store` | 记录库 | `inspectStore(dbFile, MIGRATIONS.length)` 只读查看：不存在 warn（建议 init）；版本低 warn（下次运行会自动备份并升级）；版本高 error；正常时说明版本 |
| `home` | 数据目录 | 存在且可写为 ok；不存在 warn（建议 init）；不可写 error |
| `web` | 网页 | `web/out/index.html` 存在为 ok；否则 warn（「网页还没构建」，建议在仓库里运行 `pnpm --filter leafpress-web build`） |
| `skill` | LeafPress skill | `<用户目录>/.claude/skills/leafpress/SKILL.md` 存在为 ok，否则 warn（建议 `leafpress skill install`） |
| `browser` | 浏览器 | `locateEdge` 找到为 ok，否则 warn |
| `schedule` | 定时拉数据（M2 加） | 只在 Windows 上检查，别的系统 warn「Windows 计划任务不可用」；没装 → warn（建议 `leafpress schedule install`）；状态文件说装了但系统里没有、任务被禁用、任务里的数据目录 / node / 入口不在了 → warn（各写清楚）；装了且启用且路径都在 → ok（写下次运行时间）。见[计划任务](计划任务-定时拉数据.md) |

第一阶段的 `blog-repo`、`blog-site-url` 两项删掉（M2 接博客时改成按博客账号的配置项检查）。每一项各自捕获异常；任何说明和建议里都不出现密钥。

### 启动速度

agent 会频繁调用，启动要快：入口只加载 commander 和自己，命令的实现、zod、记录库、Hono 等都在用到时才 `import()`。验收时报两个数（`pnpm build` 之后，各跑 5 次取中位数）：`node dist/cli/main.js --version`、`node dist/cli/main.js work show <作品> --home <临时目录>`。第一阶段 `--version` 要 700 毫秒，目标是两者都在 400 毫秒以内；做不到就在回报里写清时间花在哪。

## 关键决策

1. **执行和显示分开**（沿用）：测试断言数据，输出格式改了不用改一堆测试。
2. **令牌明着给 agent**：只在接手时输出一次，后续命令必须带 `--lease`；丢了用 `--force` 接管。
3. **`work show` 输出的就是任务说明原文**：agent 看到的和任务文件夹里的 `作品.md`、网页的「复制给 AI」一字不差。
4. **命令按需加载**：一次调用只加载用到的模块，Windows 上读大量小文件很慢。
5. **体检不联网、不改任何东西**（沿用）。

## 验证方式

单测在 `tests/cli/`：

1. 每个命令的 `execute*`：注入假的 `UseCases`，断言调对了用例、参数解析对（逗号分隔的列表、`--stdin` 的 JSON、`i-` 开头判断灵感）。
2. `render*`：每个命令给人看的输出逐行断言（中英文混排对齐）。
