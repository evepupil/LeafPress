# 命令行 · 入口与命令

> 模块定位：`leafpress` 命令：给 agent 推进作品、加灵感、转作品，给作者初始化、体检、起本机服务、导出、装 skill · 对应代码：`src/cli/`、`src/assets/browser.ts` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基)（入口和输出约定）、[M1 底座](../roadmap.md#m1-底座)（新命令） · 状态：进行中（M1 改造） · 最近更新：2026-10-09

## 职责与边界

- 管：参数解析；把用例的结果变成给人看的中文或给 agent 读的 JSON；退出码；体检；装 skill；起本机服务。
- 不管：业务规则（全在 `UseCases`），命令里只组装和输出。

## 结构与数据流

| 文件 | 说明 |
|---|---|
| `main.ts` | 入口（第一阶段已有）：`buildProgram()`、`main(argv)`、统一错误处理和退出码。**每个命令的实现都用动态 import 按需加载**，`main.ts` 只登记命令名、参数和说明 |
| `context.ts` | `createCliContext(globalOptions, deps?)`：按需建数据目录路径、配置、`AppContext`（`openApp`）、`UseCases`（`createUseCases`）、找 Edge；`close()` 关闭 |
| `output.ts` | 显示宽度、截断、表格、JSON（第一阶段已有） |
| `commands/<命令>.ts` | 每组命令一个文件：`register(program, getContext)`、`execute*`（只返回数据）、`render*`（数据变成文字） |
| `commands/doctor.ts`、`doctor-inspections.ts` | 体检（第一阶段已有，按下面改） |

测试时 `createCliContext` 可以注入假的 `UseCases`。

### 全局约定（沿用第一阶段）

- 全局选项 `--home <目录>`、`--json`；`--version` 读 `package.json`。
- 退出码：成功 0；出错 1；用法错误 2（参数不对、`USAGE`）。用法错误的 message 写具体原因。
- 出错时给人看：标准错误两行「错误：<message>」「提示：<hint>」；`--json` 时标准输出 `{ "ok": false, "error": { code, message, hint } }`。
- 成功时 `--json` 输出 `{ "ok": true, ...结果 }`。
- 不是 `LeafPressError` 的异常：「内部错误：<message>」，hint「设置环境变量 LEAFPRESS_DEBUG=1 可以看到详细信息」。
- 用例的 `warn` 写到标准错误「注意：<内容>」（`--json` 时也写标准错误，不混进 JSON）。
- 只读命令（`works`、`work show`、`ideas`、`accounts`、`account show`、`doctor`）在数据目录或记录库还不存在时，不顺手建出来：`doctor` 照常体检，其余报 `USAGE`「还没初始化」，hint「先运行 leafpress init」。
- 命令结束前一定关闭记录库。

### 命令

| 命令 | 调用 | 给人看的输出 | `--json` |
|---|---|---|---|
| `init` | 建数据目录及 accounts、tasks、backups、logs；配置不存在写默认的，是第 1 版就 `upgradeLegacyConfig`；`openApp` 建库或升级 | 数据目录、配置文件、记录库三个路径；升级了就写「配置已升级，旧的备份在 …」「记录库已从第 1 版升到第 2 版，备份在 …」；最后一行「下一步：运行 leafpress serve 打开工作台」 | `{ ok, home, configFile, dbFile, configUpgraded, configBackup?, migration }` |
| `doctor` | 见下 | 三列表格「检查项 \| 状态 \| 说明」+ 修复建议 + 总结 | `{ ok, checks }` |
| `serve [--port <端口>] [--open] [--dev]` | `startServer` | 「LeafPress 已启动：http://127.0.0.1:3210/（按 Ctrl+C 停止）」；`--open` 时用系统浏览器打开（Windows：`cmd /c start "" <网址>`）。收到 Ctrl+C 时关掉服务再退出 | 启动后输出一行 `{ ok, url }`，进程继续运行 |
| `works [--status <状态,…>] [--account <账号>]` | `listWorks` | 按状态分组的表格「编号 \| 账号 \| 标题 \| 进度」，组标题「待实现（3）」；待实现按排队顺序；没有作品时一句「没有作品」 | `{ ok, works }` |
| `work show <作品>` | `showWork` | 原样输出 `detail.context` | `{ ok, detail }` |
| `work next [--account <账号>]` | `startNext` | 第一行 message；有令牌时第二行「令牌：<token>（推进这个作品时都要带 --lease <token>）」；空一行后输出 `detail.context`。没有能接的作品时一句「待实现里没有能接的作品」，退出码 0 | `{ ok, message, lease?, detail }`；没有时 `{ ok: true, detail: null }` |
| `work start <作品> [--force]` | `startWork` | 同 `work next` | 同上 |
| `work step <作品> --lease <令牌> [--force]` | `stepWork` | message；仍在进行中时加一行「租约续到 <月日 时分>」 | `{ ok, message, lease?, detail }` |
| `work run <作品> --lease <令牌>` | `runWork` | 同 `work step`；代码步骤出错时退出码 1（message 照样输出） | `{ ok, message, lease?, outcome, detail }`；出错时 `ok` 仍为 true、`outcome.kind` 为 fail |
| `work back <作品> <第几步> --lease <令牌>` | `backWork` | 同 `work step` | 同 `work step` |
| `work release <作品> --lease <令牌>` | `releaseWork` | 「已交还，回到待实现最前面」 | `{ ok, work }` |
| `work feedback <作品> <文字…>` | `submitFeedback` | 「已提交，回到待实现最前面」 | `{ ok, work }` |
| `work new --account <账号,…> --title <标题> [--brief <要求>]` | `createWorks`（来源 new） | 每个作品一行「已创建 <编号>（<平台> · <账号名>，<工作流名>）」 | `{ ok, works }` |
| `convert <灵感或作品> --to <账号,…> [--brief <要求>]` | `createWorks`（编号以 `i-` 开头是灵感，否则是作品；brief 不给就用 `defaultBrief`） | 同 `work new` | `{ ok, works }` |
| `ideas [--status <状态,…>]` | `listIdeas` | 表格「编号 \| 状态 \| 一句话 \| 来源」 | `{ ok, ideas }` |
| `ideas add <一句话> [--detail] [--account] [--source <来源>] [--source-detail]` | `addIdeas` | 「已加 <编号>」 | `{ ok, ideas }` |
| `ideas add --stdin` | 从标准输入读 JSON 数组，每项 `{ text, detail?, accountId?, source?, sourceDetail? }`，source 缺省 `batch` | 每条一行「已加 <编号>：<一句话>」 | `{ ok, ideas }` |
| `accounts` | `listAccounts` + 每个账号的 `setupView` | 表格「编号 \| 平台 \| 名称 \| 接入 \| 档案」，接入为接好了 / 有问题 / 没接完，档案为已写 / 没写 | `{ ok, accounts }` |
| `account show <账号>` | `showAccount` | 名称、平台、档案路径、接入状态、还缺什么（每条一行），空一行后输出档案全文（没写时「（档案还没写）」） | `{ ok, account, setup }` |
| `account add --platform <平台> --name <名称> [--intro <一句话>]` | `addAccount` | 「已添加 <编号>，档案在 <路径>」 | `{ ok, account }` |
| `data pull [--account <账号,…>]` | `pullData` | `note` | `{ ok, outcomes, note }` |
| `export` | `exportBackup` | 「已导出到 <文件夹>」 | `{ ok, dir }` |
| `skill install [--force]` | 把仓库里的 `skills/leafpress/` 复制到 `<用户目录>/.claude/skills/leafpress/`，以及 `CODEX_HOME`（缺省 `<用户目录>/.codex`）存在时的 `<CODEX_HOME>/skills/leafpress/`。目标已存在且不带 `--force` 时跳过并说明 | 每个目标一行「已装到 <路径>」或「已存在，加 --force 覆盖：<路径>」 | `{ ok, targets: [{ path, action }] }` |

参数校验：`--status` 只认 todo、doing、waiting、done（灵感是 inbox、promising、converted）；`<第几步>` 是正整数；`--platform` 只认四个平台编号；不认识的值报用法错误并列出可选值。

### 体检

| 编号 | 检查项 | 规则 |
|---|---|---|
| `node` | Node 版本 | 低于 24.2 为 error |
| `config` | 配置 | 不存在为 ok（说明「用默认配置」）；第 1 版为 warn（建议 `leafpress init` 升级）；校验不过为 error（照搬 message 和 hint） |
| `store` | 记录库 | `inspectStore(dbFile, MIGRATIONS.length)` 只读查看：不存在 warn（建议 init）；版本低 warn（下次运行会自动备份并升级）；版本高 error；正常时说明版本 |
| `home` | 数据目录 | 存在且可写为 ok；不存在 warn（建议 init）；不可写 error |
| `web` | 网页 | `web/out/index.html` 存在为 ok；否则 warn（「网页还没构建」，建议在仓库里运行 `pnpm --filter leafpress-web build`） |
| `skill` | LeafPress skill | `<用户目录>/.claude/skills/leafpress/SKILL.md` 存在为 ok，否则 warn（建议 `leafpress skill install`） |
| `browser` | 浏览器 | `locateEdge` 找到为 ok，否则 warn |

第一阶段的 `blog-repo`、`blog-site-url` 两项删掉（M2 接博客时改成按博客账号的配置项检查）。每一项各自捕获异常；任何说明和建议里都不出现密钥。

### 启动速度

agent 会频繁调用，启动要快：入口只加载 commander 和自己，命令的实现、zod、记录库、Hono 等都在用到时才 `import()`。验收时报两个数（`pnpm build` 之后，各跑 5 次取中位数）：`node dist/cli/main.js --version`、`node dist/cli/main.js work show <作品> --home <临时目录>`。第一阶段 `--version` 要 700 毫秒，目标是两者都在 400 毫秒以内；做不到就在回报里写清时间花在哪。

## 关键决策

1. **执行和显示分开**（沿用）：测试断言数据，输出格式改了不用改一堆测试。
2. **令牌明着给 agent**：只在接手时输出一次，后续命令必须带 `--lease`；丢了用 `--force` 接管。
3. **`work show` 输出的就是任务说明原文**：agent 看到的和任务文件夹里的 `作品.md`、网页的「复制给 AI」一字不差。
4. **命令按需加载**：一次调用只加载用到的模块，Windows 上读大量小文件很慢。
5. **体检不联网、不改任何东西**（沿用）。

## 验证方式

单测在 `tests/cli/`：

1. 每个命令的 `execute*`：注入假的 `UseCases`，断言调对了用例、参数解析对（逗号分隔的列表、`--stdin` 的 JSON、`i-` 开头判断灵感）。
2. `render*`：每个命令给人看的输出逐行断言（中英文混排对齐）。
3. 用法错误：缺参数、`--status` 值不对、`<第几步>` 不是正整数、`--stdin` 读到的不是 JSON 数组，退出码 2，message 写具体原因。
4. 只读命令在没初始化的数据目录上不建出文件。
5. doctor：用临时目录和注入的环境覆盖每一项的每个级别。
6. skill install：临时的用户目录里装、已存在跳过、`--force` 覆盖、没有 `.codex` 时只装一处。
7. **集成**（`tests/integration/cli-flow.test.ts`，用 `pnpm build` 后的 `dist/cli/main.js` 起子进程、临时数据目录）：`init` → `account add --platform zhihu --name 一叶之桐 --intro 写给开发者` → `ideas add 测试灵感` → `convert i-1 --to zhihu-1` → `work next --json` 拿到令牌 → 写 `稿子.md` 到任务文件夹 → `work step` → `works --json` 里是 waiting → `work feedback <编号> 发布了 https://zhuanlan.zhihu.com/p/1` → `work next` → `work run` → `work show --json` 里是 done、url 对。

`pnpm gate` 全部通过；回报里给出启动速度的两个数。
