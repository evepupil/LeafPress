# 平台接入 · 接入框架与博客

> 模块定位：平台登记表、博客接入（原稿来源）、知乎接入的能力声明、外部命令执行 · 对应代码：`src/platforms/`、`src/shared/exec.ts` · 所属里程碑：[M0 地基](../roadmap.md#m0-地基) · 状态：开发中 · 最近更新：2026-10-05

## 职责与边界

- 管：登记有哪些平台、查某平台某形态的能力；从博客仓库列出和读取原稿；把博客仓库安全地拉到最新；声明知乎支持的形态；执行外部命令（git）。
- 不管：改写、转换、发布（M1 起补）；写博客仓库（M3）。M0 对博客仓库只读，唯一会改动仓库的是「快进到远程」，而且只在条件完全满足时才做。

### 执行外部命令 `src/shared/exec.ts`

```ts
interface ExecOptions { cwd?: string; timeoutMs?: number; env?: NodeJS.ProcessEnv }
interface ExecResult { stdout: string; stderr: string; exitCode: number; timedOut: boolean }
type ExecFn = (command: string, args: readonly string[], options?: ExecOptions) => Promise<ExecResult>;
```

- 用 `child_process.execFile`，**不经过 shell**，`windowsHide: true`，输出按 utf8 解码，`maxBuffer` 16MB，缺省超时 30 秒。
- 命令以非零退出码结束：正常返回，`exitCode` 为实际退出码。超时：返回 `timedOut: true`、`exitCode: -1`。
- 命令本身找不到（ENOENT）：抛 `LeafPressError("EXTERNAL_TOOL_MISSING")`，message 为「找不到命令 git」这样的说明。

### 平台登记表 `src/platforms/registry.ts`

```ts
class PlatformRegistry {
  register(adapter: PlatformAdapter): void; // 编号重复抛 LeafPressError("INTERNAL")
  has(id: PlatformId): boolean;
  get(id: PlatformId): PlatformAdapter; // 不存在抛 PLATFORM_UNKNOWN，message 列出已登记的平台
  list(): readonly PlatformAdapter[]; // 按登记顺序
  capability(platform: PlatformId, format: FormatId): PlatformCapability; // 不支持抛 FORMAT_UNSUPPORTED
  publishTargets(options?: { excludePlatforms?: readonly PlatformId[] }): PublishTarget[];
}

function createDefaultRegistry(options: {
  blog: { repoPath: string; contentDir: string; remote: string; branch: string };
  exec?: ExecFn;
}): PlatformRegistry; // 依次登记博客、知乎
```

- `publishTargets` 按「平台登记顺序 → 该平台能力声明顺序」展开成发布目标，可以排除指定平台（发布状态总览要排除博客自己）。
- 以后加平台：写好接入，在 `createDefaultRegistry` 里加一行登记。这是加平台时唯一要改的现有代码。

### 博客接入 `src/platforms/blog/`

`createBlogAdapter({ repoPath, contentDir, remote, branch, exec })`：编号 `blog`，名字「博客」；能力只有长文（`titleRequired: true`、`supportsCodeBlocks: true`、`supportsMath: true`、`supportsMermaid: true`、`supportsExternalLinks: true`，发布方式 `["git"]`）；带原稿来源。

**目录与 ref**

- 原稿目录 = `<repoPath>/<contentDir>`，下面每个子目录是一个语言目录（现在是 `zh`、`en`）。
- 语言目录下直接放的 `.md`、`.mdx` 文件是原稿，不往更深的目录找。
- ref = `<语言目录>/<文件名去掉扩展名>`，比如 `zh/claude-code-rules`。
- 同一语言目录下 `x.md` 和 `x.mdx` 同时存在：两个都不收，记一条问题「同名文件重复」。

**元数据**（用 gray-matter 读，zod 校验，允许出现未列出的字段）

| 字段 | 规则 | 规整后 |
|---|---|---|
| `title` | 非空字符串，必填 | 原样 |
| `description` | 字符串，可选 | 原样 |
| `published` | 必填；字符串或日期对象（YAML 里不加引号的日期会被解析成日期对象） | `YYYY-MM-DD`：日期对象取 UTC 日期；字符串必须以 `YYYY-MM-DD` 开头，取前 10 位 |
| `updated` | 可选，规则同 `published` | `YYYY-MM-DD` |
| `locale` | 非空字符串，必填 | 原样，比如 `zh-CN`、`en` |
| `tags` | 字符串数组，可选 | 缺省 `[]` |
| `draft` | 布尔，可选 | 缺省 `false` |
| `translationKey` | 字符串，可选 | 原样 |
| `source` | 字符串，可选 | `"notion"` 时 origin 为 `notion`，否则为 `repo` |

校验不过的文件不进列表，记一条问题：`{ path, message }`，message 写明哪个字段有什么问题，比如「published：不是 YYYY-MM-DD 日期」。

**`list()`**：返回全部语言目录的原稿摘要，按 `publishedAt` 倒序、同日按 ref 升序；`contentHash` 是文件原始字节的 sha256，`path` 是绝对路径；读不了的文件同样记问题，不抛错。原稿目录本身不存在时抛 `BLOG_REPO_INVALID`，hint 提示检查配置里的 `blog.repoPath` 和 `blog.contentDir`。

**`read(ref)`**：

- ref 必须形如 `语言目录/文件名`：只含一个 `/`，不含 `\`、`..`，解析后的路径必须落在原稿目录里；不合法或文件不存在都抛 `SOURCE_NOT_FOUND`。
- 先找 `.mdx` 再找 `.md`。元数据校验不过抛 `SOURCE_INVALID`。
- 返回 `ParsedSource`：摘要字段同 `list()`，另加 `description`、`body`（去掉元数据后的正文，原样）、`frontmatter`（原始元数据）、以及 `analyzeBody` 的结果。

**`analyzeBody(markdown)`**（`unified` + `remark-parse` + `remark-gfm` 解析，`unist-util-visit` 遍历）：

| 结果 | 规则 |
|---|---|
| `images` | `image` 节点的地址；`imageReference` 按同文的 `definition` 解析出地址；HTML 片段里 `<img ... src="...">` 的地址。按出现顺序，重复的也保留 |
| `mermaidBlockCount` | 语言标记为 `mermaid` 的代码块个数 |
| `internalLinks` | `link` 节点里的站内地址：以 `/` 开头但不是 `//`；或者不带协议（不匹配 `^[a-zA-Z][a-zA-Z0-9+.-]*:`）、不以 `#` 开头、不以 `//` 开头的相对地址。引用式链接按 `definition` 解析。图片地址不算链接 |

正文里的 MDX 组件、`import` 语句不需要理解，解析时不能报错即可。

**`sync()` 拉到最新**（全部用 `exec` 调 git，git 命令统一加 `-c core.quotepath=false`）：

1. 读当前分支；不是配置的分支 → `failed`，message「当前在分支 X，配置的是 Y，没有拉取」。
2. `git fetch <remote> <branch>`，超时 60 秒；失败或超时 → `failed`，message 附 stderr 第一行，**先把网址里的账号口令抹掉**（`https://用户:口令@` 改成 `https://<redacted>@`）。
3. 用 `git rev-list --left-right --count HEAD...<remote>/<branch>` 算出本地多几个（ahead）、少几个（behind）。
4. 判定：都为 0 → `up-to-date`；ahead 和 behind 都大于 0 → `skipped-diverged`；只有 ahead 大于 0 → `skipped-ahead`；只有 behind 大于 0 时，工作区有已跟踪文件的改动（`git status --porcelain --untracked-files=no` 有输出）→ `skipped-dirty`，否则执行 `git merge --ff-only <remote>/<branch>`，成功 → `fast-forwarded`，失败 → `failed`。
5. 返回的 `behindBefore`、`aheadBefore` 是第 3 步的数字。除第 4 步的快进外，任何情况都不改动仓库。

**`readRepoStatus(exec, repoPath, remote, branch)`**（给体检命令用，不联网）：返回 `{ isRepo, branch?, dirty, hasUpstream, ahead, behind }`，ahead/behind 按本地已有的远程跟踪分支算；不是 git 仓库时 `isRepo: false`，其余字段取默认值，不抛错。

## 关键决策

1. 博客接入读的是仓库文件，不读线上网站：原稿以仓库为准，Notion 写的文章同步后也在仓库里。
2. 拉取只做快进：有改动、有未推送提交、分叉，一律不动仓库，只报告，避免弄乱作者的博客仓库。
3. 外部命令不经过 shell：参数原样传递，路径里有空格、中文都不会出问题，也没有注入风险。
4. 知乎 M0 只声明能力，发布状态总览就能先显示「知乎·长文」「知乎·回答」两列；以后加平台，列会自动多出来。

## 验证方式

单测放在 `tests/platforms/`、`tests/shared/`，全部在临时目录里造数据，不碰真实博客仓库：

1. `execCommand`：正常命令、非零退出码、超时、命令不存在。
2. 登记表：重复登记报错、未知平台、不支持的形态、发布目标的展开顺序和排除。
3. 用临时目录造一个博客：`zh/` 和 `en/` 各几篇，覆盖 `.md` 和 `.mdx`、Notion 来源、加引号和不加引号的日期、缺 title、日期写错、同名 `.md` / `.mdx` 重复。验证 `list()` 的条目、排序、问题列表，`read()` 的各个字段。
4. `analyzeBody`：普通图片、引用式图片、HTML 图片、流程图、站内链接（绝对、相对、引用式）、外链、锚点、`mailto:`、带 MDX 组件和 `import` 的正文。
5. ref 不合法：`../x`、`zh/../../x`、`zh\\x`、缺语言目录、文件不存在，都抛 `SOURCE_NOT_FOUND`。
6. `sync()` 用真实 git 在临时目录造「远程裸仓库 + 本地克隆」：落后 → 快进；最新；有改动 → 不动；有未推送提交 → 不动；分叉 → 不动；远程目录被删掉导致拉取失败 → `failed` 且不动仓库；当前分支不对 → `failed`。每种情况都断言仓库的 HEAD 是否符合预期。
7. 网址里的账号口令被抹掉（直接测抹除函数）。

`pnpm gate` 全部通过。
