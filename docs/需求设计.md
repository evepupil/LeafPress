# 需求设计

> 状态：已定稿 · 最近更新：2026-10-05 · 下游：[功能清单](功能清单.md) · [技术设计](技术设计.md) · [架构设计](架构设计.md) · [roadmap](roadmap.md)

## 一句话定位

给独立开发者自己用的本地内容工作台：把日常开发变成素材，把一份原稿改成多个平台、多种形态的版本，降低持续产出内容的成本。

## 背景

现在的做法：

- 知乎是主阵地，博客（`C:\code\yeton-blog`）沉淀长文。博客 39 篇中文文章里有 22 篇是在 Notion 写好、同步进博客仓库的。
- 已有三个零件：知乎写作 skill、知乎官方发布 skill、博客问题复盘 skill。它们各管一段，彼此不连。

痛点：

| 痛点 | 具体表现 |
|---|---|
| 不知道写什么 | 素材散在各个项目的进度记录、review 记录、提交记录里，要写时得回忆、翻找 |
| 写东西累 | 每篇都从空白页开始 |
| 一份力气只发一个地方 | 博客文章不会再去知乎，换来的曝光只有一份 |
| 发了没人看 | 不知道哪类内容有效，下一篇也就没有方向 |

调研结论见 [独立开发者自媒体开源工具调研](调研/独立开发者自媒体开源工具调研.md)。

## 谁在用

| 角色 | 怎么用 | 要什么 |
|---|---|---|
| 作者 | 在 Claude Code 里说话发起：定题、写稿、转写、登记 | 操作少；发之前能过目；账号不出事 |
| Claude Code | 跑改写、出题、采访这些需要判断的步骤 | 清楚的任务说明和规则文件 |

## 名词解释

| 词 | 意思 |
|---|---|
| 作品 | 一个选题最后产出的全部内容，包含原稿、素材资产和各平台版本 |
| 原稿 | 作品的权威版本。首版是博客仓库里的一篇文章，以后也可以是一段视频母版 |
| 形态 | 内容在平台上的样子：长文、回答、短帖、图文卡片、横版视频、竖版视频 |
| 版本 | 原稿改成某个平台、某种形态后的稿子，比如「知乎回答版」 |
| 资产 | 作品用到的文件：图片、流程图、封面、视频、字幕、音频 |
| 平台接入 | 对一个平台的统一封装：能发哪些形态、各有什么限制、原稿怎么转、怎么发、怎么拉数据 |
| 发布方式 | 内容送上平台的途径：官方接口、交给其他 skill、交给外部命令行工具、写进 git 仓库、生成成品由作者手动发 |
| 素材 | 从项目记录里收来、可能值得写的片段 |
| 题单 | 根据素材和平台上的问题整理出的一批候选选题 |
| 工作流 | 一串固定步骤，中间可以停下来等 AI 或等作者，停多久都能接着跑 |

## 需求点

### 1 一稿多用

- 1.1 从原稿生成目标平台、目标形态的版本。首版做博客文章转知乎文章、知乎回答
- 1.2 改写遵循作者的文风和去 AI 味规则，出稿后自查并标出可疑的句子
- 1.3 固定的转换自动完成：流程图转图片、站内链接补成完整网址、文末附原文链接
- 1.4 发布前给作者预览，作者确认后才发
- 1.5 平台没有接口的形态，生成能直接粘贴的成品，作者发完回填链接

### 2 选题与素材

- 2.1 从作者指定的项目里收集新增的进度记录、review 记录、提交记录，再加上 CloudMind 里的近期记忆
- 2.2 按需生成题单，每题附上素材来源，以及平台上对得上的问题
- 2.3 开发中能随手记一笔，进入素材池
- 2.4 选中的题能直接开写，可以选采访模式，写成博客原稿

### 3 记录与数据

- 3.1 记录每个版本的状态和每次发布（平台、形态、链接、时间），防止重复发
- 3.2 以后定期拉平台数据，回看哪类内容有效，反过来影响题单

### 4 平台扩展

- 4.1 平台接入统一封装。加一个新平台只需要加一个接入，工作流不改
- 4.2 内容模型同时容纳图文和视频：视频母版、封面、字幕都按资产处理
- 4.3 发布方式可以插拔：官方接口、交给 skill、交给外部命令行、写 git 仓库、手动
- 4.4 平台顺序：知乎和博客 → 小红书图文卡片 → B站等视频平台

## 非功能要求

| 方面 | 要求 |
|---|---|
| 运行环境 | Windows 本机，Node 24，在 Claude Code 里使用 |
| AI 成本 | AI 步骤在 Claude Code 里跑，用现有订阅；首版不直接调大模型接口 |
| 密钥 | 只放在本地配置文件或知乎官方的共享凭证文件里，不进仓库，不在任何输出里打印 |
| 隐私 | 素材收集和发布前都做脱敏检查，抹掉密钥、内部地址、他人信息 |
| 账号安全 | 首版不做模拟浏览器发布；所有发布都要作者确认 |
| 数据位置 | 个人数据放在用户目录 `~/.leafpress/`，代码仓库里不放，按能开源的标准写 |
| 平台规则 | 发布时不勾选知乎的「包含 AI 辅助创作」声明。这是作者的决定，风险说明见调研报告第六节 |
