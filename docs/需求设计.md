## 一句话定位

一个人做多个自媒体账号的本机工作台：灵感变成各平台的作品任务，AI 按工作流去做，要人动手时停下来等你，数据每天自动拉回来客观地看。

## 背景

现在的做法：

- 知乎「一叶之桐」是主阵地，博客（`C:\code\yeton-blog`）沉淀长文，B站、小红书在筹备。
- 已有的零件：知乎写作 skill（含复制页和禁用词）、博客问题复盘 skill、DeverDesk（用户自己的一人公司工作台）。知乎官方发布凭证一直没批。
- 第一阶段做了命令行地基（记录库、工作流框架、博客读取、体检），按旧定位设计。

痛点：

| 痛点 | 具体表现 |
|---|---|
| 不知道在做什么 | 几个号、几条线各管各的，没有一处能看全：哪些在写、哪些等我、哪些发了 |
| 一份力气只发一个地方 | 博客文章不会再去知乎、小红书、B站 |
| AI 能干的活还得我盯着 | 每次都要重新交代上下文；换一个 agent 就接不上 |
| 要人动手的环节散 | 去知乎投递、校对字幕、确认大纲，做完没地方记，AI 也不知道做完没 |
| 数据看不全 | 各平台后台各看各的，拉数据靠手，周报靠回忆 |

## 谁在用

| 角色 | 怎么用 | 要什么 |
|---|---|---|
| 作者 | 在网页上记灵感、转作品、处理「等你处理」、看数据和周报；让 AI 干活都在 agent 里说（「做一下 z-jev」「继续」），网页上不设「让 AI 做」按钮 | 心智负担低；要自己动手的地方一眼看到、照着做完写一句就行 |
| agent（Claude Code、Codex 等） | 用 LeafPress 命令行读待做、接手一个作品、按工作流做、写产出到任务文件夹、该停就停 | 一个作品的上下文全在一处：要求、步骤、账号档案、来源、产出、你的反馈 |
| 定时任务 | 能用代码做的（拉作品数据）用电脑的计划任务跑；要 AI 判断的（跑灵感）用 AI 工具自带的定时任务跑 | 电脑开着就自己跑，错过了下次补 |

## 名词解释

| 词 | 意思 |
|---|---|
| 灵感 | 一句话的选题想法，带细节；来自随手记、AI 批量写入、定时跑灵感 |
| 作品 | 一个平台上的一份内容，也是一条任务。一个作品只对应一个账号（一个平台） |
| 转作品 | 灵感或已发作品选几个平台，就生成几个作品；工作流按「平台 + 来源」自动配 |
| 工作流 | 把一个作品做出来并发出去的一串步骤，步骤分三种：AI、自动（代码做）、你来 |
| 作品状态 | 待实现（AI 的待做，按先后排队）、进行中、等你处理、已完成 |
| 要你做的事 | 走到「你来」的步骤时，写给作者的一段话；作者做完在反馈框写一句 |
| 任务文件夹 | 每个作品一个文件夹，放要求、步骤状态、中间产物、要你做的事、你的反馈、记录；任何 agent 读它就能接手 |
| 账号档案 | 一份随便写的 Markdown：定位、写给谁、文风、禁用词、对标、目标……agent 写稿前整份读 |
| 接入 | 让一个账号能用起来要做的事：作品产出的工作流、数据获取的工具、这个号要配的东西 |
| 数据项 | 一个平台作品的数据，各平台不一样（知乎浏览、点赞、收藏、评论、分享；博客访问、访客、评论……）；第一项是主数据 |
| 定时工作流 | 不针对某个作品、按时自己跑的流程：拉作品数据、跑灵感、周报 |

## 需求点

### 1 作品与任务

- 1.1 作品即任务，四个状态：待实现、进行中、等你处理、已完成；待实现按先后排队，agent 从上往下挑
- 1.2 一个作品只对应一个平台；转作品选几个平台生成几个作品
- 1.3 工作流按「平台 + 来源」自动配，还没开始做时能换成同平台的别的工作流
- 1.4 走到「你来」的步骤停在等你处理，页面上写要你做的事；你在反馈框写一句（例如「发布了，链接是 …」）
- 1.5 提交反馈后回到待实现最前面，等 agent 继续；agent 读反馈，把链接归档，标记完成
- 1.6 每个作品一个任务文件夹，中间状态和产物都放这里，换哪个 agent 都能接着做
- 1.7 作品能编辑：标题、要求、工作流、链接；看板能拖动换列、排先后
- 1.8 已发作品能再转到别的平台（例：博客文章转知乎，新作品的来源就是这篇博客）
- 1.9 已发的博客文章一次导入成作品

### 2 灵感

- 2.1 随手记一句话，可挂到账号
- 2.2 AI 批量写入（agent 用命令行加）
- 2.3 定时跑灵感（按需，不一定要）：要的话用 AI 工具自带的定时任务跑，扫开发记录、CloudMind 记忆、热点，放进收件箱
- 2.4 灵感能编辑、拖动（收件箱、值得写、已转作品）
- 2.5 转作品时选平台，一转多

### 3 账号

- 3.1 账号档案是一份 Markdown，页面上能改；agent 写稿前整份读
- 3.2 接入：作品产出的工作流、数据获取的工具、要配的东西（页面上能填），状态分接好了、有问题、没接完
- 3.3 按平台一个一个接；加账号要填什么，接这个平台时才定

### 4 数据与周报

- 4.1 数据靠工具每天定时拉，用电脑的计划任务跑；不做手填；没有官方接口的平台到时候看情况做工具
- 4.2 各平台按自己的数据项存和显示；数据还没接的号显示「—」
- 4.3 客观显示：走势（粉丝、浏览、互动、发布）、分账号、作品排行
- 4.4 周报：客观小结、分账号、这周发的、我的复盘、往期
- 4.5 不设目标、不分栏目、不给建议；要分析让 AI 用工具拉数据自己分析

### 5 agent 接入

- 5.1 命令行：列待做、看一个作品的完整上下文、接手、做完一步、停下等你、完成、加灵感、转作品
- 5.2 LeafPress skill：教 agent 怎么用这些命令按工作流做事
- 5.3 网页上「复制给 AI」：复制一个作品的完整说明（含账号档案）；不做「让 AI 做」按钮，AI 都在 agent 里发起
- 5.4 MCP（让 agent 直接调用的接口）以后做

### 6 平台（每个平台都包括作品产出工作流、数据获取工具、账号配置）

- 6.1 博客：写稿（中英文）、过博客门禁、推送发布；数据只走 Umami（访问、访客）
- 6.2 知乎：博客转知乎、知乎写作（复制页 + 你去投递）、以后转知乎回答；数据怎么拿接知乎时再定（候选：知乎数据开放平台）
- 6.3 小红书：转卡片（要点 → 卡片图 → 文案 → 你在手机上发）；数据怎么拿接小红书时再定
- 6.4 B站：录屏成片（脚本 → 你录屏 → 自动剪辑和字幕 → 你校对 → 出横版竖版 → 投稿）；数据怎么拿接 B站时再定

## 非功能要求

| 方面 | 要求 |
|---|---|
| 运行环境 | Windows 本机，Node 24；网页在本机浏览器里用。手机上看以后用 Cloudflare Tunnel 加登录保护开放出去 |
| AI 成本 | AI 步骤在 agent（Claude Code、Codex）里跑，用现有订阅；LeafPress 自己不直接调大模型接口 |
| 密钥 | 只放在本机配置或凭证文件里，不进仓库，任何输出都不打印；页面上只显示「已配置」 |
| 隐私 | 个人数据放用户目录 `~/.leafpress/`；代码仓库按能开源的标准写 |
| 账号安全 | 发布都由作者确认或作者自己动手；博客例外：写完过了博客门禁就直接推送上线（用户 2026-10-09 定）。读数据的工具只读、低频（每天一次） |
| 可接手 | 任何 agent 只靠命令行和任务文件夹就能接着做，不依赖某次对话的上下文 |
| 平台规则 | 发布时不勾选知乎的「包含 AI 辅助创作」声明（作者的决定，风险见调研报告） |
