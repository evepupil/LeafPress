## 总体结构

```
┌──────────────────────────── 你的电脑 ────────────────────────────┐
│                                                                  │
│  ① 网页（浏览器打开 localhost:3210）     ⑥ agent（Claude Code、Codex）│
│         │  数据接口 + 每 2 秒问一次变更序号        │ + ⑦ LeafPress skill │
│         ▼                                         ▼              │
│  ② 本机服务 `leafpress serve`            ③ 命令行 `leafpress work …` │
│         │                                         │              │
│         └──────────────┬──────────────────────────┘              │
│                        ▼                                         │
│               ④ 用例（转作品、接手、推进、反馈、拉数据、周报）      │
│                        │            ╲                            │
│                        ▼             ╲                           │
│               ⑤ 共享规则（纯函数）     ⑧ 平台适配（博客、知乎……）   │
│                                      │ 工作流定义、自动步骤、数据工具 │
│                        ▼             ▼                           │
│  ⑨ 数据目录 ~/.leafpress：记录库、任务文件夹、账号档案、配置和凭证   │
│                        ▲                                         │
│  ⑩ Windows 计划任务 ──► `leafpress data pull`（每天）              │
│  ⑪ AI 定时任务（codeg 自动任务）──► agent 跑灵感                  │
└──────────────────────────────────────────────────────────────────┘
         ⑫ 手机：Cloudflare Tunnel + Access 登录保护（以后做）
```

1. **网页**：原型升级来的工作台。所有数据从本机服务取，改动都调接口；每两秒问一次变更序号，有变化才重新取，所以 agent 在命令行改了状态，网页几秒内就跟着变。没有「让 AI 做」按钮。
2. **本机服务**：一个 Node 进程，托管网页的静态文件，提供数据接口，只在本机能访问。不常驻也没关系：只有开网页时才需要它。
3. **命令行**：给 agent 和作者用。列待做、看一个作品的完整上下文、接手、做完一步、停下等你、反馈、完成、加灵感、转作品、拉数据。每个命令都能输出 JSON。
4. **用例**：一件业务一个用例，命令行和本机服务共用。用例负责组合规则、记录库和平台适配，并在改完记录库后更新任务文件夹里的说明文件。
5. **共享规则**：纯函数，网页也引用（用来显示进度文字、步骤状态、接入状态这类）。改状态的规则只有一份。
6. **agent**：作者在 agent 里说「看看有哪些待实现的」「做一下 z-jev」「z-design-extraction 我发好了，继续」。agent 用命令行接手，按工作流做，把产出写进任务文件夹。
7. **LeafPress skill**：教 agent 这套做法：先读上下文和账号档案，做 AI 步骤时用对应的 skill（知乎写作 skill、博客问题复盘 skill……），自动步骤调命令行执行，遇到「你来」就停，读到反馈再接着做。
8. **平台适配**：每个平台一个目录，放代码步骤的实现（读原稿、生成复制页、跑门禁、推送）和拿数据的工具（博客走 Umami）。平台和工作流的定义（步骤、产出、要你做的事、数据项、这个平台的账号要配的东西）是静态数据，放在共享规则包的平台目录和工作流目录里，网页和命令行直接用；加账号和接入里要填的就是平台目录里的配置项。另有一个通用工作流（AI 按要求和账号档案写稿 → 你去发 → 归档链接），任何平台都能用；自动配工作流时，平台还没有专用的就配它。
9. **数据目录**：记录库是唯一的事实来源；任务文件夹是它的镜像加产出；账号档案是 Markdown 文件。
10. **Windows 计划任务**：每天定时跑 `leafpress data pull`；电脑关机错过的，下次开机补。
11. **AI 定时任务**：要 AI 判断的定时活（跑灵感），用 AI 工具自带的定时任务起一个 agent 跑：codeg 自动任务每天 07:30 起 agent，照 skill 的「跑灵感」做；找候选、去重、排序由命令行的代码做，agent 只挑和写理由（M4，见 [灵感 · 跑灵感](模块设计/灵感-跑灵感.md)）。
12. **手机访问**：以后用 Cloudflare Tunnel 把本机服务开出去，前面加 Access 登录保护。

## 分层

| 层 | 代码 | 模块 | 职责 | 可以依赖谁 |
|---|---|---|---|---|
| 界面 | `web/` | 页面、组件、数据钩子 | 显示和交互，调接口 | 共享规则（只用来显示） |
| 入口 | `src/server/`、`src/cli/` | 接口路由、子命令 | 解析请求和参数，调用例，输出 | 用例、配置 |
| 用例 | `src/usecases/` | 作品、灵感、账号、数据、周报、复盘 | 一件业务一个用例，事务和租约在这里 | 共享规则、记录库、文件、平台适配 |
| 共享规则 | `packages/core/` | 类型、平台和工作流目录、作品、灵感、接入、数据、任务说明、Markdown | 纯函数：状态怎么变、怎么算；静态的定义 | 无 |
| 平台适配 | `src/platforms/<平台>/` | 代码步骤、拿数据的工具 | 跟某个平台有关、要跑命令或联网的实现 | 共享规则、文件、外部命令 |
| 存储 | `src/store/`、`src/files/` | 记录库、任务文件夹、账号档案、导出 | 读写，不做业务判断 | 共享规则（只用类型） |
| 基础 | `src/config/`、`src/schedule/`、`src/shared/` | 配置和凭证、计划任务、路径日志错误、执行外部命令 | 和业务无关的公共件 | 无 |

## 数据模型

```
账号 1 ─── n 作品 n ─── 1 工作流（按平台和来源自动配，定义在共享规则包的工作流目录里）
  │          │ 来源：灵感 / 另一个作品 / 导入 / 直接新建
  │          ├─ 记录（时间 + 一句话）
  │          ├─ 数据快照（每天，按平台数据项）
  │          └─ 任务文件夹（说明文件 + 产出）
  ├─ 档案（Markdown 文件）
  ├─ 配置项（非密钥进记录库，密钥进凭证文件）
  └─ 数据快照（每天：粉丝、主数据、互动、发布数）

灵感 1 ─── n 作品（转作品一转多）
复盘笔记（每周一条）
拉取记录（每次拉数据：哪个号、成功还是失败、原因）
变更序号（每次改数据加一，网页靠它知道要不要重新取）
```

- 一个作品只对应一个账号，平台由账号决定。
- 作品的数据按平台的数据项存（键是数据项，值是数字）；主数据是平台数据项的第一项。
- 工作流定义不进记录库：它是代码的一部分，随版本走；记录库里只记作品用的是哪个工作流、走到第几步。

## 主流程

### 一个作品从灵感到归档

```
网页：灵感 ──转作品（选知乎、博客）──► 作品 z-101（知乎写作）、b-102（博客写稿），都在待实现
                                              │
agent：「看看有哪些待实现的，挑第一个做」      ▼
  leafpress work next --json ─────────► 接手 z-101（拿到租约），状态 → 进行中
  leafpress work show z-101 ──────────► 上下文：要求、步骤、账号档案、任务文件夹位置
  AI 步骤「出大纲」：用知乎写作 skill，写 大纲.md 到任务文件夹
  leafpress work step z-101 ──────────► 记下这一步做完；下一步是「你确认大纲」→ 等你处理
                                              │
网页：等你处理 ──你看大纲，在反馈框写「可以」──► 回到待实现最前面
                                              │
agent：「z-101 我看过了，继续」                ▼
  leafpress work next / work show ───► 读到你的反馈，把你那一步记为完成，接着往下
  AI 步骤「写全文」→ 自动步骤「自查」「生成复制页」（leafpress work run z-101 执行）
  下一步「你去知乎投递」→ 等你处理（要你做的事里写好复制页的路径）
                                              │
网页：你投递完，写「发布了，链接是 https://…」──► 回到待实现最前面
agent：「继续」──► 自动步骤「归档链接」：从反馈里取链接 ──► 已完成
```

### 每天拉数据

```
Windows 计划任务 06:00 ──► leafpress data pull
   │ 对每个接了数据的账号：
   ├─ 拉数据要的配置没配好（密钥过期等）──► 记一条失败，原因写清，提醒里出现
   ├─ 调数据工具（博客：Umami）──► 账号当天的数和每个作品的数，按平台数据项存成快照
   └─ 还没接数据的账号 ──► 跳过
网页：走势、分账号、排行、周报都从快照算；提醒里显示拉取失败
```

## 状态流转

### 作品

```
                  转作品 / 新建
                       ▼
 ┌──────────────► 待实现 ◄──────────────── 你提交反馈（排到最前面）
 │                 │  ▲                          ▲
 │ 挪回待实现      │  │ 挪回                      │
 │                 ▼  │                          │
 │   agent 接手 ──► 进行中 ──走到「你来」的步骤──► 等你处理
 │                 │                              │
 │                 └──走完最后一步──► 已完成 ◄──拖到已完成（你自己做完的）
 │                                     ▲
 └─────────── 等你处理也能挪回待实现 ───┘
```

- 已完成的作品不能挪回去；要再发别的平台就「转作品」。
- 待实现里挪到「进行中」只表示有 agent 在做；网页上不能直接把作品拖进进行中（没有让 AI 做的按钮）。

### 灵感

```
收件箱 ⇄ 值得写 ──转作品──► 已转作品（还能再转到别的平台）
```

### 数据获取（每个账号）

```
还没接（工具没做）── 接上 ──► 正常 ⇄ 拉取失败（原因：配置过期、接口出错……）
```

### 接入（每个账号，算出来的，不存）

- 有问题：数据拉取失败，或有配置已过期
- 没接完：还没有这个平台专用的产出工作流（只能先用通用工作流）、拿数据的工具还没做、有配置没填
- 接好了：以上都没有

## agent 和命令行怎么配合

| 命令 | 干什么 |
|---|---|
| `leafpress works [--status todo]` | 列作品，待实现按排队顺序 |
| `leafpress work next` | 挑待实现里排最前、工作流能用的一个，接手 |
| `leafpress work show <作品>` | 完整上下文：要求、来源、步骤勾选、要你做的事、你的反馈、任务文件夹、账号档案 |
| `leafpress work start <作品>` | 接手指定的作品 |
| `leafpress work step <作品>` | AI 步骤做完了，记下产出，往下走；下一步要你动手就停在等你处理 |
| `leafpress work run <作品>` | 执行当前的自动步骤（生成复制页、跑门禁、推送、归档链接） |
| `leafpress work feedback <作品> <文字>` | 提交反馈（网页上也能做） |
| `leafpress work release <作品>` | 交还租约（agent 中途停下时） |
| `leafpress ideas add` / `ideas list` | 加灵感（可以一次加多条）、列灵感 |
| `leafpress convert <灵感或作品> --to <账号,…>` | 转作品 |
| `leafpress accounts` / `account show <账号>` / `account add` | 列账号、读账号档案、加账号 |
| `leafpress data pull [--account]` | 拉一次数据 |
| `leafpress serve` | 起本机服务，打开网页 |
| `leafpress schedule install / remove / status` | 管 Windows 计划任务 |

- 每个作品同一时刻只有一个 agent 能推进：接手时拿租约，做的过程中续约，停下或做完时交还。
- 任务文件夹里的 `作品.md`、`状态.json`、`要你做的事.md`、`你的反馈.md`、`记录.log` 由用例写，agent 只读；产出文件（大纲、改写稿、复制页……）由 agent 和自动步骤写。

## 出错与恢复

- **agent 中途断了**：作品停在进行中，租约到期后别的 agent 可以接手；`work show` 会写明上次做到哪一步、产出文件有哪些。
- **步骤可以重复跑**：自动步骤先写临时文件，成功后再改名；跑一半断掉不会留下半截文件。
- **反馈不丢**：反馈先进记录库再写文件；agent 接手时从记录库读。
- **不重复归档**：已完成的作品不能再完成一次；链接从反馈里取不到时停在等你处理，请你补链接。
- **拉数据失败不影响别的号**：一个号失败只记这个号的失败和原因，其余照常入库；提醒里能看到，修好配置后「现在拉一次」或等下次定时。
- **两边同时写**：命令行和本机服务都用短事务写记录库（开启 WAL，读写不互相卡住）；改作品状态前先核对租约和当前状态，对不上就拒绝并说明原因。
- **记录库升级前先备份**：表结构按版本号升级，升级前用 SQLite 自带的一致性复制（`VACUUM INTO`）备份到 `backups/`。
- **本机服务重启不丢东西**：服务本身不存状态，所有状态都在记录库和数据目录里。
- **外部依赖缺失说清楚怎么修**：Edge 找不到、Umami 密钥过期、博客仓库路径不对，`leafpress doctor` 都能查出来，对应步骤失败时直接给出修复办法。

## 扩展点

| 以后要加 | 改哪里 |
|---|---|
| 新平台（小红书、B站） | 共享规则包的平台目录里补上它的配置项和数据工具说明、工作流目录里加它的工作流；`src/platforms/` 加一个目录放代码步骤和数据工具的实现，在登记表里登记；网页和命令行不用改 |
| 新工作流（比如博客转知乎回答） | 工作流目录里加定义（自动配按平台和来源挑，不用另写规则）；平台目录里加它的代码步骤 |
| 新的数据工具（比如读创作中心） | 平台目录里加一个数据工具，实现「拉账号数」和「拉作品数」两个动作 |
| 定时跑灵感 | 写一个跑灵感的 skill，用 AI 工具的定时任务起 agent，结果用 `ideas add` 写进来（M4 照此做，另加 `ideas gather` 用代码找候选；新来源加在 `gatherIdeas` 里） |
| MCP | 新加一个入口，和命令行一样调用例 |
| 手机访问 | Cloudflare Tunnel 指到本机服务，加 Access 登录保护；本机服务不用改 |
