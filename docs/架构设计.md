# 架构设计

> 状态：已定稿 · 最近更新：2026-10-05 · 上游：[需求设计](需求设计.md) · [技术设计](技术设计.md) · 下游：[roadmap](roadmap.md)

## 总体结构

```
                     作者：在 Claude Code 里说一句话
                                   │
             ┌─────────────────────▼─────────────────────┐
             │ ① skill 层：听懂要干什么，承担所有 AI 步骤     │
             └──────────┬──────────────────────┬─────────┘
                        │ 调 leafpress 命令      │ 交接
             ┌──────────▼──────────┐   ┌───────▼────────────────┐
             │ ② 命令行层            │   │ ⑨ 外部发布工具            │
             └──────────┬──────────┘   │ 知乎官方 skill；以后 biliup │
                        │              └────────────────────────┘
             ┌──────────▼──────────┐
             │ ③ 工作流层            │
             └──┬───────┬───────┬──┘
                │       │       │
     ┌──────────▼─┐ ┌───▼─────┐ ┌▼──────────┐
     │ ④ 平台接入   │ │ ⑥ 资产处理 │ │ ⑦ 素材收集   │
     └──────┬─────┘ └───┬─────┘ └┬──────────┘
     ┌──────▼─────┐     │        │
     │ ⑤ 发布方式   │     │        │
     └──────┬─────┘     │        │
            └───────────┼────────┘
             ┌──────────▼──────────┐
             │ ⑧ 记录库与内容模型     │
             └─────────────────────┘
```

1. **skill 层**：作者说「把这篇发知乎」「这周写什么」「记一下」，skill 判断该走哪条工作流，调用命令行；遇到 AI 步骤（改写、出题、采访、挑问题），由 skill 自己完成，再把结果交回命令行。
2. **命令行层**：`leafpress` 的各个子命令。只做参数解析和输出，每个命令都能输出 JSON 给 skill 读。
3. **工作流层**：把一件事拆成固定步骤，记住走到了哪一步。遇到要等 AI、等作者、等外部工具的步骤就停下，之后从停下的地方接着跑。
4. **平台接入**：每个平台一份封装，回答四个问题：支持哪些形态、每种形态有什么限制、原稿怎么转成这个平台的样子、用哪种发布方式、能不能拉数据。
5. **发布方式**：把成品送上平台的几种途径，平台接入从里面挑。
6. **资产处理**：图片、流程图、封面、卡片图、视频、字幕这些文件的生成和转换。
7. **素材收集**：扫作者指定的项目，收新增的记录。
8. **记录库与内容模型**：全部数据的形状和存取，其他层都依赖它。
9. **外部发布工具**：别人维护的发布工具，LeafPress 只负责交稿和读结果。

## 分层

| 层 | 代码 | 职责 | 可以依赖谁 |
|---|---|---|---|
| skill | `skills/` | 识别意图、跑 AI 步骤、和作者对话 | 命令行（通过调用命令） |
| 命令行 | `src/cli/` | 参数解析、输出 | 工作流、记录库（只读查询）、配置 |
| 工作流 | `src/workflows/` | 步骤编排、暂停与恢复 | 平台接入、资产处理、素材收集、记录库、内容模型 |
| 平台接入 | `src/platforms/` | 每个平台的形态、限制、转换、发布方式、数据 | 发布方式、资产处理、内容模型 |
| 发布方式 | `src/publishers/` | 交给 skill、手动成品、写 git 仓库、外部命令行、接口直连 | 内容模型 |
| 资产处理 | `src/assets/` | 图片、流程图、卡片、视频 | 内容模型 |
| 素材收集 | `src/materials/` | 扫项目记录 | 内容模型 |
| 记录库 | `src/store/` | SQLite 读写、建表与升级 | 内容模型 |
| 内容模型 | `src/core/` | 类型、形态目录、纯函数 | 不依赖任何层 |
| 配置 | `src/config/` | 读配置和凭证 | 内容模型 |

依赖只能往下走。平台接入之间互不依赖，加一个平台不影响已有的平台。

## 内容模型

为多平台、多形态（包括视频）设计，首版只用到其中一部分：

```
作品（一个选题产出的全部内容）
 ├─ 原稿：类型是「文章」或「视频母版」；文章指向博客仓库里的文件，视频母版指向本地视频文件
 ├─ 资产：图片、流程图、封面、卡片图、视频、字幕、音频；每个都记内容哈希，内容没变就不重复处理
 └─ 版本：平台 + 形态 + 稿件文件 + 状态
      └─ 发布记录：发布方式、平台上的链接和编号、时间
           └─ 数据快照（以后）：阅读、赞同、播放等

另有：素材、题目、工作流运行和步骤、资产上传缓存（资产哈希 → 平台上的媒体编号，同一张图不重复上传）
```

形态目录统一定义在内容模型里，平台接入只声明自己支持哪几种：

| 形态 | 说明 | 典型限制 | 平台例子 |
|---|---|---|---|
| 长文 | 有标题的长文 | 标题长度、代码块和公式支持 | 博客、知乎文章 |
| 回答 | 挂在一个问题下的长文 | 必须关联问题 | 知乎回答 |
| 短帖 | 短文字，可配图 | 字数、图片张数 | 知乎想法 |
| 图文卡片 | 多张图加一段文案 | 图片比例和张数、标题和正文字数 | 小红书、抖音图文 |
| 横版视频 | 16:9 视频 | 时长、分辨率、封面、分区、标签 | B站 |
| 竖版视频 | 9:16 视频 | 时长、封面、话题 | 抖音、小红书视频 |

## 平台接入

每个平台接入提供同样的五样东西：

| 内容 | 说明 |
|---|---|
| 身份 | 平台编号和名字 |
| 能力 | 支持的形态，以及每种形态的限制 |
| 转换 | 把版本稿件和资产打成这个平台的成品包：正文、图片、封面、视频、元数据放在一个文件夹里 |
| 发布 | 选定一种发布方式，返回三种结果之一：已发布（带链接）、等待交接、等待作者手动发 |
| 数据 | 按发布记录拉数据，可以不提供 |

接入计划：

| 平台 | 形态 | 发布方式 | 里程碑 |
|---|---|---|---|
| 博客 | 长文（原稿） | 写 git 仓库 | M0 只读；M3 写入 |
| 知乎 | 长文、短帖 | 交给知乎官方 skill | M1 |
| 知乎 | 回答 | 手动成品（复制页） | M2 |
| 小红书 | 图文卡片 | 手动成品（卡片包） | M4 |
| B站 | 横版视频 | 外部命令行（biliup） | M6 |
| 抖音 | 竖版视频、图文卡片 | 手动成品；外部工具要等风险评估之后再定 | M6 之后 |

## 发布方式

| 发布方式 | 怎么做 | 用在哪 |
|---|---|---|
| 交给 skill | 准备好交接目录和说明，由 Claude Code 调用对方的 skill，结束后读它留下的结果文件 | 知乎文章、想法 |
| 手动成品 | 生成成品包或复制页，作者发完回填链接 | 知乎回答、小红书 |
| 写 git 仓库 | 写文件、过对方仓库的门禁、提交并推送 | 博客 |
| 外部命令行 | 调用外部发布工具，解析它的输出 | B站（biliup），以后 |
| 接口直连 | 自己签名调平台接口 | 以后需要时 |
| 模拟浏览器 | 作者明确同意后才用 | 以后评估 |

## 工作流

### 步骤的种类

| 种类 | 谁来做 | 举例 |
|---|---|---|
| 代码 | 命令行自己做完 | 解析原稿、补链接、打包、登记 |
| AI | skill 做 | 改写、出题、挑问题 |
| 确认 | 作者 | 看预览、选问题、勾题 |
| 交接 | 外部发布工具 | 知乎官方 skill 发布 |
| 手动 | 作者在平台上操作 | 粘贴回答、在手机上发卡片 |

### skill 和命令行怎么配合

1. skill 运行 `leafpress run start <工作流> <参数> --json`，命令行一直往下跑，遇到非代码步骤就停，返回「在等什么」和相关文件的路径。
2. 等 AI：命令行在 `runs/<运行编号>/<步骤>/` 下写一份任务文件，写明要做什么、输入文件在哪、结果写到哪、什么格式。skill 照着做，把结果写进指定文件。
3. 等确认：skill 把预览给作者看，作者同意或说出要改哪里。
4. 等交接：命令行备好交接目录和说明，skill 去调用对应的外部 skill。
5. 等手动：命令行生成成品，作者发完把链接告诉 skill。
6. skill 运行 `leafpress run resume <运行编号>`，必要时带上同意、驳回或链接。命令行先校验交回的结果，再接着往下跑。

每个步骤都记下自己输入文件的哈希。恢复时如果发现上游文件变了（比如作者改了稿），从变动的地方往后的步骤全部作废重跑。

### 运行的状态

```
运行中 ──► 等待中（等 AI / 等确认 / 等交接 / 等手动）──► 运行中 ──► 完成
   │            │
   │            └──► 取消
   ├──► 失败：记下原因，恢复时从失败的步骤重试；也可以取消
   └──► 异常退出（租约过期）：作者确认后加 --force 接管或取消
```

同一时刻只有一个进程能推进一次运行，靠「租约」保证：进程取得执行权时写下自己的令牌和到期时间，跑的过程中定期续约，停下时交还。租约过期说明上次的进程异常退出，只有作者确认后才能接管。

### 版本的状态

```
草稿 ──► 待确认 ──► 已发布
  ▲         │
  └─────────┘ 作者驳回或改稿后退回草稿
草稿、待确认 ──► 已放弃
```

## 主流程

### 转写：原稿 → 某平台某形态

所有一稿多用都走这一条，博客转知乎文章、转知乎回答只是参数不同；以后的小红书卡片、视频也走它，差别都在平台接入和资产处理里。

```
① 读取原稿【代码】拉博客到最新 → 解析 → 算哈希 → 找到或新建作品；同平台同形态已发布就停下提示
② 规划【代码】向平台接入要这个形态的限制和需要的资产
③ 前置确认【作者】只有部分形态需要，比如回答要先选问题
④ 改写【AI】写任务文件 → skill 按规则改写 → 交回稿件 → 校验格式
⑤ 固定转换【代码】流程图转图片、站内链接补全、文末加原文链接
⑥ 自查【代码】禁用句式、形态限制 → 有问题标给作者；作者可以让 AI 再改一轮，回到 ④
⑦ 打包【代码】平台接入把稿件和资产打成成品包
⑧ 确认与发布【按发布方式】
     交给 skill：官方 skill 自带预览和确认，发完留下结果文件
     手动成品：生成复制页，作者自己发
⑨ 登记【代码】写发布记录；没拿到平台链接就不算发布成功
```

### 题单

```
① 收集【代码】扫名单里的项目，只收上次之后新增的进度记录、review 记录、提交记录
② 补记忆【AI】skill 从 CloudMind 取近期记忆，写进素材
③ 出题【AI】把素材归成 5～8 个候选题，每题附来源
④ 找问题【代码】按每题的关键词调知乎数据接口，带回浏览量和回答数
⑤ 勾题【作者】勾中的题进入「待写」
```

「随手记」只有一个代码步骤：把一句话连同当前项目和时间写进素材。

## 出错与恢复

- **步骤可以重复跑。** 每个步骤先把结果写到临时文件，成功后再改名，跑到一半断掉不会留下半截文件。
- **失败可以重试。** 步骤失败时，运行标为失败并记下原因；恢复时从失败的步骤重新开始。
- **不重复发布。** 调平台之前先在记录库登记「发布意图」，拿到结果再改成「已发布」或「待核实」。同一目标已经发过就拦下；上次的意图或待核实记录还没处理完，也拦下，必须作者核实（发出去了就补链接，没发出去就作废）后才能再发。这样即使平台已经发出去、本地还没登记时进程崩了，也不会自动重发。拿不到平台链接的不登记为成功。
- **外部依赖缺失时说清楚怎么修。** 官方 skill 没装、Edge 找不到、凭证缺失，`leafpress doctor` 都能查出来；对应步骤失败时直接给出修复办法。
- **重启不丢进度。** 运行状态都在记录库和运行目录里，`leafpress run list` 能列出没跑完的运行，接着恢复就行。
- **输入变了就重做。** 每一步开跑前给输入文件拍快照，结束时和之后每次恢复时都核对；对不上就从这一步往后重做，旧的步骤目录改名保留，不会误用旧结果。
- **代码升级不错位。** 恢复前比对工作流定义的步骤顺序，变了就拒绝恢复，请作者重新开始。
- **记录库升级前先备份。** 表结构按版本号升级，升级前用 SQLite 自带的一致性复制（`VACUUM INTO`）备份一份。

## 扩展点

| 以后要加 | 改哪里 |
|---|---|
| 新平台（比如小红书） | `src/platforms/` 加一个子目录并在登记表里登记；工作流不用改 |
| 新形态（比如图文卡片） | 内容模型的形态目录加一项；资产处理加对应的渲染器 |
| 视频平台（比如 B站） | 原稿类型用「视频母版」；资产处理加 FFmpeg 转码、截封面、烧字幕；平台接入的发布方式选「外部命令行」 |
| 新发布方式（比如模拟浏览器） | `src/publishers/` 加一种，平台接入里声明可用 |
| 平台数据 | 平台接入提供「拉数据」，记录库加数据快照表 |
| 本地网页工作台 | 新加一层，只读记录库，工作流不用改 |
| 直接调大模型接口 | 工作流的 AI 步骤加一个执行器，skill 方式保留 |
